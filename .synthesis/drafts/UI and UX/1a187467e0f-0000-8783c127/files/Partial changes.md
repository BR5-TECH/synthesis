## Intent

When working on large documents (e.g. 50 pages HLD document describing some project) we might still need agents to make proposals. Today the agent gets the whole document in its context, and a published prompt or DOC proposal must carry the whole new text. Both fail for large documents.

This work lets an agent read only chunks of a document and propose changes without the full text in its context. It covers three targets: a draft's prompt, a published prompt, and a DOC file. Users: the author (a human) who discusses a document and reviews proposals, and the agents that answer in the discussion.

## User journey

- User is working on the large document/artifact or draft.
- User discusses some portion of the document via the comment OR via verbal instructions.
- Agent is able to read chunks of the document references by the user.
- Agent is able to identify the anchor points for the changes.
- Agents is able make a change proposal which doesn’t require full content to be present in agent’s context.
- User sees the existing change proposal UI with the existing UX, allowing the user to accept/reject or discuss any particular change or accept/reject them all.
- User sees a context indicator at the top right of the discussion column. It shows how much of the model's context window the turn uses.
- When the document is above the size limit, User sees a warning icon next to the indicator. User is responsible for splitting or shortening the document.

## Requirements

- Look and feel of “change proposal” review must stay “as is”: the hunk review of a draft (`DCR-draft-change-review.md`) and the compare modal of a published prompt or DOC file (`PCR-prompt-change-review.md`) do not change. Only the way an agent builds a proposal changes.
- **Reading chunks.** `read_file` already reads a line range. `read_draft` gains optional `offset` and `limit` (lines) with the same meaning, and still returns the draft's metadata. Extend these existing tools. Add no search tool.
- **Size tool.** One new read-only tool returns the size of a target (a project file or a draft): lines, characters, estimated tokens, the size limit in tokens, and whether the target is above it. The agent uses it before it chooses to read the whole text. Tokens are a fixed characters-per-token estimate and are labelled as an estimate. The tool is attached to every conversational agent turn.
- **Size limit.** The limit is a percent of the model's context window, default 30%. It is one Global setting (AI API section). The window is the provider's Max context size when it is set, else the size the model reports, else 1,000,000 tokens (see the Context window draft). A window is always known, so a limit always applies. The limit applies to the document in the `artifact` input section only.
- **Artifact input section.** At or below the limit, the section holds the whole text, as today. Above the limit and with a fragment-targeted discussion, the section holds the passage around the fragment: the fragment plus as much surrounding text as fits in the limit. The section is marked `truncated` and states the document size. Above the limit and with a whole-target discussion, the section holds metadata only (path, type, size, `truncated`) and no text. The agent then reads chunks with the tools above.
- **Context indicator.** It stands at the top right of the discussion column header in the New Artifact tab and in the Editor tab. It shows the whole turn's context use as a share of the model window: the input tokens the provider reported for the latest model call of the latest turn, or an estimate before any turn. A tooltip on hover shows the split: instructions, document, discussion history, current comment, tool results. The split values are estimates. The warning icon stands next to it only while the document is above the limit. Its tooltip states the document size and the limit, and says that the user must split or shorten the document. The warning never blocks the discussion or a proposal.
- **Anchors for duplicates.** Each hunk of a proposal accepts optional `lead` and `trail`: the exact text immediately before and immediately after `before` (for an `add` hunk, around `after_text`). The text `lead + before + trail` must occur exactly once. Only `before` is changed. Without `lead` and `trail`, a `before` that occurs more than once stays refused, and the refusal names the hunk place and tells the agent to add `lead` or `trail`. Both are bounded in length. The rule is the same for drafts and for published prompts and DOC files.
- **Draft proposals** (`propose_draft_changes`): the backend already resolves hunks against the whole prompt. The work is `lead`/`trail`, the new description text, and the reading tools above.
- **Published prompt and DOC proposals** (`propose_prompt_changes`): the call takes either the full new `text` or `hunks`, never both. Hunks have the shape and rules of draft hunks, including `lead` and `trail`, but no `revises`. The backend resolves the hunks against the file as it is on disk and builds the whole candidate. It records the same candidate, the same comment, and the same compare review as a full-text proposal. When the backend cannot build the candidate reliably (text not found, text found more than once, overlapping hunks), it records nothing and refuses with a retryable error that names the hunk place, so the agent can send better text or anchors. Accept and decline stay whole-candidate.

## Expected deliverables

- Tooling updates to support new behaviors.
- Documentation/skills are updated to reflect the changes as needed.
- Specifications to change: `tools/PDC-propose-draft-changes-tool.md` (`lead`/`trail`, the duplicate refusal, the hunks description); `tools/PPC-propose-prompt-changes-tool.md` and `core/PCP-prompt-change-proposals.md` (hunks accepted; the backend builds the candidate; remove "a proposal is a whole file or it is nothing" and the patch/fragment exclusion; the candidate stays whole); `tools/RDT-read-draft-tool.md` (`offset`/`limit`); a new tool specification for the size tool, plus the tool lists of `ai/CVL-conversation-loop.md` (CVL-FR-08) and `tools/TLC-tool-conventions.md` where they enumerate tools; `core/AGC-agent-conversations.md` (the artifact builders: the size limit, the passage around a fragment, metadata-only input, `truncated`); `ai/CVL-conversation-loop.md` and `core/AGC-agent-conversations.md` (a turn's usage is also made available to the discussion surface, which today reaches draft statistics only); `ui/DDS-draft-discussion.md` (the indicator, its tooltip, and the warning in the column header); `ui/GLS-global-settings.md` and `core/GSS-global-settings-storage.md` (the percent setting); `ui/AII-ai-integrations.md` and `core/AAP-ai-api-integrations.md` only where the context size source is named.
