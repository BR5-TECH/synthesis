## Intent

Create PR must respect stacks.

New workstream must respect stacks.

Create PR should be grayed out if the current branch already has a PR

## User journey

- **Create a PR on a stack.** The author opens **Create a PR** (Changes footer, Git panel, or stream row) on a branch that is in a GitHub stack. The window opens with the base branch set to the parent branch in the stack. The author edits the title and description and submits. The app submits the pull request to the stack in one call, and the pull request appears in the stack.
- **New worktree on a stack.** The author is on a branch or worktree that is in a stack and opens **New worktree**. The active branch must have an open pull request. If it has none, the dialog blocks creation and tells the author in words to create the worktree from a branch that is not in a stack, for example the default project branch. If it has one, the dialog creates the worktree and branch, and the app adds the new branch to the top of that stack at creation, before the new branch has a pull request.
- **Branch already has a pull request.** The author sees **Create a PR** disabled, with the reason in words, on a branch that already has an open pull request.
- **No stack.** When the branch is not in a stack, or stacks are unavailable, all flows behave as they do today.

## Requirements

- GitHub-related dependencies must be updated to the latest stable as a part of this work.
- Existing GitHub integration must be used for this work. 
- **Stack.** "Stack" means a GitHub stacked PRs stack (not the stream `base_branch` chain and not local Git ancestry). The app reads from the GitHub stacks API whether a branch is in a stack, which branch is its parent, and which is the top. Where the API gives no answer, the app falls back to the chain of open pull requests (the base of one is the head of another, as in CPR-FR-IPKX). The builder must confirm the exact GitHub endpoints and token scope, because the project does not yet specify them.
- **Unavailable stacks.** When stacks are unavailable (feature not enabled for the repository, token lacks scope, API error), every flow below falls back to today's behaviour. No flow blocks, and none shows an error for this cause alone.
- **Create a PR, base.** In all three openers (Changes footer CHG-FR-UPFP, Git panel **Create PR for current branch** GIT-FR-05, work stream row **Create a PR**), when the head branch is in a stack, the source that the opener gives the window has the parent branch in the stack as the base branch, in place of the default branch. The author can still change the base. A parent branch with no pull request yet is still the base.
- **Create a PR, submit.** When the head branch is in a stack and the base is its parent, **Submit** creates the pull request with one stack submit call of the GitHub API (the API behind `gh stack submit`). When that call is not available or fails for a reason of the API, **Submit** creates a normal pull request and then attaches it to the stack. When both fail, the window shows the failure inline and keeps its state. The existing push, link and block rules of CPR stay unchanged.
- **Create a PR, disabled state.** **Create a PR** is unavailable in all three openers while the current branch (the head of a stream row) has an open pull request with this head. Closed and merged pull requests do not disable it. The reason is stated in words, with the pull request number, and is the accessible description of the control. The availability rules of CHG-FR-UCRL still apply, and this rule is added to them. A read of open pull requests that fails or is still running adds no block.
- **New worktree dialog.** When **New worktree** is opened while the active branch is in a stack, the new branch is added to the top of that stack through the GitHub API at creation (after `"create worktree (branch, path)"` succeeds), and its base is the current stack top. **New worktree, validation.** Before creation, when stacks are available and the active branch is in a stack, the dialog needs an open pull request with the active branch as its head (not the stack top, and not closed or merged pull requests). When there is none, the dialog disables its create action and shows the reason in words, which also is the accessible description of that action. The reason says to create the worktree from a branch that is not in a stack, for example the default project branch. When stacks are unavailable, this check does not apply and the dialog behaves as today. A read of open pull requests that fails or is still running adds no block. Failure to add the branch to the stack does not undo the worktree. The dialog keeps its two inputs (WTS-FR-18) and shows no new input; the reason text is not an input. The app tells the author, in a toast, when the branch was not added to the stack.
- **Out of scope.** The New stream dialog (WSS-FR-XZRO) and the graduation start dialog (GSD-FR-QGTC) keep today's behaviour and do not add branches to a stack.
- **Specifications to change:** `specifications/ui/CPR-create-pull-request.md` (base from stack, stack submit, fallback, disabled reason), `specifications/ui/CHG-changes.md` CHG-FR-UCRL and CHG-FR-UPFP, `specifications/ui/GIT-git.md` GIT-FR-05, `specifications/ui/WSS-work-stream-selector.md` (row **Create a PR** availability and base), `specifications/ui/WTS-worktree-selector.md` (New worktree dialog and the stack step), `specifications/core/WTC-worktree-context.md` and `specifications/core/GTC-git.md` (new operations to read a stack, add a branch to it, and submit a stack; typed errors; token scope).
