# Draft statistics storage

**Spec code:** `DSS`

## Intent
The durable, project-local record of what a draft cost to make: the foreground time the author spent on it, the agent turns and graduation work it consumed, the versions it settled, the proposals it decided, and the provider-reported tokens all of that spent. It exists because a draft is long-lived and a graduation run is minutes or hours of agent work, and an author who wants to know what a piece of working material actually took has nothing to read it from once the run is over and the session is gone. So the account is kept as an **append-only event log per draft**, one JSON object per line, in the per-machine store this machine keeps for the repository the project belongs to (`RMS-repository-machine-storage.md`), and it is kept outside the draft's own folder in every place but one: the log is deleted with the draft, because a record of a draft nobody kept is a record of nothing. The log stands outside every worktree and reaches Git by no route, so an author's checkout is never modified by a measurement. It is **duplicate-safe by construction** — every event carries a stable identity and the fold applies the first event it sees for an identity and ignores every later one — so a relaunch, a replay, a second application process, or a concurrent append recovery that writes one event twice folds to the same totals as one write. Statistics describe **captured** activity alone: a draft's telemetry begins at the moment its first event is recorded, that instant is persisted as the draft's **activation boundary**, and nothing before it is read, reconstructed, or inferred from the comment logs, the draft history, the graduation records, the run logs, or any session state. A statistic with no captured source data is reported **unavailable** and one whose captured source data is damaged or partial is reported **incomplete**; neither is ever reported as a zero the author would read as a fact. Out of scope: rendering any of it, which is `../ui/DFI-draft-information.md`'s; producing the activity, which belongs to the modules that perform it — `AGC-agent-conversations.md`, `DHS-draft-history.md`, `DCP-draft-change-proposals.md`, and `GRD-graduation.md` each record their own events here and none of them is reimplemented; the draft, its record, and its folder, all of which are `DRS-draft-storage.md`'s; the application's own diagnostic records, which are `LGC-logging.md`'s and are a different channel with a different purpose; and any per-run account of a graduation, which is `GOB-graduation-observability.md`'s and is not composed, duplicated, or read here.

## Contract surface
The module owns the `statistics/` folder of the repository machine store, the event vocabulary, the fold that produces the totals, one Tauri command, one recording command, one event, and the internal recording and deletion API the other backend modules reach it through. Names match `../ui/DFI-draft-information.md`'s "Delegated to backend (abstract)" line byte-for-byte. Every path this module resolves is resolved against that store (per `RMS-repository-machine-storage.md` RMS-FR-ZXHM), which is outside every worktree.

### The event envelope

```
StatisticsEvent {
  v,                 // schema version of the line; 1
  event_id,          // opaque and unique; the identity the fold deduplicates on
  draft_id,          // the stable draft id the log is named for
  at,                // RFC 3339 UTC; the capture instant of the fact recorded.
                     //   For an event carrying an interval it is that interval's
                     //   own `started_at` (DSS-FR-MHJC)
  type,              // one of the vocabulary below
  ...                // the fields that type carries
}
```

### The event vocabulary

```
telemetry_activated  { }
                     // the draft's activation boundary; `at` is the boundary instant

editing_interval     { interval_id, started_at, ended_at }
                     // one settled foreground editing interval (DSS-FR-RIDW)

conversation_turn    { turn_id, thread_id, origin_kind, reached_model,
                       started_at, ended_at, outcome }
                     // one draft-scoped conversational agent turn (AGC-FR-YQMD)

agent_operation      { operation_id, bucket, run_id, started_at, ended_at }
                     // one graduation agent or model operation (GRD-FR-KPWE)

token_usage          { usage_id, scope, bucket, owner_id, representation,
                       round, attempt,
                       input_tokens?, cached_input_tokens?,
                       uncached_input_tokens?, output_tokens? }
                     // one reliable provider-reported usage record (DSS-FR-SVJU)

draft_history_entry  { entry_id, seq, source_kind }
                     // one settled draft-history entry (DHS-FR-ZQNM)

proposal_decision    { proposal_id, decision }
                     // one final draft change-proposal decision (DCP-FR-WTKA)
```

```
scope           = "conversation" | "graduation"
representation  = "per_call" | "turn_aggregate"
decision        = "accepted" | "rejected"
bucket          = "refinement" | "authoring" | "validation_handoff_publication"
                | "implementation" | "reviews" | "reconciliation"
```

### The totals

```
Availability = "available" | "incomplete" | "unavailable"

Measure   { value, availability }    // `value` is null when availability is "unavailable"
TokenPair { input: Measure, output: Measure }

BucketTimes  { refinement, authoring, validation_handoff_publication,
               implementation, reviews, reconciliation, total }      // each a Measure
BucketTokens { refinement, authoring, validation_handoff_publication,
               implementation, reviews, reconciliation, total }      // each a TokenPair

DraftStatistics {
  draft_id,
  boundary_at,           // RFC 3339 UTC; null where the draft has no boundary
  editing_time_ms:       Measure,
  ai_interactions:       Measure,
  draft_edits:           Measure,
  accepted_proposals:    Measure,
  rejected_proposals:    Measure,
  conversation_tokens:   TokenPair,
  agent_time_ms:         BucketTimes,
  agent_tokens:          BucketTokens,
  unreadable_lines       // count of lines the fold could not read and left in place
}
```

### Tauri commands
- `"read draft statistics"` → `read_draft_statistics(draft_id)` → `DraftStatistics` — folds the draft's log and returns the aggregate totals with their availability. It reads the log alone (DSS-FR-GAWO) and creates nothing (DSS-FR-JRSY).
- `"record draft editing interval"` → `record_draft_editing_interval(draft_id, started_at, ended_at)` — records one settled foreground editing interval for a draft (DSS-FR-RIDW). It returns as soon as the event is accepted for recording.

Errors are typed: `no_project_open`, `store_unavailable`, `draft_not_found`, `invalid_interval`, and `read_failed`.

### Events
- `"draft statistics changed"` — carries `{ draft_id }`, emitted when events for that draft have been appended (DSS-FR-TWNA). It carries no totals; a consumer re-reads.

### Internal (Rust API, not registered as Tauri commands and unreachable from the frontend)
- `record_statistics_event(draft_id, event)` — the single path by which an event is recorded (DSS-FR-EKZI). It accepts the event, returns immediately, and appends asynchronously (DSS-FR-TUMX). Called by `AGC-agent-conversations.md`, `DHS-draft-history.md`, `DCP-draft-change-proposals.md`, `GRD-graduation.md`, and the editing-interval command above.
- `delete_draft_statistics(draft_id)` — removes that draft's log (DSS-FR-VPBS). Called by `DRS-draft-storage.md` (DRS-FR-ZLBK) and by nothing else. Idempotent against a log that is already absent.
- `statistics_dir()` — the `statistics/` folder of DSS-FR-KQVN inside the repository machine store.

## Functional requirements
 1. **DSS-FR-KQVN** Every draft that has recorded an event has exactly one log at `statistics/<draft-id>.jsonl` inside the repository machine store (per `RMS-repository-machine-storage.md` RMS-FR-ZXHM), where `<draft-id>` is the draft's **stable id** (per `DRS-draft-storage.md` DRS-FR-02) rather than its current name, its current path, or the drafts folder it is filed in. Renaming a draft, moving it between drafts folders, archiving it, and graduating it each leave the log where it is and change no byte of it. The log is never placed inside a worktree, so a draft's account is addressed by its stable id alone and is removed by `delete_draft_statistics` and by nothing else (DSS-FR-VPBS).
 2. **DSS-FR-PWXG** The store this module resolves is selected by the **repository identity** and never by the active worktree (per `RMS-repository-machine-storage.md` RMS-FR-QJVT, RMS-FR-LPWG). A read that cannot resolve the store returns the typed `store_unavailable` (RMS-FR-WGQS); an append that cannot resolve it is dropped on the terms of DSS-FR-TUMX. This module writes no `.gitattributes`.
 3. **DSS-FR-WRPD** Each line of a log is exactly one JSON object describing one event, terminated by a newline. Appending is the **only** mutation this module performs: no line is ever rewritten, reordered, truncated, or removed, and no compaction, rotation, or pruning runs at any age or size. The log is therefore safe to append to from two application processes at once and safe to read while it is being written (per `RMS-repository-machine-storage.md` RMS-FR-PFOB).
 4. **DSS-FR-MHJC** Every event carries the envelope of the Contract surface — `v`, `event_id`, `draft_id`, `at`, and `type` — and the fields its `type` defines. `at` is the **capture instant** of the fact the event records rather than the instant the line reached disk, so an event appended late by the asynchronous writer of DSS-FR-TUMX still folds where it belongs. For an event carrying an **interval** — an `editing_interval`, a `conversation_turn`, and an `agent_operation` — the capture instant is that interval's own `started_at`, the fact having begun being captured when the interval opened rather than when it settled; for every other event it is the instant the fact happened.
 5. **DSS-FR-XBGA** The event vocabulary is exactly `telemetry_activated`, `editing_interval`, `conversation_turn`, `agent_operation`, `token_usage`, `draft_history_entry`, and `proposal_decision`. There is no event that edits, retracts, or corrects another, because the fold reconciles duplicates by identity rather than by amendment.
 6. **DSS-FR-PNUE** Every event carries an `event_id` that is opaque and unique, and every event type additionally carries the **stable identity of the thing it describes** — `interval_id`, `turn_id`, `operation_id`, `usage_id`, `entry_id`, or `proposal_id`. The fold applies the first event it sees for a given `event_id` and ignores every later one, and it counts each of those subject identities **at most once** whatever number of events name it. A log replayed after a relaunch and a log a concurrent append recovery wrote an event into twice therefore both fold to the totals an undamaged log folds to.
 7. **DSS-FR-LDFK** Every event carries `v = 1`, the schema version of the line. A line whose `v` this build does not recognise is **skipped** by the fold rather than failing it, and is left in the file untouched, so a log written by a newer build still serves the events this one understands. A line that is not valid JSON, carries no recognised `type`, or is missing a field its type requires is skipped on the same terms. Every skipped line is counted in `unreadable_lines` and makes the statistics it would have contributed to **incomplete** (DSS-FR-NCLP); one damaged line never prevents the rest of the log from being served.
 8. **DSS-FR-VCTQ** A draft's **telemetry activation boundary** is created and persisted when the **first statistics event for that draft is about to be recorded**, and by no other path. It is not created when the project is opened, when the draft is created, when the Drafts panel lists it, or when `read_draft_statistics` is called. The boundary is recorded as a `telemetry_activated` event whose `at` is the **capture instant of that first event**, and it is written **before or in the same append as** that event, so no event ever reaches the log without a boundary standing for it. That first event is **at** the boundary and is therefore post-boundary activity that counts.
 9. **DSS-FR-JRSY** Two first-event attempts that race, and two checkouts that each began recording independently, **converge on one boundary**: the fold takes the earliest `at` among the `telemetry_activated` events the log holds, tie-broken by `event_id`, as the draft's one boundary, and ignores every later one. `boundary_at` is that instant, and it is null for a draft whose log holds no `telemetry_activated` event and for a draft that has no log at all. Reading a draft's statistics writes nothing anywhere and creates no boundary, so a draft whose Information is opened before anything was recorded still holds no boundary afterwards.
10. **DSS-FR-GAWO** The fold collects **only what the log holds at or after the boundary**, and the log is the **only source it reads**. An event carrying no interval is in scope when its `at` is at or after the boundary; an event carrying an interval is in scope when its `ended_at` is at or after the boundary, and contributes the part of that interval at or after the boundary alone (DSS-FR-KYTB). This module does not read, walk, or infer from comment logs, discussion logs, draft history entries, proposal records, graduation run records, iteration records, agent activity streams, session state, or filesystem timestamps, and it backfills nothing from any of them. Activity that happened before a draft's boundary is out of scope: it contributes to no total, and it never makes a statistic incomplete, because there is nothing in the log for the fold to find it in.
11. **DSS-FR-KYTB** An event that carries an **interval** contributes only the part of that interval at or after the boundary. The fold takes its contributed duration as `ended_at` minus the **later** of `started_at` and `boundary_at`, and takes it as **zero** where that difference is negative, so an editing interval, a conversational turn, or a graduation operation that began before the draft's telemetry was activated and ended after it contributes exactly the part that was captured and no part that was not. An event whose whole interval ended before the boundary is out of scope entirely (DSS-FR-GAWO) and contributes neither duration nor count. **Clipping is not incompleteness**: the part cut away is pre-boundary activity, which is out of scope rather than missing, so a clipped event is a valid post-boundary event of its family, leaves that statistic `available`, and moves no availability anywhere (DSS-FR-NCLP). Clipping reaches **durations alone**: an event is counted whole wherever it is counted rather than measured — AI interactions, Draft edits, and the two proposal counters are counts of things that happened — and each reliable token usage record is summed whole, a reported token count having no interval in it to cut. The producers of these events report their **own whole interval** and know nothing of the boundary (per `AGC-agent-conversations.md` AGC-FR-YQMD, `GRD-graduation.md` GRD-FR-NHRY, `../ui/DFI-draft-information.md` DFI-FR-UKFR); this fold is the one place a boundary is applied, so two producers can never disagree about where one is.
12. **DSS-FR-TUMX** Recording is **asynchronous and never blocking**. `record_statistics_event` and `record_draft_editing_interval` accept the event, hand it to this module's own writer, and return; the user action or agent run that produced the event neither waits for the append nor fails with it. An append that cannot be performed — the store unresolvable, the folder unwritable, the disk full — is recorded through `LGC-logging.md` at `WARN` and dropped, and the statistic it would have contributed to is reported incomplete when the fold can tell (DSS-FR-NCLP) and simply smaller when it cannot. No caller anywhere is given a statistics failure to handle.
13. **DSS-FR-EKZI** `record_statistics_event(draft_id, event)` is the **only** path by which an event is recorded. It is internal, so no frontend call can forge an event, attribute one to another draft, or write a line of a log directly; the one recording command the frontend reaches is `record_draft_editing_interval`, which composes the event itself. The module stamps `event_id`, `v`, and `draft_id`, and refuses an event naming a draft other than the log it is being written to.
14. **DSS-FR-BQHR** A conversation is **linked to a draft** for these statistics when, and only when, its origin kind is `draft_comment` or `draft_discussion` and the origin carries that draft's id (per `AGC-agent-conversations.md` AGC-FR-05). Every such conversation counts, whether its thread is open, locked, resolved, archived, or terminal, and whichever surface it is being read in (per `../ui/CVP-conversation-presentation.md`). An `artifact_comment`, an `artifact_discussion`, and a `note_discussion` conversation are **not** linked, and neither is a discussion about a specification a graduation published, unless that conversation also carries a `draft_comment` or `draft_discussion` origin naming the draft. A second surface is not a second conversation and multiplies nothing: a turn is recorded once, against the conversation that holds it.
15. **DSS-FR-YOVS** `read_draft_statistics(draft_id)` folds the draft's log and returns the `DraftStatistics` of the Contract surface: aggregate captured-lifetime totals, each carrying its own availability, and nothing per run, per conversation, or per event. The fold is **total and deterministic**: the same log always folds to the same totals whatever order its lines physically appear in. A draft with no log answers with `boundary_at` null and every statistic `unavailable`, which is an answer rather than an error.
16. **DSS-FR-NCLP** Each statistic names a **source family** of event types, and its availability follows that family alone. A statistic whose family the fold saw **no valid post-boundary event** of is `unavailable` and carries a null value. A statistic whose family the fold saw at least one valid post-boundary event of, and also a line it could not read or a required field it could not read, is `incomplete` and carries the total of the valid events. Every other statistic is `available`. A statistic is never reported as an `available` zero on the strength of missing data, and pre-boundary activity moves no availability in either direction (DSS-FR-GAWO) — an event clipped at the boundary is a valid event of its family and leaves that family `available` (DSS-FR-KYTB). A statistic whose family the fold saw valid events of, none of which contributes a value, is `available` at **zero**, that zero being a fact the events state rather than a gap: a draft whose only conversational turns reached no model has an `available` Refinement time of zero, and a draft that has no `conversation_turn` event at all has an `unavailable` one. The families are: `editing_interval` for editing time; `conversation_turn` for AI interactions and for Refinement time; `agent_operation` carrying that bucket for each of the five graduation bucket times; `draft_history_entry` for Draft edits; `proposal_decision` for both proposal counters; and `token_usage` of the matching scope and bucket for each token total. The two totals of six buckets have no family of their own and take their availability from the buckets they are calculated over (DSS-FR-IYRG, DSS-FR-CMTP).
17. **DSS-FR-RIDW** Editing time is the sum of the boundary-clipped durations of the distinct valid `editing_interval` events (DSS-FR-KYTB), each being `ended_at` minus the later of `started_at` and `boundary_at`. An interval describes **active foreground editing**: the frontend opens one when the application has focus and a related surface is visible, and settles it when either stops being true, or at the instant five minutes without an interaction have passed — the interval running through that whole idle period and ending at its end rather than at the last interaction before it (per `../ui/DFI-draft-information.md` DFI-FR-XKRM). This module receives settled intervals whole, clips them at the boundary itself, and neither reconstructs one from the times a modal or a tab was opened nor invents one for a surface it was not told about. `record_draft_editing_interval` refuses with a typed `invalid_interval`, recording nothing, when `ended_at` precedes `started_at`.
18. **DSS-FR-FXAE** AI interactions is the count of distinct `conversation_turn` events whose `reached_model` is true. A turn that ended before any model call carries `reached_model` false, is recorded all the same so the fold can tell an absent turn from one that reached nothing, and contributes **no** interaction and **no** Refinement duration (DSS-FR-IYRG) — it is a turn that happened and spent nothing on a model, which is a different fact from a turn that was never recorded. A turn's provider retries and its additional model-call rounds after portable-tool results are part of that one turn and add no interaction, one logical conversational agent turn being one interaction whatever number of physical calls it took.
19. **DSS-FR-HGNT** Draft edits is the count of distinct `draft_history_entry` events, deduplicated by `entry_id`, including the event recorded for the `Original` a first acceptance settles (per `DHS-draft-history.md` DHS-FR-07, DHS-FR-ZQNM). A first byte-changing acceptance therefore contributes **two** — its newly settled `Original` and the version it produced — each later byte-changing acceptance contributes **one**, and an acceptance that changes no persisted prompt byte creates no history entry and contributes **none**. Ordinary typing, an unsaved buffer, the recording of a proposal, the editing of a candidate, a rejected proposal, and a pending proposal each create no history entry and are counted nowhere here.
20. **DSS-FR-OPMB** Accepted proposals is the count of distinct `proposal_decision` events whose `decision` is `accepted`, and Rejected proposals the count of those whose `decision` is `rejected`, each deduplicated by `proposal_id` so one proposal contributes at most once to at most one counter. A proposal is accepted where at least one of its changes was accepted (per `DCP-draft-change-proposals.md` DCP-FR-PWSF), and counts **even where those acceptances changed no prompt byte** and created no history entry, an acceptance being a decision rather than an edit. A proposal that is still pending has no decision event and contributes to neither counter, and a decision taken before the draft's boundary has no event in the log and moves neither counter and neither counter's availability.
21. **DSS-FR-SVJU** A `token_usage` event records **one reliable provider-reported usage record** and nothing else. It names the usage record's own stable identity (`usage_id`), the logical model-call round and the physical attempt or retry the provider reported it against, the `owner_id` of the turn or operation that produced it, its `scope`, its `bucket`, and its `representation`. A record's **input** value is `input_tokens` where the provider reported that total; where it did not, it is the sum of the non-overlapping `cached_input_tokens` and `uncached_input_tokens` components it did report; where it reported neither, the record carries no input value. Its **output** value is `output_tokens` where the provider reported it and is absent otherwise. A provider-reported total is **never added to the components it is a total of**. Nothing here is ever estimated: no token value is derived from text, from a character or word count, from a model's context limit, or from a price.
22. **DSS-FR-AWKD** Token totals sum each distinct `usage_id` **once**. The usage a **successful provider retry** reports is a distinct reliable record and is summed like any other; it adds no AI interaction and creates no second logical turn (DSS-FR-FXAE). Every answered logical model-call round contributes its record, including the rounds that follow portable-tool results; provider-native tool work performed inside one provider call has no application round of its own and is included only in the usage that call reported. Where an owner has **both** per-call records and a turn-level aggregate, the **per-call representation wins** and the aggregate is ignored; where an owner has no per-call record and one reliable aggregate, that aggregate is used **once**. The two representations are never combined for one owner.
23. **DSS-FR-DZQF** Input and output totals are kept and reported **separately** and their availability is decided independently. A family whose records report input and never output has an `available` input total beside an `unavailable` output total; a family in which some records report a direction and some do not has that direction `incomplete`. A direction the provider did not report is never filled with a zero, an estimate, or the other direction's value.
24. **DSS-FR-UBLC** Conversation tokens is the input and output total of the `token_usage` events of scope `conversation` — the reliable usage of the conversation-loop calls of the draft's linked conversations (DSS-FR-BQHR) — folded on the terms of DSS-FR-SVJU through DSS-FR-DZQF. Those same events are the Refinement bucket of the agent token totals, so the two readings of the same records always agree.
25. **DSS-FR-IYRG** Agent time is reported as **six bucket totals and one total of the six**, in the fixed order **Refinement**, **Authoring**, **Validation / hand-off / publication**, **Implementation**, **Reviews**, **Reconciliation**. Refinement time is the sum of the boundary-clipped durations of the distinct valid `conversation_turn` events **whose `reached_model` is true**; a turn that reached no model contributes nothing to it, on the terms DSS-FR-FXAE sets for the interaction it also does not contribute. Each of the other five is the sum of the boundary-clipped durations of the distinct valid `agent_operation` events carrying that bucket (DSS-FR-KYTB).

    The **total** is the sum of the buckets that carry a value, and its availability is decided by the six rather than by a family of its own: it is `unavailable` with a null value where **all six** buckets are `unavailable`; it is `incomplete` where at least one bucket carries a value and **any** bucket is `unavailable` or `incomplete`; and it is `available` only where **all six** are `available`. A bucket that is `unavailable` contributes **nothing** to the sum and is never read as a known zero — the total's `incomplete` state is the whole of what says the figure is a partial sum, and the author reads the bucket's own stated absence beside it (per `../ui/DFI-draft-information.md` DFI-FR-HSYB). An `available` bucket of zero is a different thing and is summed as the zero it is. A duration is the **actual execution interval of the agent or model operation**: queue waiting, waiting for the author to answer a question or decide a proposal, and every other idle interval are not agent time and are recorded in no event.
26. **DSS-FR-CMTP** Agent-reported tokens is reported over the **same six buckets in the same order**, each the input and output total of the distinct `token_usage` events carrying that bucket, plus a total of the six. A bucket with no reliable reported usage stays `unavailable` rather than becoming a zero. The **total** is calculated from the valid non-duplicated records alone, **per direction**, and takes its availability from the six buckets exactly as the agent-time total takes its own (DSS-FR-IYRG): a direction of the total is `unavailable` where that direction is `unavailable` in all six buckets, `incomplete` where at least one bucket carries a value for it and any bucket is `unavailable` or `incomplete` in it, and `available` only where all six carry it. An `unavailable` bucket contributes nothing to the sum and is never read as a known zero, and the two directions decide all of this independently (DSS-FR-DZQF).
27. **DSS-FR-QLEH** The bucket a `token_usage` or an `agent_operation` event carries is the bucket of the **model or agent operation that produced it**, decided by the phase or work the operation supports. Draft-scoped conversational turn execution is **Refinement**. A graduation **work** turn, and the clarification judgements that support one, are **Authoring**. The semantic turn of a stream **update** is **Reconciliation**, and a graduation **review** turn is **Reviews**. A **merge run** has no source draft, so none of its turns writes a statistic. No operation this build performs carries **Validation / hand-off / publication** or **Implementation**; both remain readable buckets, because a draft's statistics log holds events that were written under them. A graduation clarification judgement is **never** Refinement, even where its questions are about the draft's own prompt: it stays in the graduation bucket of the work it supports. The classification is settled by the module that records the event (per `GRD-graduation.md` GRD-FR-NHRY) and this module applies it rather than re-deriving it.
28. **DSS-FR-XRDM** No event this module writes ever carries a prompt, a draft's text, a candidate, a rationale, feedback, a comment body, conversation content, an assembled request, an exchange message, a tool argument, a tool result, agent output, a captured stream, a credential, a token, or a key. An event carries instants, identities, counts, a bucket, a decision, and reported token numbers, and nothing else. The log stays on this machine and reaches no checkout of the project.
29. **DSS-FR-TWNA** `"draft statistics changed"` is emitted when one or more events for a draft have been appended, carrying that draft's id and no totals, so an open Information modal re-reads and redraws (per `../ui/DFI-draft-information.md` DFI-FR-ZGBU) rather than polling. It is emitted after the append has landed and never before, it may coalesce several appends into one emission, and it is emitted nowhere else — not on a read, not on an event that was dropped, and not for a draft the append refused.
30. **DSS-FR-VPBS** `delete_draft_statistics(draft_id)` removes `statistics/<draft-id>.jsonl` in the repository machine store and nothing else. It is scoped to that one stable draft id, so no other draft's log is touched at any point; it is **idempotent**, a log that is already absent being an already completed deletion rather than an error; and it is **retryable**, a failure leaving the log exactly as it was and returning a typed error the caller repeats. It is reached from `DRS-draft-storage.md`'s deletion alone (DRS-FR-ZLBK) and is registered as no Tauri command, so no frontend call can erase a draft's statistics.
31. **DSS-FR-NKOZ** A draft's log **survives graduation**. Nothing here is removed, sealed, or made unreadable when a draft reaches `graduated` (per `DRS-draft-storage.md` DRS-FR-20): the log stays where it is, events already recorded stay readable, and `read_draft_statistics` answers for a graduated draft exactly as it answers for an active one. Events recorded for the run that graduated it stay in the log after that run reaches a terminal state, is archived, or completes.
32. **DSS-FR-QLXV** Every command errors with a typed `no_project_open` when no project is open and with `draft_not_found` when `draft_id` names no draft in the active worktree, and `read_draft_statistics` errors with `read_failed` when the folder itself cannot be read — which is distinct from a log that is absent, that being an answer with every statistic unavailable. Changing the active worktree selects the same store (per `RMS-repository-machine-storage.md` RMS-FR-TCAF), so a draft's totals read the same after the change as before it.
33. **DSS-FR-WGUP** Every write this module performs goes through `FSA-filesystem-access.md` primitives — `append_lines` for a log line (FSA-FR-15), `delete_path` for the removal of DSS-FR-VPBS — and is subject to FSA's path-escape rejection (FSA-FR-10). This module performs no raw `fs::write`, `fs::remove`, or `fs::rename` call and writes no file outside the store's `statistics/` folder. A `draft_id` crafted to resolve outside that folder is refused having written nothing.
34. **DSS-FR-ZMHT** Every operation emits through `LGC-logging.md`'s internal API under the `backend` domain: a `DEBUG` record when events are appended, naming the draft and the event types and counts; a `WARN` record when an append is dropped, when a line is skipped by the fold, and when a deletion fails, naming the draft and the reason. **No record carries a value DSS-FR-XRDM keeps out of an event**, and none carries a reported token count's provenance beyond the identities the event already holds.
35. **DSS-FR-PJOD** Nothing in this module reaches the network, contacts an AI integration, dispatches an agent turn, or touches a credential. It reads and writes files of the open project and does nothing else.
36. **DSS-FR-MVTK** A log **is never committed**. The store stands outside every worktree (per `RMS-repository-machine-storage.md` RMS-FR-HDNZ), so no log and no folder of the store is staged, committed, or reported as a change of the project by this application or by any module it calls. This module opens no repository, holds no index, resolves no signature, and writes no path under a `.git` directory.
37. **DSS-FR-RBQH** A log an earlier build committed into the project is **imported** into the store rather than read from the worktree: the import pass of `RMS-repository-machine-storage.md` (RMS-FR-JVEC) copies each of its lines the store does not already hold, and it removes nothing. The committed file stays exactly as it is, and the author removes it in a commit of their own (RMS-FR-XRPT).

## Non-functional requirements
- A log is a plain text file of one JSON object per line in an ordinary folder of this machine's application data, so an author can read a draft's whole account with a file manager.
- Appending costs one `append_lines` call per batch and never a read of what the log already holds, so recording is independent of how much a draft has accumulated.
- Reading costs one pass over one draft's log. The fold holds one accumulator per statistic and one identity set per subject kind, so a long-lived draft is bounded by its own event count rather than by the project's.
- Nothing here holds an event, a boundary, or a total in memory between calls beyond the writer's own pending queue, and nothing watches the folder: the log is the whole of the state, so a relaunch finds every recorded event exactly where the last process left it.
- The writer's queue is bounded and never grows without limit: it drops the oldest pending events with a `WARN` rather than delaying a caller or exhausting memory, because a statistic is worth less than the operation it describes.
- No operation here contacts the network or any AI integration, and the whole module is exercisable without a provider credential.
