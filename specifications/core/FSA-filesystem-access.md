# Filesystem access

**Spec code:** `FSA`

## Intent
The shared filesystem primitive every other core module sits on, and the single interface through which the backend touches a disk. It is a configured object rather than a loose collection of functions: an instance is built when a session begins, carrying the allowlist of directories that session may reach and the policy it applies to symbolic links, and every read, write, listing, and structural mutation is a method on it. That shape is what makes isolation enforceable rather than advisory — a module cannot reach outside the allowlist by composing a path, because there is no unguarded primitive to compose it into. On top of that guard sit the operations the rest of the backend needs: directory listing, whole-file reads, atomic writes, file metadata, file creation and opening, copy, rename, delete, SHA-256 content checksumming, project ignore-file bookkeeping, and project-root discovery. A third, read-only profile reaches the paths a user selected for the Documents collection (`DCL-documents-collection.md`) and nothing else. The UI never imports these primitives directly; higher-level core modules wrap them into Tauri commands.

## Contract surface
This is an internal Rust API exposed by `synthesis-core` (per the monorepo structure on the Notion Architectural decisions index). Two operations, `browse_for_folder` and `browse_for_save_path`, are additionally exposed as Tauri commands under the same names on the wire (`"browse for folder"` from `../ui/PPK-project-picker.md`, `"browse for save path"` from `../ui/LOG-logs.md`), because a dialog is a request for the user's choice rather than a filesystem operation a higher-level module could perform on the UI's behalf.

### Free functions
Five operations are not methods on the instance, because each is needed either before an instance exists or to establish where one may reach. They read no file content and mutate nothing an instance guards.

- **`browse_for_folder()`** — opens the OS-native folder picker. Returns the selected directory as a `UserChosenPath` or `None` if cancelled. Exposed to the UI as the Tauri command `"browse for folder"` (see `../ui/PPK-project-picker.md`).
- **`browse_for_save_path(default_name)`** — opens the OS-native save-file dialog with `default_name` pre-filled as the suggested filename. Returns the chosen destination as a `UserChosenPath` or `None` if cancelled. It resolves a destination and writes nothing itself. Exposed to the UI as the Tauri command `"browse for save path"` (see `../ui/LOG-logs.md`).
- **`discover_project_root(start_path)`** — walks upward from `start_path` until a directory containing `.synthesis/project.toml` is found. Returns that directory, or a `NotAProject` sentinel if the walk reaches the filesystem root without finding one. Mirrors `git`'s upward-walk for `.git/`. It is a free function because its whole job is to walk out of the directory it was given, which is what an instance exists to forbid, and because it runs to decide what an instance's root should be.
- **`app_data_dir()`** — returns the platform-correct user-scoped data root for Synthesis (e.g. `~/Library/Application Support/synthesis` on macOS). Used by `GSS-global-settings-storage.md` for user-global config, by `PSS-project-settings-storage.md` for the no-project default-layout slot, and by `RMS-repository-machine-storage.md` for the per-repository store of the conversation and statistics logs (RMS-FR-ZXHM). It reports a location and opens nothing, so it answers before any instance is built and its result is one of the roots the IDE instance is then built with (FSA-FR-21).
- **`short_data_dir()`** — returns a second user-scoped root, the OS user's home directory joined with `.synthesis`. It is chosen for the shortness of the paths under it rather than for platform convention, and `GRD-graduation.md` puts a graduation run's whole store there (per `GSU-graduation-start.md` GSU-FR-RJRF), because a run's checkout is the directory an execution turn stands in and the container names the same path the host names (per `../tools/EAC-execute-agent-cli.md` EAC-FR-ZKMR). It reports a location and opens nothing, so it answers before any instance is built and its result is one of the roots the IDE instance is then built with (FSA-FR-21).

### Construction
```
FsAccess::builder()
    .allow_root(path)          // repeatable; at least one required
    .follow_symlinks(bool)     // default false
    .session_temp(bool)        // default false
    .read_only_file(path)      // repeatable; the documents profile only (FSA-FR-DMKC)
    .read_only_folder(path)    // repeatable; the documents profile only (FSA-FR-DMKC)
    .build() -> Result<FsAccess, FsAccessBuildError>
```

`FsAccess` is the guarded handle every operation below hangs off. It is immutable once built — no method widens the allowlist or changes the symlink policy — so a reference handed to a module is a capability of exactly known reach.

The application builds two read-write profiles from this one builder, differing only in which roots they allow, and a third, read-only profile from the read-only grant methods:

| Profile | Roots | Held by |
|---|---|---|
| **IDE** (FSA-FR-21) | active worktree, `app_data_dir()`, `short_data_dir()`, own session temp | the modules serving the application's own surfaces |
| **agent** (FSA-FR-29) | active worktree, own session temp | one per agent session |
| **documents** (FSA-FR-DMKC) | the selected Documents files and folders, read-only | the Documents collection of `DCL-documents-collection.md` |

Both refuse symbolic links, both are read-write across every root they hold, and neither outlives the worktree it was built against. The difference that matters is the two application-owned roots, `app_data_dir()` and `short_data_dir()`: what stands under them is the application's own state rather than any project's, so an agent session has no path to either.

### Instance operations
Every method takes an absolute path and refuses one that resolves outside the allowlist (FSA-FR-10) or that reaches through a symbolic link under the default policy (FSA-FR-17).

- **`list_dir(path)`** → `[DirEntry]` — the immediate children of the directory at `path`, sorted by name, one level deep and never recursive. Each entry reports its own kind, so a symbolic link is listed as a link rather than as the file or directory it points at.
- **`list_dir_reporting(path)`** → `([DirEntry], omitted)` — `list_dir` that also reports how many entries disappeared during the listing and were omitted.
- **`file_info(path)`** → `FileInfo` — the kind, byte size, modification time, and read-only flag of the entry at `path`. Describes the entry itself: a symbolic link reports as a link with its own size, and nothing is resolved to find out what it points at.
- **`read_bytes(path)`** / **`write_bytes_atomic(path, bytes)`** — the durability primitive. Reads pull the whole file into memory and return raw bytes; writes go through a sibling temp file + rename so an interrupted process never leaves a half-written target. Parent directories are created on demand.
- **`read_text(path)`** / **`write_text_atomic(path, text)`** — UTF-8 text convenience over the byte primitives. Used for Markdown artifact bodies and any other text-shaped file the project holds.
- **`read_toml<T>(path)`** / **`write_toml_atomic<T>(path, value)`** — TOML (de)serialisation convenience layered on top of the text primitives. Calls `toml::from_str` after `read_text` and `toml::to_string` before `write_text_atomic`. Provided as a convenience because `.synthesis/*.toml` files are the most common consumer; not a separate durability primitive.
- **`append_lines(path, lines)`** — appends each line of `lines`, newline-terminated, to the end of the file at `path`, opening it in append mode and creating it if it is absent. The write is one call rather than a read-modify-write, so a concurrent append from another process is added alongside rather than overwriting or being overwritten. Backs the append-only JSONL logs of `CMS-comments-storage.md`.
- **`create_file(path, mode)`** where `mode ∈ { Truncate, Exclusive }` — creates a zero-length file at `path`, creating missing parents. `Truncate` empties an existing file; `Exclusive` yields a typed "exists" error if any entry already occupies `path`. Distinct from the write primitives, which create a file *with* content in one atomic step; this one establishes an empty file whose content arrives later.
- **`open_file(path, mode)`** → `FileHandle` where `mode ∈ { ReadOnly, Append, Truncate }` — opens `path` and returns a guarded handle for streaming access. The one path through this module that does not read or write a whole file in a single call.
- **`copy_path(source, dest)`** — copies the file or directory tree at `source` to the new path `dest`. Fails with a typed "exists" error if `dest` already exists; it never overwrites.
- **`rename_path(path, new_name)`** — renames the entry at `path` to the bare basename `new_name` within the same parent directory. Fails with a typed error if `new_name` contains a path separator or if an entry of that name already exists; it never overwrites.
- **`move_path(source, dest)`** — relocates the file or directory tree at `source` to the new path `dest`, which may sit under a different parent. Fails with a typed "exists" error if `dest` already exists and with a typed "invalid destination" error if `dest` lies inside `source`'s own subtree; it never overwrites and never copies.
- **`delete_path(path, recursive)`** — removes the entry at `path`. A file is removed whatever `recursive` says. A directory is removed together with its whole subtree when `recursive` is true, and only when it is already empty when `recursive` is false — a non-empty directory under `recursive = false` yields a typed "not empty" error and nothing is removed, which is what lets a caller learn that a folder has contents without walking it. A missing path is a typed error.
- **`delete_owned_tree(path)`** — removes the directory tree at `path`, which must lie under `app_data_dir()` or `short_data_dir()`. It unlinks a symbolic link it meets instead of refusing the tree and instead of following it. A `path` under any other root is a typed "escapes allowed roots" error, and a missing path is a typed error.
- **`delete_author_tree(path)`** — removes the directory tree at `path`, which must lie under a root the instance was built to remove author trees from (FSA-FR-OWVT). It unlinks a symbolic link it meets instead of refusing the tree and instead of following it. A `path` under any other root, and the root itself, is a typed "escapes allowed roots" error, and a missing path is a typed error.
- **`create_dir(path)`** — creates an empty directory at `path`, creating its missing parents as needed. Fails with a typed "exists" error if any entry already occupies `path`; it never reuses or clears an existing one.
- **`read_regular_bytes(path, max_bytes)`** — reads the whole content of the **regular file** at `path`, for a caller that cannot trust what stands at the path. It opens the file without following a symbolic link and without blocking on a FIFO or a device, checks the opened handle, and refuses a handle that is not a regular file with a typed "not a regular file" error. It reads at most `max_bytes` and refuses a larger file with a typed "too large" error that carries the limit. It never holds more than `max_bytes` plus one chunk in memory.
- **`sha256_file(path)`** — returns the SHA-256 of the file's content as a lowercase hex string. The checksum primitive backing Artifact-model file tracking (Notion: Artifact model → File tracking).
- **`ensure_gitignored(synthesis_dir)`** — guarantees `<synthesis_dir>/.gitignore` exists, ignores at least `cache/` and `local.toml`, and holds no `drafts/` entry (Notion: Project storage → Folder structure).
- **`session_temp_dir()`** → `Option<Path>` — the scratch directory this instance created and allowlisted, or `None` when it was built without one.
- **`write_bytes_at_user_choice(chosen, bytes)`** / **`write_text_at_user_choice(chosen, text)`** — the only writes that reach outside the allowlist, and they accept a `UserChosenPath` alone. Backs the log export of `LGC-logging.md` (LGC-FR-18).
- Errors surface as typed failures distinguishing missing, unreadable, and (for the typed variants) malformed.

### Payload shapes
```
EntryKind = "file" | "dir" | "symlink" | "other"   // "other": a FIFO, socket, or device

DirEntry {
  name,           // the basename, no path
  kind            // EntryKind, describing the entry itself
}

FileInfo {
  kind,           // EntryKind, describing the entry itself
  size,           // bytes
  modified,       // modification instant
  readonly        // whether the entry is write-protected
}

CreateMode = "truncate" | "exclusive"
OpenMode   = "read-only" | "append" | "truncate"

UserChosenPath   // an absolute path a dialog returned; constructible
                 // only by browse_for_folder / browse_for_save_path

FileHandle       // a mode-bound, instance-bound open file (FSA-FR-26)
```

## Functional requirements
1. **FSA-FR-01** `browse_for_folder()` opens the OS-native folder picker via the Tauri `dialog` plugin (which requires a corresponding entry in `src-tauri/capabilities/default.json`) and returns either the selected directory as a `UserChosenPath` or a "cancelled" sentinel; it never throws on user cancellation.
2. **FSA-FR-02** `discover_project_root(start_path)` walks upward from `start_path` and returns the first ancestor (including `start_path` itself) that contains a `.synthesis/project.toml` file.
3. **FSA-FR-03** When `discover_project_root` reaches the filesystem root without finding `.synthesis/project.toml`, it returns a typed "not a project" result; it does not return an arbitrary fallback path.
4. **FSA-FR-04** `write_bytes_atomic` performs the write via a sibling temp file in the same directory followed by `rename`, so that an interrupted process never leaves the target file half-written. `write_text_atomic` and `write_toml_atomic` are layered on top of it and inherit the same guarantee.
5. **FSA-FR-05** Every write primitive creates parent directories as needed before writing.
6. **FSA-FR-06** `read_bytes`, `read_text`, and `read_toml` read the file's entire content into memory and distinguish three error cases: file does not exist, file exists but cannot be read (permissions, I/O), and — for `read_text` only — content is not valid UTF-8, or — for `read_toml` only — content cannot be deserialised into the requested type.
7. **FSA-FR-07** `sha256_file` returns the SHA-256 of the file's exact byte content as a lowercase hex string and reads the file in a streaming manner that does not require holding the full content in memory.
8. **FSA-FR-08** `ensure_gitignored(synthesis_dir)` creates `<synthesis_dir>/.gitignore` if missing and ensures it contains entries that exclude at minimum `cache/` and `local.toml`. It also **removes any entry that ignores `drafts/`**, draft storage being committed (per `DRS-draft-storage.md` DRS-FR-04). Existing user entries are otherwise preserved, missing required entries are appended, and no file outside `<synthesis_dir>/.gitignore` is read or written.
9. **FSA-FR-09** `app_data_dir()` returns a platform-correct user-scoped path that is stable across launches for the same OS user; on first call it creates the directory if it does not exist.
10. **FSA-FR-10** Every instance operation refuses a path that does not resolve inside one of the instance's allowlisted roots, with a typed "escapes allowed roots" error, and performs no filesystem access of any kind before that refusal. The path is normalised lexically first — `.` segments dropped and `..` segments collapsed against their preceding segment, without consulting the disk — and it is the normalised result that must lie inside a root, so a path that climbs out and back in is judged by where it ends rather than by where it passed. An operation taking two paths — `copy_path`, `rename_path`, and `move_path` — requires both to satisfy this, and refuses the pair when either fails. Containment is decided against the whole set of roots rather than against any single one, so a path inside any root is accepted; nothing outside every root is reachable through this module except through the user-choice writes of FSA-FR-28. A symbolic link is the other way out of an allowlisted root, and it is governed by the instance's symlink policy (FSA-FR-17).
11. **FSA-FR-11** `delete_path(path, recursive)` removes the entry at `path`. A file is removed regardless of `recursive`. A directory is removed together with its entire subtree when `recursive` is true; when `recursive` is false it is removed only if it is already empty, and a directory holding any entry at all yields a typed "not empty" error with nothing removed. That error is the module's report that the directory has contents, drawn from the filesystem rather than from any caller's picture of it, so it counts entries the caller may never have been shown. A path that does not exist yields a typed "missing" error, distinct from both an I/O failure and "not empty".
12. **FSA-FR-ZUCF** `delete_owned_tree(path)` removes the directory tree at `path` and unlinks every symbolic link in it rather than following it or refusing the tree. It accepts a `path` under `app_data_dir()` or `short_data_dir()` alone and refuses any other with the typed "escapes allowed roots" error of FSA-FR-10, before it reads or removes anything.
    - *Why:* A graduation run's checkout holds a dependency store built of symbolic links, so the refusal of FSA-FR-17 leaves the application unable to reclaim its own directories.
13. **FSA-FR-12** `rename_path(path, new_name)` renames the entry at `path` to `new_name` within its existing parent directory. `new_name` is a bare basename: a value containing a path separator is rejected with a typed "invalid name" error, and a pre-existing entry at the destination yields a typed "exists" error. The operation never overwrites an existing entry.
14. **FSA-FR-13** `copy_path(source, dest)` copies the file or directory tree at `source` to `dest`, creating parent directories of `dest` as needed (FSA-FR-05). A pre-existing `dest` yields a typed "exists" error; the operation never overwrites.
15. **FSA-FR-14** `create_dir(path)` creates an empty directory at `path`, creating any missing parent directories on the way as the write primitives do (FSA-FR-05). An entry already at `path` — whether a directory or a file — yields a typed "exists" error and nothing is created or modified, so the primitive never adopts, clears, or merges into an existing directory.
16. **FSA-FR-15** `append_lines(path, lines)` opens `path` in append mode, creating the file and its missing parents as the write primitives do (FSA-FR-05), and writes every line of `lines` newline-terminated in a single write call. It never reads, rewrites, or truncates what the file already holds, so an append performed while another process is appending to the same file adds to it rather than replacing it. An empty `lines` writes nothing and creates nothing.
17. **FSA-FR-16** `browse_for_save_path(default_name)` opens the OS-native save-file dialog via the Tauri `dialog` plugin (which requires a corresponding entry in `src-tauri/capabilities/default.json`) with `default_name` pre-filled, and returns either the chosen destination as a `UserChosenPath` or a "cancelled" sentinel; it never throws on user cancellation, exactly as FSA-FR-01 does not. It creates, opens, and writes nothing at the returned path, so a caller that never follows up leaves the filesystem untouched.
18. **FSA-FR-17** An instance follows no symbolic link unless it was built with `follow_symlinks(true)`, and the default is `false`. Under the default, a path is refused with a typed "symlink refused" error, before anything is read, written, created, or removed, when its final component is a symbolic link or when any ancestor component on the way to it is one. `delete_path` and `copy_path`, which walk a subtree rather than touching a single entry, apply the same rule to the whole tree they would traverse and refuse before removing or copying anything, so a refusal never leaves a half-removed or half-copied result. A symbolic link is therefore never created, read, written, copied, renamed, or followed by such an instance, whether it points inside an allowlisted root or outside it. `delete_owned_tree` and `delete_author_tree` are the only operations that remove a link (FSA-FR-ZUCF, FSA-FR-OWVT), and each unlinks it rather than following it, so it reaches no target either — the rule is about the link, not about its target, so it holds without the instance ever resolving one to find out where it goes. Refusal is the whole behaviour: no operation silently skips a link and proceeds with the rest. `list_dir` and `file_info` are the two exceptions, and only because they report rather than traverse: each names a link as a link (FSA-FR-22, FSA-FR-23) without resolving it, while a link among the path's *ancestors* refuses both, since reaching the entry at all would mean traversing one.
19. **FSA-FR-18** An `FsAccess` is constructed only through `FsAccess::builder()`, which takes at least one `allow_root`, `read_only_file`, or `read_only_folder` and yields a typed build error when given none. Each root is canonicalised at build time — the one symbolic-link resolution that happens whatever the instance's policy, because it establishes the root's own identity rather than traversing to a target, and without it a root reached through a link (`/tmp` on macOS) would contain none of the paths resolved beneath it. A root that does not exist, that is not a directory, or that cannot be canonicalised yields a typed build error and no instance. The built instance is immutable: no method adds a root, removes one, or changes the symlink policy, so a handle's reach is fixed for its whole lifetime and can be reasoned about from where it was built.
20. **FSA-FR-19** Every operation except `browse_for_folder`, `browse_for_save_path`, `discover_project_root`, `app_data_dir`, and `short_data_dir` is a method on an `FsAccess` instance; there is no free function through which any file is read, written, created, listed, or removed. Every such method requires an absolute path, and a relative one is refused with a typed "relative path" error before any filesystem access, because an instance holding several roots has no single directory to resolve it against — a caller with a project-relative path resolves it against the root it means first, as `PST-project-storage.md` PST-FR-26 does.
21. **FSA-FR-KVWD** `short_data_dir()` returns the OS user's home directory joined with `.synthesis`, a path stable across launches for the same OS user; on first call it creates the directory if it does not exist. It stands one segment below the home directory because what lives under it is read as a working directory by an agent in a container as well as by this application, and every segment of such a path is read by that agent on each command it runs.
22. **FSA-FR-20** A builder given `session_temp(true)` creates a fresh directory under the OS temporary location, unique to this instance and to this run, adds it to the allowlist, and reports it from `session_temp_dir()`; a builder without it leaves `session_temp_dir()` returning `None`. The instance owns that directory's whole life: it is empty when the instance is built, and dropping the instance removes it with its entire contents, so a session leaves nothing behind whether it ended by closing the project or by the process exiting normally. Two instances alive at once hold two distinct temp directories and neither can reach the other's, since a directory is allowlisted only for the instance that made it.
23. **FSA-FR-21** The application builds an **IDE instance** at project open, with four roots — the project's active worktree (`WTC-worktree-context.md` WTC-FR-03), `app_data_dir()`, `short_data_dir()`, and a session temp directory (FSA-FR-20) — and with `follow_symlinks` left at its default of `false`. It is the instance every backend module serving the application's own surfaces reaches the filesystem through, and the only one of the two profiles that reaches either application-owned root, because user-global settings and a graduation run's store are the application's own state rather than any project's. Before any project is open the application holds an IDE instance built with `app_data_dir()`, `short_data_dir()`, and a session temp directory alone, which is what lets `GSS-global-settings-storage.md` serve the recent-projects list on a fresh machine (GSS-FR-01) and `LGC-logging.md` answer with no content root (LGC-FR-20). Opening a project, and changing the active worktree (`WTC-worktree-context.md` WTC-FR-08), each replace it with a newly built one rather than mutating the old, so the outgoing worktree stops being reachable at the moment it stops being active.
24. **FSA-FR-22** `list_dir(path)` returns the immediate children of the directory at `path` as `DirEntry` values sorted by name, and descends into nothing: a child directory contributes one entry and none of its own contents. Each entry's `kind` describes that entry itself, so a symbolic link is reported as `symlink` and never as the file or directory it points at, and an entry that is neither a regular file, a directory, nor a link — a FIFO, a socket, or a device — is reported as `other` and never as `file`. An entry that disappears between the directory read and its description is omitted, and the listing still succeeds; `list_dir_reporting(path)` answers with the same entries and the number of entries it omitted, so a caller can record the omission. No filter is applied — every child the operating system reports is returned, hidden and ignored files included, because deciding what to omit belongs to the caller that knows why (`ASC-artifact-scanning.md` ASC-FR-09 excludes for the scan, ASC-FR-23 drops the links). A `path` that does not exist yields a typed "missing" error and one naming a file rather than a directory yields a typed "not a directory" error, each distinct from an unreadable-directory I/O failure.
25. **FSA-FR-23** `file_info(path)` returns the `FileInfo` of the entry at `path` without reading its content, so its cost does not scale with file size. It describes the entry itself and resolves nothing: a symbolic link reports `kind = "symlink"` with the link's own size and modification time, never its target's, which is what makes it usable for deciding whether a path is a link at all. A `path` that does not exist yields a typed "missing" error, distinct from an entry that exists but cannot be stat'd.
26. **FSA-FR-24** `create_file(path, mode)` creates a zero-length file at `path`, creating missing parent directories as the write primitives do (FSA-FR-05). Under `Exclusive` an entry already at `path` — file or directory alike — yields a typed "exists" error with nothing created or modified, and the check and the creation are one operation at the filesystem level rather than a test followed by a write, so two callers racing to create the same path cannot both succeed. Under `Truncate` an existing file is emptied and an existing *directory* still yields the typed "exists" error, because truncating a directory means nothing. Either mode leaves the file present and empty on success.
27. **FSA-FR-25** `open_file(path, mode)` returns a `FileHandle` over `path`. `ReadOnly` requires the file to exist and yields a typed "missing" error otherwise, creating nothing. `Append` creates the file when absent and positions every write at the end, never disturbing what the file already holds. `Truncate` creates the file when absent and empties it when present. `Append` and `Truncate` create missing parent directories (FSA-FR-05); `ReadOnly` creates nothing at all, parents included. The path is validated on the terms of FSA-FR-10 and FSA-FR-17 before the file is opened, so a refused path never yields a handle.
28. **FSA-FR-26** A `FileHandle` is bound to the instance that opened it and to the mode it was opened with. It exposes no way to name another path, so it cannot be re-targeted after the containment check that produced it, and it does not outlive its instance. Its mode is enforced on every call rather than only at open: a write through a `ReadOnly` handle and a read through an `Append` or `Truncate` handle each return a typed "wrong mode" error and change nothing. Writes through a handle reach the file directly and are therefore the one write path in this module outside the temp-file-and-rename guarantee of FSA-FR-04 — a process that dies mid-write leaves whatever it had written — which is the price of streaming a file too large to hold in memory and of the append-only logs that want their bytes on disk before the next record is formed. Dropping a handle flushes and closes it.
29. **FSA-FR-27** An instance built with `follow_symlinks(true)` resolves each symbolic link it meets and validates the resolution against FSA-FR-10 rather than accepting it. Validation is recursive: a link pointing at another link is followed through the whole chain, and *every* hop — each intermediate target and the final one — must resolve inside an allowlisted root, so a chain that leaves the allowlist at any hop is refused with the typed "escapes allowed roots" error even when its last target lands back inside. The rule applies to links found among a path's ancestors exactly as to one at its final component, and to every link encountered while walking the subtree of a `delete_path` or `copy_path`, which is refused before anything is removed or written just as under the default policy. A chain that revisits a link it has already followed, or that exceeds a bounded number of hops, is refused with a typed "symlink cycle" error rather than followed further.
30. **FSA-FR-28** `write_bytes_at_user_choice(chosen, bytes)` and `write_text_at_user_choice(chosen, text)` write to a destination the user picked in a dialog, and they accept a `UserChosenPath` and nothing else — a path expressed as a string or a plain path value does not reach them, so the exemption cannot be taken by a caller that merely composed a path. A `UserChosenPath` is constructed only by `browse_for_folder` and `browse_for_save_path` (FSA-FR-01, FSA-FR-16) and by no other means, which makes holding one proof that the user chose that location in this session. These two writes are exempt from FSA-FR-10 and from FSA-FR-10 alone: they retain the atomicity of FSA-FR-04, they create parent directories as FSA-FR-05 requires, and they replace an existing file at the destination, since choosing an occupied path in a save dialog is how a user asks for it to be replaced. Every other operation on the instance remains bound to the allowlist whatever the caller holds.
31. **FSA-FR-29** The application builds an **agent instance** for each agent session it runs, with two roots — the same active worktree the IDE instance holds, and a session temp directory of its own (FSA-FR-20) — and with `follow_symlinks` left at its default of `false`. `app_data_dir()` is not among them, so the recent-projects list, the token registry, and every other user-global record are unreachable from an agent session by any path it could compose, rather than merely out of bounds to the callers that behave. Both roots are read-write: an agent acts on the project it was pointed at, and this module bounds where it may reach rather than what it may do there. Two sessions running at once hold two instances and two temp directories, and neither can reach the other's (FSA-FR-20), so one session's scratch work is invisible to the next as well as to the one beside it. An agent instance is built only while a project is open and never against a closed one, and it is discarded exactly when the IDE instance is — on project close (`PST-project-storage.md` PST-FR-14) and on a change of active worktree (`WTC-worktree-context.md` WTC-FR-08) — taking its temp directory with it, so no instance outlives the root it was built against and no session keeps reading a checkout the application has stopped showing. An agent session is begun and ended by `../ai/CVL-conversation-loop.md` (CVL-FR-24), which runs one per conversational turn; what is fixed here is the reach an instance has for as long as one holds it.
32. **FSA-FR-30** `move_path(source, dest)` relocates the entry at `source` to `dest`, which need not share `source`'s parent, creating parent directories of `dest` as needed (FSA-FR-05). It is `rename_path`'s counterpart across parents (FSA-FR-12) and the only primitive that relocates a subtree without copying it: a directory arrives whole, with everything beneath it, in one operation whose cost does not grow with what it holds, which is what lets a caller reorganise a tree of files it must not duplicate. A pre-existing `dest` yields a typed "exists" error and the operation never overwrites; a `dest` lying inside `source`'s own subtree, `source` itself included, yields a typed "invalid destination" error, so nothing is ever moved into itself; a missing `source` yields a typed "missing" error. Both paths are validated on the terms of FSA-FR-10, and the subtree is checked for symbolic links on the terms of FSA-FR-17 before anything is moved. Within one filesystem the relocation is atomic at the OS level; across filesystems it is not, and a failure partway may leave a partial result on the terms the other structural mutations do (Non-functional requirements).
33. **FSA-FR-DMKC** The application builds one **documents instance** while a project is open. Its reach is exactly the Documents sources of `DCL-documents-collection.md`: each selected folder and everything below it, and each selected file and nothing else. It holds no worktree root, no `app_data_dir()`, no `short_data_dir()`, and no session temp directory. It follows no symbolic link (FSA-FR-17).
34. **FSA-FR-UKAE** An instance built with a read-only grant refuses every operation that writes, creates, copies into, renames, moves, deletes, or opens for writing, with the typed error "read only", before any filesystem access. It allows `list_dir`, `file_info`, `read_bytes`, `read_regular_bytes`, `read_text`, `sha256_file`, and `open_file` in `ReadOnly` mode. A read-only grant and a read-write root never share one instance.
35. **FSA-FR-TXZU** A selected Documents path never widens any other instance. The IDE instance (FSA-FR-21), every agent instance (FSA-FR-29), and the pre-project instance gain no selected path. An agent reads a selected document only through the tools of `../tools/GDT-get-document-tool.md`, which resolve a document id through the collection.
36. **FSA-FR-KAQV** `read_only_file(path)` and `read_only_folder(path)` canonicalise the **ancestors** of the granted path at build time, as FSA-FR-18 does for a root. A granted path whose final component is a symbolic link, that does not exist, or that is the wrong kind yields a typed build error for that path.
37. **FSA-FR-GHBN** Containment on a documents instance is judged after the lexical normalisation of FSA-FR-10. A file grant contains its exact canonical file path and nothing else. A folder grant contains that folder and its subtree.
38. **FSA-FR-WBKZ** The application keeps one documents instance while a project is open and discards it on project close (`PST-project-storage.md` PST-FR-14). It rebuilds the instance only when the set of grantable Documents sources changes: a stored source is added or removed, or the path of a stored source becomes grantable or stops being grantable. A refresh that finds the same set of grantable sources keeps the same instance. Each refresh re-probes every stored source without a rebuild, so availability is reported at the time of the refresh. A removed source's path is refused from the rebuild on. A change of active worktree does not rebuild it. While no source is grantable, no documents instance exists.
39. **FSA-FR-NRQE** `read_regular_bytes(path, max_bytes)` reads only a regular file. A FIFO, a socket, a device, a directory, and a symbolic link are each refused without a read that can block, and a file larger than `max_bytes` is refused with a typed "too large" error after at most `max_bytes` plus one chunk of its content has been read. The check is made on the opened handle, so a path that is replaced after a metadata check cannot make the read block or run without a bound.
40. **FSA-FR-LKTD** A read-only instance checks the granted path itself on every operation that traverses to it, not only at build time. When the granted file, or the granted folder that contains the path, is a symbolic link at the time of the operation, the operation is refused with the typed "symlink refused" error and reads nothing. A file grant that is replaced by a symbolic link after the build reaches nothing, whatever the link points at.

41. **FSA-FR-OWVT** `delete_author_tree(path)` removes the directory tree at `path` and unlinks every symbolic link in it rather than following it or refusing the tree. It accepts a `path` strictly under an **author root** alone. An author root is a directory the caller names when it builds the instance, and the root itself is never removed. A `path` under no author root, or equal to one, is refused with the typed "escapes allowed roots" error of FSA-FR-10 before anything is read or removed. A symbolic link among the components between the root and the tree is refused as FSA-FR-17 refuses it; only the tree below the target is exempt. No instance the application builds for the IDE, an agent session, or the documents profile has an author root (FSA-FR-21, FSA-FR-29, FSA-FR-DMKC). The only caller is the removal of a linked worktree (`WTC-worktree-context.md` WTC-FR-RDVK), which names the worktree's parent directory so that the reach is that one worktree and nothing beside it.
    - *Why:* A linked worktree is the author's own directory, and installed dependencies in it are symbolic links that no dirty-path list shows. The refusal of FSA-FR-17 would leave a branch deletion failing at its last step, and `delete_owned_tree` reaches application-owned roots alone.

## Non-functional requirements
- An `FsAccess` is `Send + Sync` and shared as an `Arc` rather than cloned per module: an instance is a capability handed to the modules that share its reach, not something a module mints for itself, since a module building its own would be a module choosing its own allowlist. How many exist is decided by how many distinct reaches the application needs — one for its own surfaces and one per agent session (FSA-FR-21, FSA-FR-29) — and never by how many modules want a handle. All filesystem operations are synchronous from the caller's perspective; concurrency is owned by callers, not this module.
- The builder is the whole configuration surface, and its defaults are the safe ones — links refused, no temp directory — so the permissive settings are the ones a caller has to name. Construction is fallible and validates once, at build, rather than re-validating roots on every call.
- A path returned by `browse_for_save_path` may already hold a file; the user-choice writes replace it (FSA-FR-28), and nothing else in this module can reach it.
- `append_lines` and the handle writes are the write paths that are not temp-file-and-rename: a single small append is atomic at the OS level, which is what makes a shared append-only log safe for two writers, and the temp-and-rename guarantee of FSA-FR-04 would destroy that by replacing the whole file.
- Durability primitive is byte-level. Text and TOML helpers are thin convenience layers; new serialisation formats (e.g. JSON for a future plugin manifest) are added at the convenience layer, not by introducing parallel durability primitives.
- Atomic writes are the only durability story; there is no journal or write-ahead log.
- Structural mutations (`delete_path`, `delete_owned_tree`, `rename_path`, `move_path`, `copy_path`) are not transactional: `rename_path` and `move_path` are atomic at the OS level within a single filesystem, but a `move_path` across filesystems, or a `delete_path` or `copy_path` over a large tree, that fails partway may leave a partially-moved, partially-removed, or partially-copied subtree. They share the synchronous, caller-owned-concurrency contract of the other primitives and add no journal. The symlink checks of FSA-FR-17 and FSA-FR-27 are the exception that is settled up front rather than encountered partway, precisely so a link found deep in a tree does not produce one of those partial results. `delete_owned_tree` and `delete_author_tree` need no such check, a link being one more entry they unlink.
- Refusing symbolic links outright is the default because it is the cheap and total reading of FSA-FR-10: a link that resolves inside a root today may point outside it tomorrow without any path the instance was given having changed, so the target-based validation of FSA-FR-27 is only as good as the moment it ran and has to be paid again on every access. An instance that follows links accepts that cost knowingly; neither instance the application builds takes it (FSA-FR-21, FSA-FR-29).
- The `recursive = false` mode of `delete_path` is the module's emptiness probe as well as its narrow delete: a caller that wants to know whether a directory has contents attempts the removal and reads the typed "not empty" error, rather than enumerating the directory itself and deciding from a listing that may be filtered.
- This module writes no log records of its own. A refusal is reported to its caller as a typed error and nothing else, which is what lets `PST-project-storage.md` PST-FR-26 log exactly one record for a path that both it and this module would reject.
- Containment is enforced structurally rather than by convention: because the guarded operations exist only as methods on an instance, a module cannot reach a file by importing a primitive, and a review looking for unguarded access needs to find raw `std::fs` calls rather than audit every path expression.
