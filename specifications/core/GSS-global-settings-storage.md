# Global settings storage

**Spec code:** `GSS`

## Intent
The persistence home for every **user-global** (cross-project, per-machine) setting: app-level preferences — the theme, the fonts the application sets text in, the main window's OS full-screen state, whether the vertical panel's selection follows the active tab, and the width the graduation history rail is proportioned to — the recent-projects list, the installed-plugin registry, the installed-adapter registry, the descriptions of the author's stored GitHub tokens, the two AI integration registries — one for agentic backends and one for AI API providers — the registry of conversational agents the author has described, the **Docker backend** the application reaches a container runtime through, with the verification state that backend last earned, and the **relay endpoint** the application reaches a remote client through, with the verification state that endpoint last earned. It additionally holds the per-project facts that must not live inside the project on disk — the shell's layout preferences, the project's active worktree, the GitHub token the project uses, the agentic and AI API integrations it overrides to, and the reference documents it selects — because a project's `.synthesis/` is committed content that exists once per worktree, and those facts have to be stable across worktrees and readable before any worktree has been chosen. These facts survive across projects, are never written into a project's `.synthesis/`, and are never synced. This module is the backend half of `../ui/GLS-global-settings.md`; project-scoped settings that do belong inside the project live in the paired `PSS-project-settings-storage.md`.

## Contract surface
The module owns one persisted store (`synthesis.toml` under `FSA-filesystem-access.md::app_data_dir()`) and the Tauri commands that read and mutate it.

### Storage scope
- **User-global** — `app_data_dir()/synthesis.toml`. Holds **app preferences** (theme, per-role font settings, main-window full-screen state, selection-follows-tab, graduation rail width), the **recent-projects list**, the **installed plugin registry**, the **installed agent adapter registry**, the **GitHub token registry** (descriptions only — no secret, GSS-FR-22), the **agentic integration registry** and the active agentic integration (GSS-FR-14), the **AI API provider registry** and the active provider (descriptions only — no key, GSS-FR-27), the **conversational agent registry** (GSS-FR-30), the **Docker backend configuration** and its verification state (GSS-FR-35), the **relay endpoint** and its validation state (GSS-FR-ZKQT), and a **per-project slot** keyed by project holding that project's **layout preferences**, its **active worktree**, its **GitHub token binding**, its **agentic integration override**, its **AI API integration override**, its **enrolled agents** (GSS-FR-31), and its **document sources** (GSS-FR-CDYK). Survives across projects; not synced; never written into a project.

### Tauri commands

App preferences (per `../ui/GLS-global-settings.md` Appearance, Navigation, and Notifications sections, `../ui/OVW-overview.md` OVW-FR-13, `../ui/SNV-shell-navigation.md` SNV-FR-15 / SNV-FR-16 / SNV-FR-38 / SNV-FR-64, `../ui/SCH-search.md` SCH-FR-13, `../ui/DFV-diff-viewer.md` DFV-FR-23, `../ui/CHG-changes.md` CHG-FR-34, `../ui/NTF-notifications.md` NTF-FR-12, and `../ui/GRH-graduation-history.md` GRH-FR-MCHQ):
- `"load app preferences"` → `load_app_preferences` → `{ theme: "light" | "dark" | "system", main_window_fullscreen: bool, search_query_mode: "literal_insensitive" | "smart_case" | "regex", diff_visualization_mode: "unified" | "side_by_side" | "final", diff_rendering_mode: "source" | "rich", changes_commit_action: "commit" | "commit_and_push" | "push", notifications_enabled: bool, selection_follows_tab: bool, graduation_rail_width_fraction: number, graduation_paths_width_fraction: number, git_files_width_fraction: number, fonts: { ui: FontRole, rich: FontRole, source: FontRole } }`
- `"save app preferences"` → `save_app_preferences(prefs)` — whole-record write of that same shape

```
FontRole {
  family?,       // family name as chosen from `FNT-font-enumeration.md`; unset means the built-in default face for the role
  size_px?,      // unset means the built-in default size for the role
  line_height?   // multiplier of the role's font size; unset means the built-in default for the role
}
```

Recent projects (per `../ui/GLS-global-settings.md` Recent projects section and `../ui/PPK-project-picker.md`):
- `"list recent projects"` → `list_recent_projects`
- `"remove recent project"` → `remove_recent_project(path)`
- `"clear recent projects"` → `clear_recent_projects`
- `"pin recent project"` → `pin_recent_project(path)`
- `"unpin recent project"` → `unpin_recent_project(path)`

Plugin registry (per `../ui/GLS-global-settings.md` Installed plugins section; see `PLG-plugins-system.md`):
- `"list installed plugins"` → `list_installed_plugins` (registry is user-global; per-project enablement annotation is project-public, owned by `PSS-project-settings-storage.md`)
- `"install plugin (source)"` → `install_plugin`
- `"uninstall plugin"` → `uninstall_plugin` (writes user-global registry; cascades a disable into project-public)

Adapter registry (per `../ui/GLS-global-settings.md` Installed adapters section):
- `"list agent adapters"` → `list_agent_adapters`
- `"install adapter (source)"` → `install_adapter`

GitHub token registry (no UI consumer here; read and written by `GTS-github-token-storage.md`, which exposes the commands `../ui/GHA-github-authentication.md` invokes):
- `load_github_token_registry()` / `save_github_token_registry(records)` — the descriptive records of GSS-FR-22. Secrets are not part of this store at all; they live in the application secret vault (`ASV-application-secret-vault.md` ASV-FR-01, per `GTS-github-token-storage.md` GTS-FR-01).

Agentic integration registry (no UI consumer here; read and written by `AIC-agentic-integrations.md`, which exposes the commands `../ui/AII-ai-integrations.md` invokes):
- `load_agentic_registry()` / `save_agentic_registry(records, active_vendor)` — the per-vendor records and the active choice of GSS-FR-14. No credential is part of this store: every agent credential — an API-kind backend's key, Claude Code's OAuth token, and Claude Code's gateway token — lives in the application secret vault (`ASV-application-secret-vault.md` ASV-FR-01, per `AIC-agentic-integrations.md` AIC-FR-20).

AI API provider registry (no UI consumer here; read and written by `AAP-ai-api-integrations.md`, which exposes the commands `../ui/AII-ai-integrations.md` invokes):
- `load_ai_api_registry()` / `save_ai_api_registry(records, active_provider)` — the descriptive per-provider records and the active choice of GSS-FR-27. Keys are not part of this store at all; they live in the application secret vault (`ASV-application-secret-vault.md` ASV-FR-01, per `AAP-ai-api-integrations.md` AAP-FR-07).

Conversational agent registry (no UI consumer here; read and written by `AGR-agent-registry.md`, which exposes the commands `../ui/AGT-agents.md` invokes):
- `load_agent_registry()` / `save_agent_registry(agents)` — the agent records of GSS-FR-30. No key is part of this store: the key behind the active AI API provider lives in the application secret vault (`AAP-ai-api-integrations.md` AAP-FR-07), and an agent record names no provider.

Docker backend (per `../ui/GLS-global-settings.md` Docker section):
- `"load docker backend"` → `load_docker_backend` → `DockerBackend`. Reads the stored record; runs no executable and reaches no daemon.
- `"save docker backend"` → `save_docker_backend(config)` → `DockerBackend`. Persists the selected mode, endpoint, and CLI path, and returns the record with the verification state those values carry (GSS-FR-39).
- `"detect docker cli binary"` → `detect_docker_cli_binary` → `{ path: string | null }`. Locates a candidate executable; persists nothing and executes nothing.
- `"verify docker backend"` → `verify_docker_backend(config)` → `DockerBackend` on success, or a typed error. Docker CLI mode fails with `cli_path_empty`, `cli_not_found`, `cli_not_executable`, `not_the_docker_cli`, `daemon_unreachable`, or `timed_out`; Docker Engine mode fails with `endpoint_empty`, `endpoint_invalid`, `daemon_unreachable`, or `timed_out`.

```
DockerBackendMode = "bollard" | "docker_cli"

DockerEndpoint =
    "automatic"                  // the platform's own default location
  | { unix_socket: string }      // an absolute socket path
  | { windows_pipe: string }     // a named pipe
  | { tcp: string }              // a URL

DockerBackendConfig {
  mode:      DockerBackendMode,  // defaults to "bollard"
  endpoint:  DockerEndpoint,     // defaults to "automatic"
  cli_path:  string | null       // docker_cli mode only
}

DockerBackend {
  mode, endpoint, cli_path,
  state:           "unverified" | "verified",
  server_version:  string | null,
  verified_at:     timestamp | null
}
```

Remote connectivity (per `../ui/GLS-global-settings.md` Remote connectivity section):
- `"load relay endpoint"` → `load_relay_endpoint` → `RelayEndpoint`. Reads the stored record; reaches no network.
- `"save relay endpoint"` → `save_relay_endpoint(url)` → `RelayEndpoint`. Persists the URL and returns the record with the validation state that URL carries (GSS-FR-NLDC).
- `"verify relay endpoint"` → `verify_relay_endpoint(url)` → `RelayEndpoint` on success, or a typed error: `endpoint_empty` for an empty URL, `endpoint_invalid` for one that is not a well-formed absolute URL, `scheme_unsupported` for a scheme that is neither `http` nor `https`, `unreachable` when nothing answered, `timed_out` when the bound was exceeded, `not_a_relay` for an answer that is not the health object, and `capability_missing` for a health response that omits a capability the application needs.

```
RelayEndpoint {
  url:            string | null,   // unset until the author gives one
  state:          "unset" | "unverified" | "verified",
  version:        string | null,   // the relay version the last success reported
  capabilities:   string[],        // the identifiers the last success reported
  verified_at:    timestamp | null
}
```

Per-project slot (no UI consumer; read and written by other core modules):
- `load_project_layout(project_key)` / `save_project_layout(project_key, prefs)` — backs the `"load layout preferences"` / `"save layout preferences"` commands `PSS-project-settings-storage.md` exposes to the shell (PSS-FR-06).
- `load_active_worktree(project_key)` / `save_active_worktree(project_key, path)` — read and written by `WTC-worktree-context.md` (WTC-FR-17).
- `load_github_token_binding(project_key)` / `save_github_token_binding(project_key, token_id)` — read and written by `GTS-github-token-storage.md` (GTS-FR-11).
- `load_agentic_override(project_key)` / `save_agentic_override(project_key, vendor)` — read and written by `AIC-agentic-integrations.md` (AIC-FR-18).
- `load_ai_api_override(project_key)` / `save_ai_api_override(project_key, provider)` — read and written by `AAP-ai-api-integrations.md` (AAP-FR-18).
- `load_project_agent_enrolment(project_key)` / `save_project_agent_enrolment(project_key, agent_ids)` — read and written by `AGR-agent-registry.md` (AGR-FR-12).
- `load_document_sources(project_key)` / `save_document_sources(project_key, sources)` — the source references of GSS-FR-CDYK, read and written by `DCL-documents-collection.md` (DCL-FR-HNRM).

Internal (no UI consumer; not a Tauri command and unreachable from the frontend):
- `resolve_docker_backend()` — returns the verified backend a container or a build operation is performed through, `{ mode: "bollard", endpoint }` or `{ mode: "docker_cli", cli_path }`, or the typed refusal `docker_backend_unverified`. It reads the stored record and probes nothing (GSS-FR-40). Called by `PSS-project-settings-storage.md`'s project image build (PSS-FR-26) and by `../tools/EAC-execute-agent-cli.md`'s runtime seam (EAC-FR-39).

The MRU append on project open/create is performed by `PST-project-storage.md` (PST-FR-06), which writes into this module's store; this module owns the store and its management commands, PST is an appender.

## Functional requirements
1. **GSS-FR-01** User-global config is read from `app_data_dir()/synthesis.toml` (from `FSA-filesystem-access.md`). On first launch the file does not exist; reads return defaults and the first save creates the file.
2. **GSS-FR-02** The user-global store holds app preferences, the recent-projects list, the installed-plugin registry, the installed-adapter registry, the GitHub token registry, the agentic integration registry, the AI API provider registry, the Docker backend configuration, the relay endpoint, and a per-project slot carrying each project's layout preferences, active worktree, GitHub token binding, agentic integration override, AI API integration override, enrolled agents, and document sources; none of these are ever written into a project's `.synthesis/` (the project scopes are owned by `PSS-project-settings-storage.md` PSS-FR-01).
3. **GSS-FR-03** Every save command writes the store atomically via `FSA-filesystem-access.md::write_toml_atomic`.
4. **GSS-FR-04** `load_app_preferences` returns the persisted app-preferences record — `theme ∈ { light, dark, system }`, defaulting to `system` when unset, `main_window_fullscreen` (GSS-FR-19), `search_query_mode` (GSS-FR-21), the two diff-viewer modes (GSS-FR-24), `changes_commit_action` (GSS-FR-25), `notifications_enabled` (GSS-FR-32), `selection_follows_tab` (GSS-FR-33), `graduation_rail_width_fraction` (GSS-FR-34), `graduation_paths_width_fraction` (GSS-FR-QDNV), `git_files_width_fraction` (GSS-FR-MSPQ), and the three typographic roles' font settings (GSS-FR-29) — and `save_app_preferences` persists it. These commands back the `../ui/GLS-global-settings.md` Appearance section, the shell top-chrome theme selector (`../ui/SNV-shell-navigation.md` SNV-FR-15 / SNV-FR-16), and the shell's full-screen tracking (SNV-FR-38); the theme entry points read and write the one stored theme value. Live OS tracking for `system` and app-wide application of the theme are owned by `../ui/OVW-overview.md` (OVW-FR-09 / OVW-FR-10); this module only persists the chosen value.
5. **GSS-FR-05** `list_recent_projects` returns entries `{ name, path, last_opened, pinned, missing }` ordered pinned-first and then most-recent-first within each group. Each entry is one project, and its `path` is the project's anchor: the repository's primary worktree when the project is inside a Git repository (per `WTC-worktree-context.md` WTC-FR-18), and the project root itself when it is not.
6. **GSS-FR-06** `list_recent_projects` prunes unpinned entries whose `.synthesis/project.toml` no longer exists at the entry's recorded path; a pinned entry whose project is missing is retained and flagged `missing = true` rather than pruned. A linked worktree being removed never prunes an entry, the recorded path being the primary worktree.
7. **GSS-FR-07** The unpinned portion of the recent-projects list is bounded to a maximum length; opening or creating beyond the cap evicts the oldest unpinned entry. Pinned entries are exempt from the cap.
8. **GSS-FR-08** `remove_recent_project(path)` removes a single entry and `clear_recent_projects()` removes all entries. Neither deletes any project directory on disk; they only mutate the list.
9. **GSS-FR-09** `pin_recent_project(path)` and `unpin_recent_project(path)` toggle an entry's `pinned` flag in user-global; the flag governs ordering (GSS-FR-05), pruning (GSS-FR-06), and capping (GSS-FR-07).
10. **GSS-FR-10** The recent-projects MRU append on successful project open/create is performed by `PST-project-storage.md` PST-FR-06 writing into this store; this module owns persistence and the listing/management commands, and PST does not define them.
11. **GSS-FR-11** `list_installed_plugins`, `install_plugin(source)`, and `uninstall_plugin(id)` operate on the user-global plugin registry; plugin **enablement** is project-public and owned by `PSS-project-settings-storage.md`. `uninstall_plugin` cascades a disable of the plugin in the currently-open project (if any) so that `list_installed_plugins` never returns enablement entries referencing a missing plugin (`PLG-plugins-system.md` relies on this cascade).
12. **GSS-FR-12** `list_agent_adapters` and `install_adapter(source)` operate on the user-global adapter registry; adapter **configuration** is project-public and owned by `PSS-project-settings-storage.md`.
13. **GSS-FR-13** Reading a missing or malformed `synthesis.toml` does not panic; the store is repaired to defaults and the defaults are persisted on the next save.
14. **GSS-FR-14** The user-global store holds the **agentic integration registry**: one record per supported vendor carrying the configuration fields that vendor has — a binary path and how it was arrived at for a CLI-kind backend, a base URL for an API-kind one, the masked hint of a credential for whichever vendor holds one, and for Claude Code its authentication mode, its gateway base URL, its gateway token variable name, the masked hint of its gateway token, and its author-supplied environment variables — together with the version and timestamp of its last successful verification, its model list and the origin of that list, the model chosen as its default together with the per-turn-kind model overrides that stand above that default, the reasoning effort chosen as its default together with the per-turn-kind effort overrides that stand above that one (`AIC-agentic-integrations.md` AIC-FR-10), and which single vendor is the active integration across both kinds (the shapes `AIC-agentic-integrations.md` AIC-FR-02 defines). No credential is present in this store in any form: an API-kind backend's key, Claude Code's OAuth token, and Claude Code's gateway token all live in the application secret vault (the gateway token under the id `claude_code_gateway`), and Codex and OpenCode hold no credential at all (`AIC-agentic-integrations.md` AIC-FR-20). This module persists the records and interprets none of them: detection, verification, model probing, and the single-active rule are owned by `AIC-agentic-integrations.md`.
15. **GSS-FR-15** All commands above exist with typed payloads in the walking-skeleton build. Stub implementations may keep state in memory and persist nothing, provided the same shape is returned to the UI.
16. **GSS-FR-16** The per-project slot records the project's **active worktree** path, written by `WTC-worktree-context.md` (WTC-FR-17) whenever it changes and read back when that project is next opened. It is user-global rather than project-local, having to be readable before any worktree has been chosen. A project with no recorded worktree — or one whose recorded worktree no longer exists — reads back as unset, so the caller falls back to the primary worktree.
17. **GSS-FR-17** The per-project slot records the project's **layout preferences** — the vertical panel's width as a fraction of the shell's inner width, the bottom panel's height, the bottom panel's active surface, panel side, collapse/hide state, the main window's outer size and maximized state, and the split ratio each draft's discussion was last read at, keyed by draft id — which back the `"load layout preferences"` / `"save layout preferences"` commands `PSS-project-settings-storage.md` exposes (PSS-FR-06). Holding them here rather than in a project's `.synthesis/local.toml` is what keeps the shell's shape stable as the active worktree changes (per `../ui/SNV-shell-navigation.md` SNV-FR-08). The panel width is stored as a fraction rather than a pixel count, so a project restored on a display of a different size keeps its proportions; the clamping of that fraction is owned by the shell (`../ui/SNV-shell-navigation.md` SNV-FR-34) and this module stores whatever value it is given.
18. **GSS-FR-18** A recent-projects entry and a per-project slot are keyed by project, not by directory. Opening a path that resolves into a repository already represented in the list updates that one entry's `last_opened` and reuses its slot rather than adding a second entry, so a repository with several worktrees appears exactly once (per `WTC-worktree-context.md` WTC-FR-18).
19. **GSS-FR-19** The app-preferences record holds `main_window_fullscreen`, the main window's OS full-screen state, defaulting to `false` when unset. It is user-global rather than a field of the per-project layout slot (GSS-FR-17), so it applies to whichever project is opened; the shell writes it whenever the main window enters or leaves full-screen and reads it when the main window mounts (`../ui/SNV-shell-navigation.md` SNV-FR-38 / SNV-FR-39). This module persists the flag and does not interpret it: nothing here consults it when serving the Project picker, which is never full-screen (`../ui/PPK-project-picker.md` PPK-FR-14).
20. **GSS-FR-20** `save_app_preferences` writes the app-preferences record whole. A caller editing one field supplies the others unchanged, so a theme change from `../ui/GLS-global-settings.md` never clears `main_window_fullscreen`, `search_query_mode`, either diff-viewer mode, `changes_commit_action`, `notifications_enabled`, `selection_follows_tab`, `graduation_rail_width_fraction`, `graduation_paths_width_fraction`, `git_files_width_fraction`, or any of the three roles' font settings; a font change from the Appearance section never resets the theme; a full-screen change from the shell never resets either; a query-mode change from the search input never disturbs any of them; a mode change from a Diff tab disturbs none of the rest; an action change from the Changes panel disturbs none of them either; a change to the notifications switch or to the selection-follows-tab switch disturbs none of them at all; and a rail-width or paths-column-width change from the Runs panel's graduation section disturbs none of them either.
21. **GSS-FR-21** The app-preferences record holds `search_query_mode ∈ { literal_insensitive, smart_case, regex }`, the interpretation the universal search bar applies to a query, defaulting to `literal_insensitive` when unset. It is user-global rather than project-scoped because it describes how the user searches rather than anything about a project; the search input reads it on mount and writes it whenever the user changes the active toggle (`../ui/SCH-search.md` SCH-FR-13). This module persists the value and does not interpret it: the modes themselves are defined by `SCC-search.md` SCC-FR-05.
22. **GSS-FR-22** The user-global store holds the **GitHub token registry**: one descriptive record per stored token, carrying its id, label, resolved account login, granted scopes, masked hint, and its added and last-verified timestamps (the shape `GTS-github-token-storage.md` GTS-FR-02 defines). No token secret is present in this store in any form — the secret of every record lives in the application secret vault under the record's id (`GTS-github-token-storage.md` GTS-FR-01) — so `synthesis.toml` remains a file that can be read, copied, or attached to a bug report without disclosing a credential. This module persists the records and interprets none of them: their meaning, their verification, and the commands that mutate them are owned by `GTS-github-token-storage.md`.
23. **GSS-FR-23** The per-project slot records the project's **GitHub token binding** — the id of the registry record that project's authenticated GitHub operations use, unset until one is chosen. It is user-global rather than project-local because a project's `.synthesis/project.toml` is committed content that would carry one author's choice to everyone who clones the repository, and it sits in the per-project slot rather than the app-preferences record because it is a fact about one project. Keyed by project (GSS-FR-18), it is one binding for the repository however many worktrees it has. This module stores whatever id it is given and never checks that the record still exists; a binding pointing at a removed record is resolved by `GTS-github-token-storage.md` GTS-FR-10.
24. **GSS-FR-24** The app-preferences record holds the diff viewer's two modes: `diff_visualization_mode ∈ { unified, side_by_side, final }`, defaulting to `unified` when unset, and `diff_rendering_mode ∈ { source, rich }`, defaulting to `source`. They are user-global rather than project-scoped or per-tab because they describe how the author reads a diff rather than anything about a project or a file; a Diff tab reads them when it mounts and writes them whenever the user activates a different toggle (`../ui/DFV-diff-viewer.md` DFV-FR-23). This module persists both values and interprets neither: what each mode renders is owned by `../ui/DFV-diff-viewer.md`, and a stored `rich` is persisted unchanged even while the open file cannot be rendered rich (DFV-FR-18).
25. **GSS-FR-25** The app-preferences record holds `changes_commit_action ∈ { commit, commit_and_push, push }`, the action the Changes panel's footer control performs, defaulting to `commit` when unset. It is user-global rather than project-scoped or per-worktree because it describes the author's committing habit rather than anything about a project; the Changes panel reads it on mount and writes it whenever the author picks a different action (`../ui/CHG-changes.md` CHG-FR-34), and a graduation's start preflight reads the same value to open its own control on it and writes none back. This module persists the value and does not interpret it: which actions are available at a given moment is decided by that panel (CHG-FR-36, CHG-FR-37), and a stored `push` is persisted unchanged even while nothing is pushable.
26. **GSS-FR-26** The per-project slot records the project's **agentic integration override** — the vendor whose integration that project uses in place of the user-global active one, unset until one is chosen. It is user-global rather than project-local because a project's `.synthesis/project.toml` is committed content that would carry one author's choice of tooling to everyone who clones the repository, and it sits in the per-project slot rather than the agentic registry because it is a fact about one project. Keyed by project (GSS-FR-18), it is one override for the repository however many worktrees it has. This module stores whatever vendor it is given and never checks that the integration is still usable; an override naming a cleared or unverified integration is resolved by `AIC-agentic-integrations.md` AIC-FR-16.
27. **GSS-FR-27** The user-global store holds the **AI API provider registry**: one descriptive record per supported provider carrying its base URL, the masked hint of its key, the timestamp of its last successful verification, its model list — each model with its optional conversation route `mode` (`AAP-ai-api-integrations.md` AAP-FR-RTMZ) — and the origin of that list, the model chosen for it, the reasoning level chosen for that model, and the turn timeout chosen for it — together with which single provider is the active API integration (the shapes `AAP-ai-api-integrations.md` AAP-FR-02 defines). No key is present in this store in any form — the key of every configured provider lives in the application secret vault under the provider's id (`AAP-ai-api-integrations.md` AAP-FR-07), exactly as a GitHub token's secret does (`GTS-github-token-storage.md` GTS-FR-01) — so `synthesis.toml` remains a file that can be read, copied, or attached to a bug report without disclosing a credential. This module persists the records and interprets none of them: verification, model probing, and the single-active rule are owned by `AAP-ai-api-integrations.md`.
28. **GSS-FR-28** The per-project slot records the project's **AI API integration override** — the provider whose integration that project uses in place of the user-global active one, unset until one is chosen. It is independent of the agentic override (GSS-FR-26): a project may override one level, both, or neither. Keyed by project (GSS-FR-18) and held here rather than in a project's committed `.synthesis/` for the same reason as every other per-project fact, it is one override for the repository however many worktrees it has. This module stores whatever provider it is given and never checks that the integration is still usable; an override naming a cleared or unverified provider is resolved by `AAP-ai-api-integrations.md` AAP-FR-16.
29. **GSS-FR-29** The app-preferences record holds one **font setting per typographic role** — one for the UI role, one for the Rich Markdown role, and one for the Source code role (`../ui/OVW-overview.md` OVW-FR-13) — each carrying a family, a size, and a line height, and each of those three independently unset until chosen. They are user-global rather than project-scoped because they describe how the author wants to read rather than anything about a project; the Appearance section reads them on mount and writes them whenever the user changes a control (`../ui/GLS-global-settings.md` GLS-FR-17, GLS-FR-20). This module persists the values and interprets none of them: it never checks that a stored family is installed on this machine and never bounds a size or a line height, so a family since uninstalled reads back exactly as stored. Resolving an absent family is owned by `../ui/GLS-global-settings.md` GLS-FR-22 and bounding the numeric values by GLS-FR-19.

30. **GSS-FR-30** The store holds the **conversational agent registry**: one record per agent the author has described, each carrying its id, nickname, title, model, reasoning choice, and instructions (`AGR-agent-registry.md` AGR-FR-01). A record holds no AI API provider id: the model is read against the provider that is active for the open project (`AAP-ai-api-integrations.md` AAP-FR-APRV). A record written by an earlier build with a `provider` field loads without error, the field is ignored, and the next write of that record omits it. The title is persisted as the trimmed string the registry holds (`AGR-agent-registry.md` AGR-FR-23), and a record that carries no title field at all reads back with a title of `""` — the same value an author who named none stores — so a store written before the field existed is read without a migration and without an error. It is user-global because a persona describes how its author wants to be argued with rather than anything about a repository, and it holds no secret at all — the key of the active provider lives in the application secret vault — so `synthesis.toml` gains no credential by gaining an agent.
31. **GSS-FR-31** The per-project slot records the project's **enrolled agents**: the ids of the registry's agents that may be addressed in that project, empty until one is enrolled. It sits here rather than in the project's `.synthesis/` because it names records that exist only on this machine, and because a project's `.synthesis/` is committed content one clone would carry to everyone; keyed by project rather than by directory (GSS-FR-18), it is one fact for the repository and survives a change of active worktree. An id naming a record the registry no longer holds is not written, because deleting an agent clears it from every slot in the same operation (`AGR-agent-registry.md` AGR-FR-11).
32. **GSS-FR-32** The app-preferences record holds `notifications_enabled`, the switch governing whether the application posts operating-system notifications at all — and only those, the in-app attention indication a tab takes standing whatever this flag says (`../ui/NTF-notifications.md` NTF-FR-29) — defaulting to `true` when unset. It is user-global rather than project-scoped because it describes how the author wants the operating system to interrupt them rather than anything about a project; the Notifications section reads it on mount and writes it whenever the switch changes (`../ui/GLS-global-settings.md` GLS-FR-25), and `../ui/NTF-notifications.md` reads it at startup (NTF-FR-12). This module persists the flag and does not interpret it: whether any given raise becomes a posted notification is decided by `../ui/NTF-notifications.md` NTF-FR-08, and the operating system's own permission is not stored here in any form — it is read from the platform each time it is needed (`NTD-notification-delivery.md` NTD-FR-02), so a store copied to another machine carries no stale claim about what that machine allows.
33. **GSS-FR-33** The app-preferences record holds `selection_follows_tab`, the switch governing whether a change of the main viewport's active tab moves the vertical panel's selection to the item that tab is a view onto, defaulting to `true` when unset. The default holds for a record that has never been written and for one written before the field existed, so a machine that has been in use reads the same value a fresh one does. It is user-global rather than project-scoped because it describes how the author navigates rather than anything about a project; the Navigation section reads it on mount and writes it whenever the switch changes (`../ui/GLS-global-settings.md` GLS-FR-28), and the shell reads it at every qualifying tab activation (`../ui/SNV-shell-navigation.md` SNV-FR-64). This module persists the flag and does not interpret it: which panel a given tab selects in, and what happens when its target cannot be resolved, are decided by `../ui/SNV-shell-navigation.md` SNV-FR-66 and SNV-FR-67.
34. **GSS-FR-34** The app-preferences record holds `graduation_rail_width_fraction`, the width of the Runs panel's **graduation history rail** as a fraction of that panel's usable content width, defaulting to `0.20` when unset. The default holds for a record that has never been written and for one written before the field existed, so a machine that has been in use reads the same value a fresh one does. It is user-global rather than a field of the per-project layout slot (GSS-FR-17), and the two are separate facts: the layout slot holds the shape of one project's shell, while this describes how wide the author wants a run history beside a run wherever they read one, so it survives a change of project exactly as the theme does. The graduation section reads it when it mounts and writes it when a drag completes or a keyboard adjustment is made (`../ui/GRH-graduation-history.md` GRH-FR-MCHQ). This module persists the value and does not interpret it: the fraction's bounds, what the fraction is measured against, and the steps a key press moves it by are owned by `../ui/GRH-graduation-history.md` GRH-FR-MCHQ, and a stored value outside those bounds is returned exactly as stored for that surface to clamp.
35. **GSS-FR-QDNV** The app-preferences record holds `graduation_paths_width_fraction`, the width of the graduation run region's **paths column** as a fraction of the width of its two columns, defaulting to `0.30` when unset or written before the field existed. It is user-global. This module persists the value exactly as stored; its bounds and its use belong to `../ui/GRU-graduation-runs.md` GRU-FR-KWRB.
36. **GSS-FR-MSPQ** The app-preferences record holds `git_files_width_fraction`, the width of the Git panel's **files column** as a fraction of the width of its large view, defaulting to `0.30` when unset or written before the field existed. It is user-global. This module persists the value exactly as stored; its bounds and its use belong to `../ui/GIT-git.md` GIT-FR-FATV.

35. **GSS-FR-35** The user-global store holds the **Docker backend configuration**: the selected mode, the Docker Engine endpoint, the Docker CLI executable path, and the verification state of GSS-FR-39. The mode defaults to `bollard` — Bollard / Docker Engine — when unset, so a machine that has configured nothing reaches Docker the way the platform itself does. It is user-global rather than project-scoped because how this machine reaches a container runtime is a fact about the machine: it is never written into a project's `.synthesis/project.toml` or into any other committed project file, whatever project is open (per `PSS-project-settings-storage.md` PSS-FR-01).
36. **GSS-FR-36** The endpoint is **platform-neutral** and holds one of four forms: `automatic`, which is the platform's own default location and the value an unset endpoint reads as; a Unix socket path; a Windows named pipe; and a TCP URL. The stored form is whatever the author selected, so the same record describes a local daemon, a daemon behind a pipe, and a remote one. The CLI executable path is required only while the mode is `docker_cli`, and the endpoint applies only while the mode is `bollard`; the store keeps both whichever mode is selected, so returning to a mode returns to the values it last carried.
37. **GSS-FR-37** `detect_docker_cli_binary` searches the current `PATH` and the platform's conventional install locations for the Docker CLI executable and returns the first match, or null when nothing matches. Detection neither persists its result nor executes what it found, exactly as CLI-kind agentic detection does not (`AIC-agentic-integrations.md` AIC-FR-03).
38. **GSS-FR-38** `verify_docker_backend(config)` verifies **the mode the configuration selects** and reports that mode's own states. In `docker_cli` mode it distinguishes a missing or invalid executable — `cli_path_empty` for an empty path, `cli_not_found` for one that does not exist, `cli_not_executable` for one that cannot be run, and `not_the_docker_cli` for a program that is not the Docker CLI — from a **Docker daemon that cannot answer**, which is `daemon_unreachable`, and from a run that exceeds the bounded timeout, which is `timed_out`. In `bollard` mode it distinguishes an **invalid endpoint** — `endpoint_empty` for an empty one and `endpoint_invalid` for one that is not a well-formed socket path, pipe name, or URL — from `daemon_unreachable` and `timed_out` on the same terms. Verification succeeds only when the daemon answered and reported its version, so a reachable executable behind a daemon that cannot answer is never returned as a success.
39. **GSS-FR-39** A successful verification is **bound to the three selected values** it was performed against — the mode, the Docker Engine endpoint, and the Docker CLI executable path — and the store records them beside the reported server version and the verification timestamp. `load_docker_backend` reads `state = "verified"` only while the stored selection still equals the bound one; a `save_docker_backend` that changes any of the three returns the record to `unverified` and requires Verify again. Nothing else invalidates it: a daemon that is restarted, stopped, or moved out of reach afterwards leaves the stored success exactly as it was, because the record describes what the author configured and proved rather than what the daemon is doing at this moment.
40. **GSS-FR-40** `resolve_docker_backend()` is the single read path for an actual Docker operation, and it **probes nothing**: it returns the stored verified backend or refuses with `docker_backend_unverified`, and it never runs the executable, opens the endpoint, or asks the daemon anything. It is not registered as a Tauri command, so no frontend call reaches it. A backend that resolves and then turns out to be unavailable is reported by the operation that used it — `PSS-project-settings-storage.md`'s build failure (PSS-FR-28) or `../tools/EAC-execute-agent-cli.md`'s `RuntimeUnavailable` (EAC-FR-17) — rather than by a second verification here.

41. **GSS-FR-ZKQT** The user-global store holds the **relay endpoint**: the URL of the one relay instance this machine reaches, with the validation state of GSS-FR-NLDC, the relay version and the capability identifiers the last success reported, and the time of that success. The URL is unset until the author gives one, and the store holds one endpoint rather than a list.
42. **GSS-FR-VMRB** The store holds no `SYNTHESIS_SERVER_TOKEN`, no relay credential, and no private key in any form. The token reaches the application, the relay, and the mobile client as runtime configuration, and `synthesis.toml` gains no secret by gaining a relay endpoint.
43. **GSS-FR-HPWE** `verify_relay_endpoint(url)` reads the unauthenticated health response of `../server/BMS-backend-microservice.md` BMS-FR-11 at that URL, within a bounded timeout, and sends no credential. It fails with the typed errors the contract surface names, and succeeds only for a health response that advertises both `remote_session` and `websocket`.
44. **GSS-FR-NLDC** The validation state is `unset` while no URL is stored, `unverified` for a stored URL that no success is bound to, and `verified` while the stored URL equals the one the last success used. A `save_relay_endpoint` that changes the URL returns the record to `unverified`, and a relay that later stops answering leaves a stored success unchanged.
45. **GSS-FR-TXAO** This module persists the endpoint and interprets it no further: it opens no WebSocket, holds no session, and reaches the relay only in `verify_relay_endpoint`. The session and frame contracts are `../server/RSN-remote-session.md`'s and `../server/WSK-websocket.md`'s.
46. **GSS-FR-CDYK** The per-project slot records the project's **document sources**: an ordered list of `{ kind, path }`, where `kind` is `file` or `folder` and `path` is the absolute path as the user selected it. The list is empty until a source is added. It holds references only and never a document's content, its extracted text, or an index.
47. **GSS-FR-ZWJW** The document sources are keyed by project (GSS-FR-18): one list serves a repository however many worktrees it has, and a change of the active worktree reads the same list. The list is user-global because a selected path may lie outside the project. This module stores the paths it is given and does not check that they exist.

## Non-functional requirements
- All user-global settings load on app start without network access.
- A first launch on a fresh machine yields a usable default user-global config (empty recent list, `theme = system`, `main_window_fullscreen = false`, `search_query_mode = literal_insensitive`, `diff_visualization_mode = unified`, `diff_rendering_mode = source`, `changes_commit_action = commit`, `notifications_enabled = true`, `selection_follows_tab = true`, `graduation_rail_width_fraction = 0.20`, `graduation_paths_width_fraction = 0.30`, `git_files_width_fraction = 0.30`, every typographic role's family, size, and line height unset, empty registries including an empty GitHub token registry, and every agentic integration and every AI API provider unconfigured with none active in either level) without user input.
- The user-global store is free of secret material, so it can be inspected, backed up, or attached to a support request without disclosing a credential. Every secret the application manages is held in one keyring entry instead (`ASV-application-secret-vault.md` ASV-FR-01), and no registry, binding, or override in this store is written into that entry (`ASV-application-secret-vault.md` ASV-FR-08).
- The app-preferences record must be readable in a single round-trip at startup so the app can apply the theme and all three roles' font settings before first paint (per `../ui/OVW-overview.md` OVW-FR-09 and OVW-FR-14) and the main window can mount already in its stored presentation (per `../ui/SNV-shell-navigation.md` SNV-FR-39).
- Missing or malformed user-global files are repaired silently.
- `load_relay_endpoint` completes without network access, so the Remote connectivity section renders offline and instantly; verification is the only operation in it that reaches anything, and it is bounded rather than open-ended.
- `load_docker_backend` completes without network access and without running any executable, so the Docker section renders offline and instantly; verification is the only operation here that reaches a daemon, and it is bounded rather than open-ended.
