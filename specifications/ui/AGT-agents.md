# Agents

**Spec code:** `AGT`

## Intent
Agents is where the author describes the AI collaborators they want to think alongside, and decides which of them a given project may hear from. An agent is a persona rather than a tool: a nickname it answers to, a title naming the role it is there to take, a conversational model it runs on, how hard that model should think, and — where the author has something to say about it — the instructions it works under. Personas are described once for the machine in the Global settings **Agents** section, because a reviewer the author has taught to argue well about specifications is worth having in every repository they open; each project then enrols the ones it wants in its own **Agents** section, because who belongs in a conversation differs from one project to the next. A control in the top chrome opens a roster of the agents the open project has enrolled, so the author can see who is available and who is currently answering without leaving what they are doing. An agent is addressed by typing its nickname where a person's would go — or the whole room at once through the reserved handle `@all`, for the question worth putting to every collaborator the project has rather than to one of them — and it answers in the same place a person would, which is why this surface configures agents and never converses with them. An agent runs on the model and the reasoning its own description carries, so the model and the reasoning held in the AI API section are never what an agent answers on (`AII-ai-integrations.md` AII-FR-54). An agent names no provider: its models are the ones the AI API provider that is active for the open project serves, and a conversation uses that provider's endpoint and credential, so switching the active provider moves every agent at once and marks the agents whose model the new provider does not serve. Out of scope: the conversation itself, which happens in the surface the agent was addressed from (`CMT-comments.md`, `NAW-new-artifact.md`) and is carried by `../core/AGC-agent-conversations.md`; the endpoints, keys, and provider verification an agent's model depends on, which are configured in the AI API section (`AII-ai-integrations.md`) and merely read from here; and the agent backends the application hands work to, which are a different kind of integration entirely and are configured in the Agentic AI section — an agent here answers and never acts.

## User stories
- As an author, I want to describe a reviewer once — the model it runs on and how it should behave — and then have it available in every project I open, rather than re-describing it per repository.
- As an author, I want a project to hear from only the agents I chose for it, so a personal project is not full of the personas I built for work.
- As an author mid-sentence, I want to summon an agent by typing its name where I would type a colleague's, rather than leaving what I am writing to find a control.
- As an author with three reviewers enrolled, I want one handle that puts a question to all of them, so asking the room costs no more typing than asking any one of them.
- As an author, I want to see at a glance which agents this project has and which of them are answering something right now.
- As an author whose provider key has expired, I want the agent that depended on it to say so plainly rather than quietly vanish from the list.

- Layout notes: the chrome control sits in the top chrome's trailing cluster (per `SNV-shell-navigation.md` SNV-FR-59) and carries the count of agents the project has enrolled, so the roster's size is legible without opening it. The roster is a chrome-anchored dropdown, aligned to the control's trailing edge, and each of its rows is two lines — the nickname above, its model and reasoning below — with an in-flight marker or an availability warning occupying the row's trailing edge. The add action is pinned below the rows, outside anything that scrolls. The Global settings section renders one row per agent with its nickname, model, and reasoning on one line, an availability warning on a second line where there is one, and its two actions trailing; the create action is pinned below the list. The editor is a modal within the Global settings window, its fields in the order nickname, title, model, reasoning, instructions, with the nickname's hint below it, the title's below that, and the instructions' below them; the reasoning row is absent entirely for a model that declares none, and the rows beneath close the gap rather than leaving one. The Project settings section renders one line per enrolled agent with a remove action trailing, the add action below the list, and one sentence naming where personas are described. The mention picker is anchored to the composer at the caret's line and is a transient surface of the surface that owns the composer rather than a window overlay; its entries are one line each — the nickname leading, the agent's title trailing, that trailing position simply blank where the agent carries no title, and an availability warning taking it where there is one — and exactly one of them carries the highlight that Tab and Enter complete. No model appears anywhere in it. The `@all` entry takes that same single line, the handle leading and the nicknames it stands for trailing where a nickname's entry carries its title, elided with a count of the remainder when they do not fit; it renders above every nickname whenever the typed fragment matches it, and an availability warning takes the nicknames' place while none of them can answer.

## UI contract boundary
- **Owned by the UI**: the chrome control, its enrolled-agent count, and the roster it opens; the roster's rows, their in-flight markers, their availability warnings, its add action, and its empty state; the Global settings Agents section, its list, its ordering, its per-row actions, and its empty states; the persona editor, its field order, its client-side validation of a nickname, its title field, its model selector, filled from the active provider, and the filtering within it, the shape its reasoning selector takes from the selected model, its instructions field, and the enablement of its confirm action; the delete confirmation and what it states; the Project settings Agents section, its list, its add picker, its remove action, and its empty state; the mention picker, what opens and closes it, the tag syntax it inserts, the client-side matching and ordering that narrow and rank it, the title each of its entries carries and the blank it leaves where an agent has none, and its keyboard handling; the `@all` handle — its entry in the picker, its rank there, and its expansion into the enrolled agents that can answer; the bold rendering of a live tag inside a message body and the plainness of every `@` that resolves to nobody; and the inline surfacing of every typed error the operations below return.
- **Delegated to backend (abstract)**: `"list agents"`, `"create agent"`, `"update agent"`, `"delete agent"`, `"list project agents"`, `"enrol project agent"`, `"remove project agent"`, every one owned by `../core/AGR-agent-registry.md`; and `"get active ai api catalog"`, owned by `../core/AAP-ai-api-integrations.md` (AAP-FR-APRV) and consumed here to populate the model and reasoning selectors from the provider that is active for the open project. The `@all` handle is expanded here from what `"list project agents"` already returned and reaches no operation of its own, so the whole of it is a read of state the composer's surface holds. The roster's in-flight markers follow `"list agent turns"` and the `"agent turn state changed"` event, both owned by `../core/AGC-agent-conversations.md`; dispatching a turn belongs to the surface the agent was addressed from (`CTA-comment-agent-turns.md` CTA-FR-EACI, CTA-FR-QUXJ and `ACT-action-control.md` ACT-FR-16) and this surface never invokes it.

## Functional requirements
1. **AGT-FR-01** An agent is described here by a nickname, a title, the model it runs on, the reasoning that model is asked for, and the instructions it works under, and it stores no provider. Every surface here presents some part of that and nothing else: the roster and both Agents sections name the nickname, the model, and the reasoning, the mention picker names the nickname and the title (AGT-FR-43), and the persona editor is where all of it is authored. No surface here presents a base URL, an API key, a masked hint, a binary path, or a verification state, because the provider that serves an agent and the credentials behind it belong to the AI API section (`AII-ai-integrations.md`). This is the only surface where the model and the reasoning an agent runs on are chosen: the model and the reasoning that section holds are the graduation loop's and are never what an agent answers on (per `AII-ai-integrations.md` AII-FR-54).
2. **AGT-FR-02** The top chrome carries an agents control (placed by `SNV-shell-navigation.md` SNV-FR-59) showing how many agents the open project has enrolled, read from `"list project agents"`. A project enrolling none carries the control with a count of none rather than no control at all.
3. **AGT-FR-03** Activating the control opens the **roster**: a dropdown listing the open project's enrolled agents, ordered by nickname. It is a floating overlay of the main window and is mutually exclusive with every other (per `SNV-shell-navigation.md` SNV-FR-56), and it dismisses on Escape, on an outside pointer-down, and on a second activation of the control.
4. **AGT-FR-04** Each roster row names the agent's nickname, its model, and its reasoning where it has one. A row carries no action of its own beyond activating it (AGT-FR-06), because the roster reports who is available rather than changing anything.
5. **AGT-FR-05** A roster row marks an agent that is currently answering something, from `"list agent turns"` when the roster opens and from the `"agent turn state changed"` event while it is open, so an agent working on a conversation in a tab the author is not looking at is visible from the chrome. An agent is answering only while a turn of its own is `running`: one whose turn ended by asking the author something is waiting on a person rather than working, and is marked no more than an idle agent is (per `../core/AGC-agent-conversations.md` AGC-FR-28). The marker clears when the agent's last running turn ends, by whichever route.
6. **AGT-FR-06** Activating a roster row opens the Global settings window on its Agents section with that agent's editor open, focusing that window where it is already open and closing the Project settings window first where that one is open (per `SWN-settings-windows.md` SWN-FR-06, SWN-FR-07), so the roster is how an agent is reached to be looked at or changed. The roster performs no edit itself.
7. **AGT-FR-07** The roster carries an **Add an agent** action that opens the Global settings window on its Agents section with a fresh editor, on the same terms (per `SWN-settings-windows.md` SWN-FR-13), so describing a new persona is one action from the chrome.
8. **AGT-FR-08** A project enrolling no agent renders a first-class roster empty state naming the Project settings Agents section as where agents are enrolled, and carrying the add action of AGT-FR-07 for the case where none has been described yet. It is not an error.
9. **AGT-FR-09** The Global settings Agents section (placed by `GLS-global-settings.md` GLS-FR-24) lists every agent described on this machine, read from `"list agents"` when the section is opened, ordered by nickname without regard to case. It is where a persona is created, edited, and deleted, and it lists the whole registry rather than any project's enrolment.
10. **AGT-FR-10** Each row in that section names the agent's nickname, its model, and its reasoning where it has one, and carries an edit action and a delete action. A row names no provider. An agent whose availability is not `ready` additionally states the reason on its own line — no provider is configured, no provider is active for the project, or the active provider does not offer the chosen model — and names the AI API section as where a provider is corrected, or the editor as where an available model is chosen. The availability of each row is computed from the active provider's model list (AGT-FR-PRVQ). The row is neither hidden nor cleared for it (per `../core/AGR-agent-registry.md` AGR-FR-17).
11. **AGT-FR-11** The section carries a create action opening the **persona editor** with empty fields, and the edit action opens the same editor seeded with that agent's stored values. The editor is a modal over the tab and is the only place a persona is authored.
12. **AGT-FR-12** The editor presents exactly five controls in this order: the nickname field, the title field (AGT-FR-42), the model selector, the reasoning selector where one is rendered (AGT-FR-16), and the instructions field. It has no provider selector. Moving between the editor's fields neither discards nor applies anything.
13. **AGT-FR-13** The nickname field is validated client-side as non-empty, free of whitespace and of `@`, and not the reserved handle `all` in any case (AGT-FR-41), and states that the nickname is what is typed to address the agent. The confirm action is disabled while it is invalid, so no call is made with a nickname the backend would refuse — against the reserved one the field states that `all` addresses every agent the project has enrolled, so an author reads why the name is unavailable rather than only that it is; a nickname already taken is knowable only to the backend and renders as its typed error inline against the field (per `../core/AGR-agent-registry.md` AGR-FR-05).
14. **AGT-FR-14** The editor and the section read the provider that is active for the open project from `"get active ai api catalog"`. When none resolves, the section renders a first-class empty state naming Global settings → AI API as where one is configured, and the create action is disabled, because an agent that could not be spoken to is not worth describing. The confirm action of an existing agent's editor is likewise disabled while no provider resolves.
15. **AGT-FR-15** The model selector is the filterable selector of `AII-ai-integrations.md` (AII-FR-36 through AII-FR-40) — a filter box that takes focus on open, matching on label or model identifier without regard to case, a count of how many of the record's models are showing, a first-class row when nothing matches, and full keyboard operation. It offers the models the active provider's catalog carries and nothing else, so choosing a model is the same act here as in Global settings. Where the active provider is Custom, the selector states that the list came from the Custom gateway.
16. **AGT-FR-16** The reasoning selector renders only while a model is selected whose record declares reasoning, and it offers exactly what that model declares, on the terms `AII-ai-integrations.md` sets: a model declaring its own levels offers those levels and no others (AII-FR-42), one declaring reasoning but no levels offers off and on (AII-FR-43), one whose reasoning is mandatory offers no off entry and says the model always reasons, and every shape is preceded by an entry meaning the model's own default (AII-FR-44). A model declaring no reasoning renders no reasoning row at all.
17. **AGT-FR-17** Changing the selected model re-renders the reasoning selector against what the new model declares and returns it to the model-default entry when the new model cannot honour the previous choice, so the editor never holds a combination the backend would reject. An editor opened for an agent whose stored model the active provider does not offer shows no model selected and states that the stored model is unavailable, and its confirm action stays disabled until the author selects an available model. The stored model is not rewritten until the author confirms.
18. **AGT-FR-18** The instructions field is a multi-line plain-text field, stated as optional, that neither validates nor formats what is typed into it. An empty field is an ordinary state and does not disable the confirm action.
19. **AGT-FR-19** Confirming the editor invokes `"create agent"` for a new persona or `"update agent"` for an existing one, with every field as it stands. On success the editor closes and the section's list re-renders from what the operation returned; on a typed failure the editor stays open with its fields intact and the error renders inline against the field it concerns, so one value is corrected rather than all of them re-entered. Cancelling invokes nothing.
20. **AGT-FR-20** The delete action opens a confirmation naming the agent and stating that it is removed from every project that enrolled it; confirming invokes `"delete agent"` and removes the row. Dismissing the confirmation invokes nothing.
21. **AGT-FR-21** Every action in the Global settings Agents section applies immediately through its own operation rather than through a section save, so the section holds no dirty state and contributes nothing to the Global settings window's save-before-close sweep (per `GLS-global-settings.md` GLS-FR-13 and GLS-FR-24).
22. **AGT-FR-22** The Project settings Agents section (placed by `SET-project-settings.md` SET-FR-15) lists the open project's enrolled agents, read from `"list project agents"` when the section mounts, ordered by nickname. Each line names the agent, its model, and its reasoning, states the reason where its availability is not `ready`, and carries a remove action; none carries an edit action, because a persona is described in Global settings and this section decides only who is in this project.
23. **AGT-FR-23** The section carries an add action opening a picker of the agents described on this machine that this project has not yet enrolled; confirming one invokes `"enrol project agent"` at once and the remove action invokes `"remove project agent"` at once, so both sit outside the Project settings window's dirty state (per `SET-project-settings.md` SET-FR-08). Removing an agent from the project leaves its description untouched, and the section says so. A project that has enrolled every described agent renders the add action stating there is nothing left to add, and a machine with no agent described at all renders an empty state naming the Global settings Agents section as where one is described.
24. **AGT-FR-24** An agent is addressed by a **tag**: an `@` immediately followed by an agent's nickname or by the reserved handle `all` (AGT-FR-35), written inline in the message where a person's name would go. Matching a tag is case-insensitive, and a tag reaches only agents the open project has enrolled, so the same text in a project that has not enrolled that agent addresses nobody. A tag therefore resolves to one agent, to several, or to none, and every surface that dispatches on tags acts on the set a tag resolves to rather than on a single name.
25. **AGT-FR-25** A composer that offers agents opens the **mention picker** when the author types an `@` that begins a word — one that is the first character in the composer, or that follows whitespace, an opening bracket, a quote, or a dash. An `@` typed inside a word opens nothing, so an email address or a code sample is written straight through. The picker is anchored to the composer at the caret's line and lists the project's enrolled agents, and the `@all` handle, narrowed by the characters typed after the sigil (AGT-FR-33). Choosing an entry replaces the sigil and everything typed after it with that entry's full tag, leaves the caret directly after it, and closes the picker.
26. **AGT-FR-26** An agent whose availability is not `ready` is offered in the picker in its ranked position with the reason stated, and is not selectable: the highlight passes over it and no key completes it, so an author looking for an agent that is present but cannot answer learns why rather than finding it silently absent from a list.
27. **AGT-FR-27** The picker is operable from the keyboard alone. The arrow keys move a highlight through the selectable entries the filter is showing, and the highlight returns to the top match (AGT-FR-33) whenever the fragment changes. Enter and Tab both insert the highlighted entry's tag (AGT-FR-25) and close the picker, so completing a nickname is one key from where the author's hands already are and neither key ever disagrees with the entry the list shows highlighted. Escape closes the picker leaving what was typed exactly as it was. Tab pressed while nothing is highlighted — because the fragment matches neither a nickname nor the handle, or because everything it matches is an agent that cannot answer or a handle that resolves to none (AGT-FR-39) — does whatever it does in that composer otherwise, since a key with nothing to complete must not strand the author's focus.
28. **AGT-FR-28** A tag typed by hand that resolves to no enrolled agent is ordinary text: it is not emphasised (AGT-FR-29), it addresses nobody, and it produces no error, because an author writing an email address or a code sample must be able to type an `@` without being interrupted.
29. **AGT-FR-29** A tag that resolves to at least one enrolled agent is rendered **bold** wherever a message body is rendered — in a thread's card, in a discussion's, and in the Comments panel alike — so a reader can tell at a glance who a message was addressed to. The emphasis marks a live tag and nothing else: an `@` resolving to nobody keeps the weight of the prose around it (AGT-FR-28), and so does every other `@` a body may carry — an email address, a code sample, a handle belonging to some other system — because bolding text that addressed no one promises a reader a participant who was never in the conversation. A live `@all` is bold on the same terms as a nickname and stays the text `@all`, naming nobody in particular (AGT-FR-40).
30. **AGT-FR-30** The mention picker is a transient surface of the surface that owns the composer rather than a floating overlay of the main window: opening it closes none of the window's mutually-exclusive overlays and none of them closes it (per `SNV-shell-navigation.md` SNV-FR-56). It is a transient of the composer that owns it rather than a peer of that surface's other transients, so opening it dismisses none of them and closes no composer (per `CMT-comments.md` CMT-FR-32 and `ACT-action-control.md` ACT-FR-12). Being a transient of the composer is also what gives it Escape first: in a surface Escape would otherwise dismiss — a composer in a conversation tab or in a discussion panel — an open picker takes the keystroke and closes, and the surface holding it is left exactly as it was, because completing a nickname and closing a composer are not the same gesture.
31. **AGT-FR-31** Every surface here renders and is navigable with nothing configured: no agent described, no agent enrolled, and no provider verified each render their own first-class empty state naming what is needed and where, and none of them is an error.
32. **AGT-FR-32** No surface here dispatches a turn, cancels one, or renders a reply. The roster reports that an agent is answering (AGT-FR-05) and nothing more; a conversation is begun where the agent was addressed — a comment composer read in the comment margin (`CMT-comments.md`), or the tab action control's Discuss composer (per `ACT-action-control.md` ACT-FR-16), whose discussion is read in the surface that `revealDiscussion` selects (per `CVP-conversation-presentation.md`) rather than in the margin itself.
33. **AGT-FR-33** The picker offers exactly the enrolled agents whose nickname **begins with** the characters typed after the sigil, matched without regard to case, ordered by nickname without regard to case; a fragment of no characters offers every enrolled agent. The `@all` handle is offered on that same prefix test and leads them all (AGT-FR-39). The **top match** is the first selectable entry of the list as it renders, and it is what the highlight rests on, so the entry Tab completes is always the one at the head of what the author can see. A fragment matching neither a nickname nor the handle renders a first-class row saying so rather than an empty box.
34. **AGT-FR-34** The picker follows the text under the caret rather than the single keystroke that opened it: it shows while the caret sits at the end of a **candidate tag** — a word-initial `@` (AGT-FR-25) followed only by characters a nickname may carry — and closes as soon as that stops holding. Typing whitespace closes it, because a nickname carries none (per `../core/AGR-agent-registry.md` AGR-FR-04) and what is being typed is therefore no longer a tag; moving the caret out of the candidate tag closes it; and Escape closes it and keeps it closed until the caret leaves that candidate tag. Deleting characters back into a candidate tag shows the picker again against the shorter fragment, so a mistyped nickname is corrected without retyping the sigil.
35. **AGT-FR-35** `@all` is a **reserved handle** rather than an agent: a tag reading `all`, matched without regard to case like any other (AGT-FR-24), addresses every agent the open project has enrolled that can answer. It exists because a question about a specification is often worth putting to the whole room rather than to one reviewer, and an author who must name three collaborators one after another to ask it asks it of one of them instead.
36. **AGT-FR-36** `@all` resolves to exactly the enrolled agents whose availability is `ready`, read from `"list project agents"` (per `../core/AGR-agent-registry.md` AGR-FR-13). An agent that cannot answer is left out of the resolution on the same terms it cannot be completed in the picker (AGT-FR-26), because a handle that dispatched to an expired key would render the refusal as that agent's own failure to reply.
37. **AGT-FR-37** The handle is resolved afresh wherever it is read rather than expanded once when it is typed, so it always means the project's roster as it stands: an agent enrolled after the tag was written is addressed by it, one since removed from the project or gone unavailable is not, and the same body says different things about two different rosters. Nothing records what the handle meant when it was posted, because `all` names a membership rather than a list of names.
38. **AGT-FR-38** In a project where no enrolled agent can answer — none enrolled at all, or none of them `ready` — `@all` resolves to nobody and a body carrying it is an ordinary message in every respect: it addresses no one, dispatches nothing, renders unemphasised (AGT-FR-29), and raises no error, exactly as a tag matching no nickname does (AGT-FR-28). Enrolling an agent is what makes that same text live, nothing about the message having to change.
39. **AGT-FR-39** The picker offers `@all` as its **first** entry whenever the characters typed after the sigil are a prefix of `all`, ahead of every nickname however the nicknames sort, so it is the top match Tab completes (AGT-FR-33). Its entry names the agents it stands for where a nickname's entry names its title (AGT-FR-43), bounded to the one line every entry occupies and reporting how many more it holds when they do not fit, so an author reads whom they are about to address before addressing them. It is selectable while it resolves to at least one agent; while it resolves to none (AGT-FR-38) it is offered in that same position with the reason stated and completed by no key, on the terms AGT-FR-26 sets for an agent that is present but cannot answer — an author reaching for the handle learns that the project has nobody to hear it rather than finding it silently absent.
40. **AGT-FR-40** Completing `@all` inserts the handle itself and nothing else: the composer reads `@all` rather than the nicknames it stands for, and the posted body carries that one tag. The expansion is therefore never frozen into the message, which is what lets the roster change under it (AGT-FR-37), and a reader sees a question asked of everyone rather than a list of names they have to count.
41. **AGT-FR-41** `all` is reserved across the whole registry: no agent carries it as a nickname, in any case, so the handle means one thing in every project and no author describes a persona they would then be unable to summon. The nickname field refuses it client-side (AGT-FR-13), and the registry refuses it as a typed `nickname_reserved` (per `../core/AGR-agent-registry.md` AGR-FR-04) for any route that reaches the backend without passing that field.
42. **AGT-FR-42** The editor's **Title** field is a single-line plain-text field, labelled and stated as optional, holding the role the agent takes in a conversation — `UI/UX designer`, `Developer`. It validates nothing and formats nothing, an empty field is an ordinary state that leaves the confirm action enabled, and it is seeded from the agent's stored title when an existing persona is opened (AGT-FR-11) and carried on the confirm of AGT-FR-19 like every other field. What the author typed is sent as typed; the trimming that decides what is stored is the registry's (per `../core/AGR-agent-registry.md` AGR-FR-23), so an agent saved from a field holding surrounding whitespace reopens showing the trimmed value with its internal whitespace and casing intact.
43. **AGT-FR-43** A mention-picker entry for an agent names that agent's **title**, read from `"list project agents"` with the rest of the roster. An agent whose title is empty leaves that position **blank**: no placeholder, no `Not defined`, and not the model in its stead, because the position says what role this collaborator takes and filling it with something else would answer a question the author did not ask. It is the same position an availability warning claims where there is one (AGT-FR-26), so an entry states either the agent's role or why it cannot answer, never both and never a model.

44. **AGT-FR-PRVQ** The Global settings Agents section computes each agent's availability from the active provider's catalog, read from `"get active ai api catalog"` when the section opens and again whenever the active provider, a verification, or a clear changes. An agent is `ready` when that catalog contains its stored model and is `model_unavailable` otherwise, and when no catalog resolves the agent is `provider_unconfigured` where nothing is configured and `provider_unverified` otherwise (per `../core/AGR-agent-registry.md` AGR-FR-16). The section, the editor, and the roster therefore agree on which models exist, and an agent is never rewritten because the provider changed.
45. **AGT-FR-MDQW** An agent whose stored model is not in the active provider's model list stays in the Global settings list and in the roster and is shown as unavailable with the reason of AGT-FR-10. It cannot start a conversation: its tag is not completable (AGT-FR-26) and a dispatch for it is refused (per `../core/AGC-agent-conversations.md` AGC-FR-14). Opening its editor and selecting a model that the active provider offers makes it available again.
46. **AGT-FR-RFSH** Changing the active AI API provider refreshes the model and reasoning data that the Agents editors offer, without a restart. When the Custom provider is active, the reasoning selector is absent for every model (AGT-FR-16), because Custom model discovery declares no reasoning.

## Non-functional requirements
- Every surface here renders from stored state without network access: the roster, both sections, and every selector read registries and make no request to a provider, so an agent list is instant and works offline.
- The mention picker filters the agents already loaded and issues no operation and no request, so it stays responsive to every keystroke while the author is mid-sentence.
- Resolving `@all` is a read of the enrolled agents the surface already holds, so a message carrying it costs no operation and no request of its own however many agents it turns out to address, and re-resolving it whenever a body is rendered (AGT-FR-37) costs nothing either.
- Bolding a tag is decided from the enrolled agents already loaded, so a body renders without waiting on anything and a long comment full of `@` characters costs one pass over what is already in hand.
- Typing `@` never costs the author their sentence: the picker takes no focus away from the composer, the only keys it takes while showing are the arrow keys, Enter, Tab, and Escape, every other key reaches the text, and dismissing it leaves what was typed untouched.
- The picker re-filters and re-ranks within a keystroke of the fragment changing, so an author completing a nickname with Tab is never racing a list that has not caught up with what they typed.
- The only credential-derived text any surface here could render is none: nothing about the active provider's key reaches this surface, including its masked hint.
- The roster opens and closes without re-reading the registry more than once per opening, so an author checking who is available does not pay for it repeatedly.
- Every control in every surface here is reachable and operable from the keyboard alone, the mention picker included, so summoning an agent never requires a pointer.
- An agent whose provider has degraded stays visible everywhere it was visible before, with the reason stated, so nothing an author configured disappears without explanation.
