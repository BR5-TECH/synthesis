# Agents

**Spec code:** `AGT`

## Intent
Agents is where the author describes the AI collaborators they want to think alongside. An agent is a persona rather than a tool: a nickname it answers to, a title naming the role it takes, a conversational model it runs on, how hard that model should think, and — where the author has something to say about it — the instructions it works under. A persona has one of two scopes. A **Project agent** is stored in the project, is committed with it, and is shared by every contributor, so a team argues with the same reviewer under the same instructions; the author describes it in the **Project Agents** section of the Project group of the Settings window. A **Personal agent** is stored on the author's machine and follows the author into every project, because a reviewer the author has taught to argue well about specifications is worth having in every repository they open; the author describes it in the **Personal Agents** section of the Global group. Both sections use the same persona editor. A control in the top chrome opens a roster of the agents of the open project — its Project agents and the author's Personal agents together — so the author can see who is available and who is currently answering without leaving what they are doing. An agent is addressed by typing its nickname where a person's would go — or the whole room at once through the reserved handle `@all`, for the question worth putting to every collaborator the project has rather than to one of them — and it answers in the same place a person would, which is why this surface configures agents and never converses with them. When a Project agent and a Personal agent carry the same nickname, the Project agent wins in that project and the Personal agent is shown as shadowed. An agent runs on the model and the reasoning its own description carries, so the model and the reasoning held in the AI API section are never what an agent answers on (`AII-ai-integrations.md` AII-FR-54). The one exception is the Custom provider's reasoning effort, which an agent with no reasoning of its own uses as its default. An agent names no provider: its models are the ones the AI API provider that is active for the open project serves, and a conversation uses that provider's endpoint and credential, so switching the active provider moves every agent at once and marks the agents whose model the new provider does not serve. Out of scope: the conversation itself, which happens in the surface the agent was addressed from (`CMT-comments.md`, `NAW-new-artifact.md`) and is carried by `../core/AGC-agent-conversations.md`; the endpoints, keys, and provider verification an agent's model depends on, which are configured in the AI API section (`AII-ai-integrations.md`) and merely read from here; and the agent backends the application hands work to, which are a different kind of integration entirely and are configured in the Agentic AI section — an agent here answers and never acts.

## User stories
- As a contributor, I want the agents of a project to be committed with it, so that everyone on the team argues with the same personas under the same instructions.
- As an author, I want to describe a reviewer once on my machine and have it in every project I open, without any step per project.
- As an author, I want a project to define its own agent with the nickname of one of mine, and I want the project's agent to win in that project, so that the team's persona is the one that answers.
- As an author mid-sentence, I want to summon an agent by typing its name where I would type a colleague's, rather than leaving what I am writing to find a control.
- As an author with three reviewers in a project, I want one handle that puts a question to all of them, so asking the room costs no more typing than asking any one of them.
- As an author, I want to see at a glance which agents this project has, which of them are mine, and which of them are answering something right now.
- As an author whose provider key has expired, I want the agent that depended on it to say so plainly rather than quietly vanish from the list.

- Layout notes: the chrome control sits in the top chrome's trailing cluster (per `SNV-shell-navigation.md` SNV-FR-59) and carries the count of the agents on the open project's roster — Project agents and Personal agents together — so the roster's size is legible without opening it. The roster is a chrome-anchored dropdown, aligned to the control's trailing edge, and each of its rows is two lines — the nickname above, its model and reasoning below — with the scope (Project or Personal) and an in-flight marker or an availability warning occupying the row's trailing edge. The add action is pinned below the rows, outside anything that scrolls. The Personal Agents section and the Project Agents section each render one row per agent with its nickname, model, and reasoning on one line, an availability warning on a second line where there is one, and its two actions trailing; the create action is pinned below the list. The editor is a modal within the Settings window, its fields in the order nickname, title, model, reasoning, instructions, with the nickname's hint below it, the title's below that, and the instructions' below them; the reasoning row is absent entirely for a model that declares none, and the rows beneath close the gap rather than leaving one. The Project Agents section opens with one sentence saying that its agents are saved in the project and are shared when committed. The mention picker is anchored to the composer at the caret's line and is a transient surface of the surface that owns the composer rather than a window overlay; its entries are one line each — the nickname leading, the agent's title trailing, that trailing position simply blank where the agent carries no title, and an availability warning taking it where there is one — and exactly one of them carries the highlight that Tab and Enter complete. No model appears anywhere in it. The `@all` entry takes that same single line, the handle leading and the nicknames it stands for trailing where a nickname's entry carries its title, elided with a count of the remainder when they do not fit; it renders above every nickname whenever the typed fragment matches it, and an availability warning takes the nicknames' place while none of them can answer.

## UI contract boundary
- **Owned by the UI**: the chrome control, its agent count, and the roster it opens; the roster's rows, their scope markers, their in-flight markers, their availability warnings, its add action, and its empty state; the Personal Agents section and the Project Agents section, their lists, their ordering, their per-row actions, their shadowed warnings, and their empty states; the persona editor, its field order, its client-side validation of a nickname, its title field, its model selector, filled from the active provider, and the filtering within it, the shape its reasoning selector takes from the selected model, its instructions field, and the enablement of its confirm action; the delete confirmation and what it states; the mention picker, what opens and closes it, the tag syntax it inserts, the client-side matching and ordering that narrow and rank it, the title each of its entries carries and the blank it leaves where an agent has none, and its keyboard handling; the `@all` handle — its entry in the picker, its rank there, and its expansion into the roster agents that can answer; the bold rendering of a live tag inside a message body and the plainness of every `@` that resolves to nobody; and the inline surfacing of every typed error the operations below return.
- **Delegated to backend (abstract)**: `"list personal agents"`, `"list project agents"`, `"create agent"`, `"update agent"`, `"delete agent"`, and the event `"agents changed"`, every one owned by `../core/AGR-agent-registry.md`; and `"get active ai api catalog"`, owned by `../core/AAP-ai-api-integrations.md` (AAP-FR-APRV) and consumed here to populate the model and reasoning selectors from the provider that is active for the open project; and `"list voice ai voices"`, owned by `../core/VOP-voice-ai-providers.md`, consumed here to populate the voice selector. The `@all` handle is expanded here from what `"list project agents"` already returned and reaches no operation of its own, so the whole of it is a read of state the composer's surface holds. The roster's in-flight markers follow `"list agent turns"` and the `"agent turn state changed"` event, both owned by `../core/AGC-agent-conversations.md`; dispatching a turn belongs to the surface the agent was addressed from (`CTA-comment-agent-turns.md` CTA-FR-EACI, CTA-FR-QUXJ and `ACT-action-control.md` ACT-FR-16) and this surface never invokes it.

## Functional requirements
1. **AGT-FR-01** An agent is described here by a nickname, a title, the model it runs on, the reasoning that model is asked for, the instructions it works under, and an optional voice, and it stores no provider. Every surface here presents some part of that and nothing else: the roster and both Agents sections name the nickname, the model, and the reasoning, the mention picker names the nickname and the title (AGT-FR-43), and the persona editor is where all of it is authored. No surface here presents a base URL, an API key, a masked hint, a binary path, or a verification state, because the provider that serves an agent and the credentials behind it belong to the AI API section (`AII-ai-integrations.md`). This is the only surface where the model and the reasoning an agent runs on are chosen: the model and the reasoning that section holds are the graduation loop's, except the Custom reasoning default of AGT-FR-SOIO (per `AII-ai-integrations.md` AII-FR-54).
2. **AGT-FR-02** The top chrome carries an agents control (placed by `SNV-shell-navigation.md` SNV-FR-59) showing how many agents are on the open project's roster — its Project agents and its Personal agents together — read from `"list project agents"`. A project with no agent carries the control with a count of none rather than no control at all.
3. **AGT-FR-03** Activating the control opens the **roster**: a dropdown listing the Project agents and the Personal agents of the open project together, ordered by nickname without regard to case. It is a floating overlay of the main window and is mutually exclusive with every other (per `SNV-shell-navigation.md` SNV-FR-56). It dismisses on Escape, on an outside pointer-down, and on a second activation of the control.
4. **AGT-FR-04** Each roster row names the agent's nickname, its scope (**Project** or **Personal**), its model, and its reasoning where it has one. A Personal agent that a Project agent shadows is shown as shadowed and unavailable (AGT-FR-RWHL). A row carries no action beyond activating it (AGT-FR-06), because the roster reports who is available rather than changing anything.
5. **AGT-FR-05** A roster row marks an agent that is currently answering something, from `"list agent turns"` when the roster opens and from the `"agent turn state changed"` event while it is open, so an agent working on a conversation in a tab the author is not looking at is visible from the chrome. An agent is answering only while a turn of its own is `running`: one whose turn ended by asking the author something is waiting on a person rather than working, and is marked no more than an idle agent is (per `../core/AGC-agent-conversations.md` AGC-FR-28). The marker clears when the agent's last running turn ends, by whichever route.
6. **AGT-FR-06** Activating a roster row opens the Settings window on the **Project Agents** section of the Project group for a Project agent, or on the **Personal Agents** section of the Global group for a Personal agent, with that agent's editor open. An open window is focused (per `SWN-settings-windows.md` SWN-FR-06, SWN-FR-HZWD). The roster performs no edit itself.
7. **AGT-FR-07** The roster carries an **Add an agent** action. It opens the Settings window on the Project Agents section of the Project group with a fresh editor (per `SWN-settings-windows.md` SWN-FR-13). The roster exists only while a project is open, so the action needs no route for the case of no project.
8. **AGT-FR-08** A project with no agent on its roster renders a first-class roster empty state naming the Project Agents section of Project settings as where an agent of the project is described, and the Personal Agents section of Global settings as where an agent of the author is described. It carries the add action of AGT-FR-07. It is not an error.
9. **AGT-FR-09** The **Personal Agents** section of the Global group (placed by `GLS-global-settings.md` GLS-FR-24) lists every Personal agent, read from `"list personal agents"` when the section opens, ordered by nickname without regard to case. It is where a Personal agent is created, edited, and deleted. It lists no Project agent, and it is available when no project is open.
10. **AGT-FR-10** Each row in the Personal Agents section and in the Project Agents section names the agent's nickname, its model, and its reasoning where it has one, and carries an edit action and a delete action. A row names no provider. An agent whose availability is not `ready` additionally states the reason on its own line — no provider is configured, no provider is active for the project, or the active provider does not offer the chosen model — and names the AI API section as where a provider is corrected, or the editor as where an available model is chosen. The availability of each row is computed from the active provider's model list (AGT-FR-PRVQ). The row is neither hidden nor cleared for it (per `../core/AGR-agent-registry.md` AGR-FR-17).
11. **AGT-FR-11** Each of the two sections carries a create action opening the **persona editor** with empty fields, and an edit action opening the same editor seeded with that agent's stored values. The editor is a modal over the section and is the only place a persona is authored. It has the same fields and behaviour in both sections, and it writes the scope of the section it was opened from.
12. **AGT-FR-12** The editor presents exactly six controls in this order: the nickname field, the title field (AGT-FR-42), the model selector, the reasoning selector where one is rendered (AGT-FR-16), the instructions field, and the voice selector (AGT-FR-DIVM). It has no provider selector. Moving between the editor's fields neither discards nor applies anything.
12. **AGT-FR-DIVM** The voice selector is optional, for Personal and Project agents. It offers the result of "list voice ai voices", and it is a text field when that result is null. An empty value means the provider's default voice. With no active Voice AI provider, it is disabled and keeps its value.
13. **AGT-FR-13** The nickname field is validated client-side as non-empty, free of whitespace and of `@`, and not the reserved handle `all` in any case (AGT-FR-41), and states that the nickname is what is typed to address the agent. The confirm action is disabled while it is invalid, so no call is made with a nickname the backend would refuse — against the reserved one the field states that `all` addresses every agent on the project's roster, so an author reads why the name is unavailable rather than only that it is; a nickname already taken is knowable only to the backend and renders as its typed error inline against the field (per `../core/AGR-agent-registry.md` AGR-FR-05).
14. **AGT-FR-14** The editor and each section read the provider that is active for the open project from `"get active ai api catalog"`. When none resolves, the section renders a first-class empty state naming Global settings → AI API as where one is configured, and the create action is disabled, because an agent that could not be spoken to is not worth describing. The confirm action of an existing agent's editor is likewise disabled while no provider resolves.
15. **AGT-FR-15** The model selector is the filterable selector of `AII-ai-integrations.md` (AII-FR-36 through AII-FR-40) — a filter box that takes focus on open, matching on label or model identifier without regard to case, a count of how many of the record's models are showing, a first-class row when nothing matches, and full keyboard operation. It offers the models the active provider's catalog carries and nothing else, so choosing a model is the same act here as in Global settings. Where the active provider is Custom, the selector states that the list came from the Custom gateway.
16. **AGT-FR-16** The reasoning selector renders only while a model is selected whose record declares reasoning, which every Custom model does (AGT-FR-SOIO), and it offers exactly what that model declares, on the terms `AII-ai-integrations.md` sets: a model declaring its own levels offers those levels and no others (AII-FR-42), one declaring reasoning but no levels offers off and on (AII-FR-43), one whose reasoning is mandatory offers no off entry and says the model always reasons, and every shape is preceded by an entry meaning the model's own default (AII-FR-44). A model declaring no reasoning renders no reasoning row at all.
17. **AGT-FR-17** Changing the selected model re-renders the reasoning selector against what the new model declares and returns it to the model-default entry when the new model cannot honour the previous choice, so the editor never holds a combination the backend would reject. An editor opened for an agent whose stored model the active provider does not offer shows no model selected and states that the stored model is unavailable, and its confirm action stays disabled until the author selects an available model. The stored model is not rewritten until the author confirms.
18. **AGT-FR-18** The instructions field is a multi-line plain-text field, stated as optional, that neither validates nor formats what is typed into it. An empty field is an ordinary state and does not disable the confirm action.
19. **AGT-FR-19** Confirming the editor invokes `"create agent"` for a new persona or `"update agent"` for an existing one, with the scope of the section and every field as it stands. On success the editor closes and the list re-renders from a fresh read. On a typed failure the editor stays open with its fields intact and the error renders inline against the field it concerns. Cancelling invokes nothing.
20. **AGT-FR-20** The delete action opens a confirmation naming the agent. In the Personal Agents section it states that the agent is removed from every project. In the Project Agents section it states that the agent is removed from the project and, once committed, from every contributor. Confirming invokes `"delete agent"` with the scope of the section. Dismissing it invokes nothing.
21. **AGT-FR-21** Every action in the Personal Agents section and in the Project Agents section applies immediately through its own operation rather than through a section save, so neither section holds dirty state and contributes anything to the Settings window's save-before-close sweep (per `GLS-global-settings.md` GLS-FR-13 and GLS-FR-24, and `SET-project-settings.md` SET-FR-08 and SET-FR-15).
22. **AGT-FR-22** The **Project Agents** section of the Project group (placed by `SET-project-settings.md` SET-FR-15) lists the Project agents of the open project, read from `"list project agents"` when the section mounts, ordered by nickname. Each line names the agent, its model, and its reasoning, states the reason where its availability is not `ready`, and carries an edit action and a delete action.
23. **AGT-FR-23** The Project Agents section states that its agents are saved in the project's `.synthesis/` folder and are shared with the other contributors when committed. It carries a create action. A project with no Project agent renders a first-class empty state that names the create action. The empty state is not an error.
24. **AGT-FR-24** An agent is addressed by a **tag**: an `@` immediately followed by an agent's nickname or by the reserved handle `all` (AGT-FR-35), written inline in the message where a person's name would go. Matching a tag is case-insensitive, and a tag reaches only agents on the open project's roster, so the same text in a project that has no such agent addresses nobody. A tag therefore resolves to one agent, to several, or to none, and every surface that dispatches on tags acts on the set a tag resolves to rather than on a single name.
25. **AGT-FR-25** A composer that offers agents opens the **mention picker** when the author types an `@` that begins a word — one that is the first character in the composer, or that follows whitespace, an opening bracket, a quote, or a dash. An `@` typed inside a word opens nothing, so an email address or a code sample is written straight through. The picker is anchored to the composer at the caret's line and lists the agents of the project's roster that are not shadowed, and the `@all` handle, narrowed by the characters typed after the sigil (AGT-FR-33). Choosing an entry replaces the sigil and everything typed after it with that entry's full tag, leaves the caret directly after it, and closes the picker.
26. **AGT-FR-26** An agent whose availability is not `ready` is offered in the picker in its ranked position with the reason stated, and is not selectable: the highlight passes over it and no key completes it, so an author looking for an agent that is present but cannot answer learns why rather than finding it silently absent from a list.
27. **AGT-FR-27** The picker is operable from the keyboard alone. The arrow keys move a highlight through the selectable entries the filter is showing, and the highlight returns to the top match (AGT-FR-33) whenever the fragment changes. Enter and Tab both insert the highlighted entry's tag (AGT-FR-25) and close the picker, so completing a nickname is one key from where the author's hands already are and neither key ever disagrees with the entry the list shows highlighted. Escape closes the picker leaving what was typed exactly as it was. Tab pressed while nothing is highlighted — because the fragment matches neither a nickname nor the handle, or because everything it matches is an agent that cannot answer or a handle that resolves to none (AGT-FR-39) — does whatever it does in that composer otherwise, since a key with nothing to complete must not strand the author's focus.
28. **AGT-FR-28** A tag typed by hand that resolves to no roster agent is ordinary text: it is not emphasised (AGT-FR-29), it addresses nobody, and it produces no error, because an author writing an email address or a code sample must be able to type an `@` without being interrupted.
29. **AGT-FR-29** A tag that resolves to at least one roster agent is rendered **bold** wherever a message body is rendered — in a thread's card, in a discussion's, and in the Comments panel alike — so a reader can tell at a glance who a message was addressed to. The emphasis marks a live tag and nothing else: an `@` resolving to nobody keeps the weight of the prose around it (AGT-FR-28), and so does every other `@` a body may carry — an email address, a code sample, a handle belonging to some other system — because bolding text that addressed no one promises a reader a participant who was never in the conversation. A live `@all` is bold on the same terms as a nickname and stays the text `@all`, naming nobody in particular (AGT-FR-40).
30. **AGT-FR-30** The mention picker is a transient surface of the surface that owns the composer rather than a floating overlay of the main window: opening it closes none of the window's mutually-exclusive overlays and none of them closes it (per `SNV-shell-navigation.md` SNV-FR-56). It is a transient of the composer that owns it rather than a peer of that surface's other transients, so opening it dismisses none of them and closes no composer (per `CMT-comments.md` CMT-FR-32 and `ACT-action-control.md` ACT-FR-12). Being a transient of the composer is also what gives it Escape first: in a surface Escape would otherwise dismiss — a composer in a conversation tab or in a discussion panel — an open picker takes the keystroke and closes, and the surface holding it is left exactly as it was, because completing a nickname and closing a composer are not the same gesture.
31. **AGT-FR-31** Every surface here renders and is navigable with nothing configured: no agent described, no agent on the roster, and no provider verified each render their own first-class empty state naming what is needed and where, and none of them is an error.
32. **AGT-FR-32** No surface here dispatches a turn, cancels one, or renders a reply. The roster reports that an agent is answering (AGT-FR-05) and nothing more; a conversation is begun where the agent was addressed — a composer of the discussion column (`CMT-comments.md`), or the tab action control's Discuss composer (per `ACT-action-control.md` ACT-FR-16), whose discussion is read in the surface that `revealDiscussion` selects (per `CVP-conversation-presentation.md`) rather than in the margin itself.
33. **AGT-FR-33** The picker offers exactly the roster agents that are not shadowed and whose nickname **begins with** the characters typed after the sigil, matched without regard to case, ordered by nickname without regard to case; a fragment of no characters offers every such agent. The `@all` handle is offered on that same prefix test and leads them all (AGT-FR-39). The **top match** is the first selectable entry of the list as it renders, and it is what the highlight rests on, so the entry Tab completes is always the one at the head of what the author can see. A fragment matching neither a nickname nor the handle renders a first-class row saying so rather than an empty box.
34. **AGT-FR-34** The picker follows the text under the caret rather than the single keystroke that opened it: it shows while the caret sits at the end of a **candidate tag** — a word-initial `@` (AGT-FR-25) followed only by characters a nickname may carry — and closes as soon as that stops holding. Typing whitespace closes it, because a nickname carries none (per `../core/AGR-agent-registry.md` AGR-FR-04) and what is being typed is therefore no longer a tag; moving the caret out of the candidate tag closes it; and Escape closes it and keeps it closed until the caret leaves that candidate tag. Deleting characters back into a candidate tag shows the picker again against the shorter fragment, so a mistyped nickname is corrected without retyping the sigil.
35. **AGT-FR-35** `@all` is a **reserved handle** rather than an agent: a tag reading `all`, matched without regard to case like any other (AGT-FR-24), addresses every agent on the open project's roster that can answer. It exists because a question about a specification is often worth putting to the whole room rather than to one reviewer, and an author who must name three collaborators one after another to ask it asks it of one of them instead.
36. **AGT-FR-36** `@all` resolves to exactly the roster agents whose availability is `ready`, read from `"list project agents"` (per `../core/AGR-agent-registry.md` AGR-FR-13). An agent that cannot answer is left out of the resolution on the same terms it cannot be completed in the picker (AGT-FR-26), because a handle that dispatched to an expired key would render the refusal as that agent's own failure to reply.
37. **AGT-FR-37** The handle is resolved afresh wherever it is read rather than expanded once when it is typed, so it always means the project's roster as it stands: an agent created after the tag was written is addressed by it, one since deleted or gone unavailable is not, and the same body says different things about two different rosters. Nothing records what the handle meant when it was posted, because `all` names a membership rather than a list of names.
38. **AGT-FR-38** In a project where no roster agent can answer — none on the roster at all, or none of them `ready` — `@all` resolves to nobody and a body carrying it is an ordinary message in every respect: it addresses no one, dispatches nothing, renders unemphasised (AGT-FR-29), and raises no error, exactly as a tag matching no nickname does (AGT-FR-28). Creating an agent is what makes that same text live, nothing about the message having to change.
39. **AGT-FR-39** The picker offers `@all` as its **first** entry whenever the characters typed after the sigil are a prefix of `all`, ahead of every nickname however the nicknames sort, so it is the top match Tab completes (AGT-FR-33). Its entry names the agents it stands for where a nickname's entry names its title (AGT-FR-43), bounded to the one line every entry occupies and reporting how many more it holds when they do not fit, so an author reads whom they are about to address before addressing them. It is selectable while it resolves to at least one agent; while it resolves to none (AGT-FR-38) it is offered in that same position with the reason stated and completed by no key, on the terms AGT-FR-26 sets for an agent that is present but cannot answer — an author reaching for the handle learns that the project has nobody to hear it rather than finding it silently absent.
40. **AGT-FR-40** Completing `@all` inserts the handle itself and nothing else: the composer reads `@all` rather than the nicknames it stands for, and the posted body carries that one tag. The expansion is therefore never frozen into the message, which is what lets the roster change under it (AGT-FR-37), and a reader sees a question asked of everyone rather than a list of names they have to count.
41. **AGT-FR-41** `all` is reserved in both scopes: no Project agent and no Personal agent carries it as a nickname, in any case, so the handle means one thing in every project and no author describes a persona they would then be unable to summon. The nickname field refuses it client-side (AGT-FR-13), and the registry refuses it as a typed `nickname_reserved` (per `../core/AGR-agent-registry.md` AGR-FR-04) for any route that reaches the backend without passing that field.
42. **AGT-FR-42** The editor's **Title** field is a single-line plain-text field, labelled and stated as optional, holding the role the agent takes in a conversation — `UI/UX designer`, `Developer`. It validates nothing and formats nothing, an empty field is an ordinary state that leaves the confirm action enabled, and it is seeded from the agent's stored title when an existing persona is opened (AGT-FR-11) and carried on the confirm of AGT-FR-19 like every other field. What the author typed is sent as typed; the trimming that decides what is stored is the registry's (per `../core/AGR-agent-registry.md` AGR-FR-23), so an agent saved from a field holding surrounding whitespace reopens showing the trimmed value with its internal whitespace and casing intact.
43. **AGT-FR-43** A mention-picker entry for an agent names that agent's **title**, read from `"list project agents"` with the rest of the roster. An agent whose title is empty leaves that position **blank**: no placeholder, no `Not defined`, and not the model in its stead, because the position says what role this collaborator takes and filling it with something else would answer a question the author did not ask. It is the same position an availability warning claims where there is one (AGT-FR-26), so an entry states either the agent's role or why it cannot answer, never both and never a model.

44. **AGT-FR-PRVQ** The Personal Agents section and the Project Agents section compute each agent's availability from the active provider's catalog, read from `"get active ai api catalog"` when the section opens and again whenever the active provider, a verification, or a clear changes. An agent is `ready` when that catalog contains its stored model and is `model_unavailable` otherwise, and when no catalog resolves the agent is `provider_unconfigured` where nothing is configured and `provider_unverified` otherwise (per `../core/AGR-agent-registry.md` AGR-FR-16). The sections, the editor, and the roster therefore agree on which models exist, and an agent is never rewritten because the provider changed.
45. **AGT-FR-MDQW** An agent whose stored model is not in the active provider's model list stays in its section's list and in the roster and is shown as unavailable with the reason of AGT-FR-10. It cannot start a conversation: its tag is not completable (AGT-FR-26) and a dispatch for it is refused (per `../core/AGC-agent-conversations.md` AGC-FR-14). Opening its editor and selecting a model that the active provider offers makes it available again.
46. **AGT-FR-RFSH** Changing the active AI API provider refreshes the model and reasoning data that the persona editors offer, without a restart. When the Custom provider is active, the reasoning selector renders for every selected model (AGT-FR-SOIO).
47. **AGT-FR-RWHL** A Personal agent shadowed in the open project (per `../core/AGR-agent-registry.md` AGR-FR-15) is listed in the roster and in the Personal Agents section with availability `shadowed`, and its row says that a Project agent of that nickname wins in this project. It is not completable in the mention picker, is left out of `@all`, and is addressed by no tag there.
48. **AGT-FR-NJXP** When the author creates, edits, or deletes a Project agent or a Personal agent, the roster, its count, and the mention picker show the change in the open project without a restart. The surfaces read again when the event `"agents changed"` arrives (per `../core/AGR-agent-registry.md` AGR-FR-ZRJD), whichever window made the write.
49. **AGT-FR-ZCDV** A Project agent whose model the active provider does not offer on this machine renders in the roster and in the Project Agents section with the unavailable state of AGT-FR-10. The editor keeps the stored model id unchanged until the author confirms another model, so opening the editor writes nothing to the committed file.
50. **AGT-FR-SOIO** When the active provider is Custom, the editor's reasoning selector offers the model-default entry, then `none`, `low`, `medium`, and `high`, for every model (per `AII-ai-integrations.md` AII-FR-XGIM). The model-default entry states that the Custom provider's reasoning effort applies. A chosen level overrides that default for this agent only.

## Non-functional requirements
- Every surface here renders from stored state without network access: the roster, both sections, and every selector read stored state and make no request to a provider, so an agent list is instant and works offline.
- The mention picker filters the agents already loaded and issues no operation and no request, so it stays responsive to every keystroke while the author is mid-sentence.
- Resolving `@all` is a read of the roster agents the surface already holds, so a message carrying it costs no operation and no request of its own however many agents it turns out to address, and re-resolving it whenever a body is rendered (AGT-FR-37) costs nothing either.
- Bolding a tag is decided from the roster agents already loaded, so a body renders without waiting on anything and a long comment full of `@` characters costs one pass over what is already in hand.
- Typing `@` never costs the author their sentence: the picker takes no focus away from the composer, the only keys it takes while showing are the arrow keys, Enter, Tab, and Escape, every other key reaches the text, and dismissing it leaves what was typed untouched.
- The picker re-filters and re-ranks within a keystroke of the fragment changing, so an author completing a nickname with Tab is never racing a list that has not caught up with what they typed.
- The only credential-derived text any surface here could render is none: nothing about the active provider's key reaches this surface, including its masked hint.
- The roster opens and closes without re-reading the registry more than once per opening, so an author checking who is available does not pay for it repeatedly.
- Every control in every surface here is reachable and operable from the keyboard alone, the mention picker included, so summoning an agent never requires a pointer.
- An agent whose provider has degraded stays visible everywhere it was visible before, with the reason stated, so nothing an author configured disappears without explanation.
