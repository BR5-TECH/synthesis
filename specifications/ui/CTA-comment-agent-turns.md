# Comment agent turns

**Spec code:** `CTA`

## Intent
How an agent takes part in a conversation held in any discussion surface. An author summons a collaborator by typing its nickname into the comment they are writing, and the same act reaches a person or an agent — there is no separate control for talking to a machine. What the agent is doing while it composes renders in the discussion as a message that has not arrived yet, worded as a participant who has been asked something rather than as a spinner, and what it finally says becomes an ordinary comment of the discussion. Who a comment reaches is derived from the conversation itself rather than recorded anywhere: the agents the author last addressed are the ones a follow-up goes to, so a conversation continues without the author naming everybody again, and an author who turns to somebody else has turned to them. Out of scope: the discussion, the shared surface and composer, and the fragment a discussion may sit on, which are `CMT-comments.md`'s and `CVP-conversation-presentation.md`'s; the enrolled agents and the mention picker itself, which are `AGT-agents.md`'s; what a turn does once dispatched, which is `../core/AGC-agent-conversations.md`'s and `../ai/CVL-conversation-loop.md`'s; and any record of a pending or a failed contribution, since neither is part of the conversation and neither survives the running application.

## UI contract boundary
- **Owned by the UI**: the derivation of a conversation's active agents from its own comments; the rules that decide which agents a posted comment is dispatched to and the one batched dispatch a question-set submission takes (CTA-FR-PXJB); the pending contribution, its activity status and its cancel control; the failed contribution and its Retry control; the unsupported-image notice; the composer placeholder that names who an untagged comment will reach; the title line an agent comment renders; and the reading of a proposal reference the discussion surface does not yet hold. None of it is stored: the active set is read back out of the comments each time it is wanted, and the pending, failed and notice states live in session stores keyed by the discussion id for as long as the application runs.
- **Delegated to backend (abstract)**: `"dispatch agent turn"`, `"cancel agent turn"`, `"retry agent turn"`, `"list agent turns"`, `"list recoverable agent turn failures"`, `"list agent turn image notices"`, and the event `"agent turn state changed"` — all owned by `../core/AGC-agent-conversations.md`. `"list project agents"` is owned by `AGT-agents.md`. The comments themselves are appended and read through `CMT-comments.md`'s own operations, and this surface adds none of its own.

## Functional requirements
1. **CTA-FR-VQFJ** A composer offers the project's enrolled agents through the mention picker of `AGT-agents.md` (AGT-FR-25), opened by an `@` that begins a word, narrowed as the nickname is typed, and completed with Tab or Enter (AGT-FR-27).
2. **CTA-FR-TBGF** An agent is summoned by typing its nickname into the comment being written rather than through a control of the discussion surface's own, the act of addressing a collaborator being the same act whether the collaborator is a person or not.
3. **CTA-FR-KDRN** Typing the `@all` handle summons every agent at once, that handle standing for them all (per `AGT-agents.md` AGT-FR-35).
4. **CTA-FR-SKXK** A discussion carrying no composer — locked or resolved (per `CMT-comments.md` CMT-FR-15, CMT-FR-16) — offers no way to address anyone, a discussion that takes no further comment taking no further participant either.
5. **CTA-FR-EACI** Posting a comment appends it first and unconditionally, before anything is dispatched.
6. **CTA-FR-RPVU** The discussion surface then invokes `"dispatch agent turn"` once per distinct agent the comment is to be answered by, each naming this conversation as its origin and the just-appended comment as what addressed it.
7. **CTA-FR-FAWE** The dispatch is taken over the agents themselves rather than over the tags that named them, so a comment reading `@all @arch` dispatches one turn for `@arch` rather than two, and a nickname written twice dispatches one turn rather than two.
8. **CTA-FR-OYFP** A tag resolves to one agent, to several, or to none (per `AGT-agents.md` AGT-FR-24), a single `@all` standing for every enrolled agent that can answer (per `AGT-agents.md` AGT-FR-36).
9. **CTA-FR-FKLG** The author's message stands whether or not any agent answers it, and a comment nobody is to be answered by dispatches nothing at all, an `@all` in a project where none can answer included (per `AGT-agents.md` AGT-FR-28, AGT-FR-38).
10. **CTA-FR-KREF** Dispatching rewrites nothing that was stored: the tags stay in the appended body exactly as they were typed, and that body is what every later derivation of the conversation's active agents reads.
11. **CTA-FR-ZVKL** A comment posted while turns are already outstanding dispatches its own without waiting for them and without cancelling them.
12. **CTA-FR-BXNF** An agent addressed again before it has answered is addressed again, so a discussion carries as many outstanding turns as the author has asked for, a participant asked a second question being answered rather than silenced (per `../core/AGC-agent-conversations.md` AGC-FR-03).
13. **CTA-FR-ZOLW** Each agent with one or more **running** turns in a discussion renders there as **one pending contribution**: a message shaped exactly like a comment, attributed to that agent, and in the position of that agent's oldest running turn. It stays until that agent has no running turn in that discussion.
    - *Why:* An agent asked twice runs two turns (CTA-FR-BXNF), but the author waits on one participant, so two rows for one agent read as a defect.
14. **CTA-FR-XMCQ** A pending contribution reads the **activity status** of that agent's newest running turn and carries a control that invokes `"cancel agent turn"` for every running turn of that agent in that discussion.
15. **CTA-FR-QCMP** A pending contribution is worded as a participant who has been asked something and has not answered yet rather than as a spinner or a progress bar, what the author waits on being a collaborator composing a reply.
16. **CTA-FR-VHOY** A pending contribution carries no attachment and no timestamp of its own, having nothing yet to stamp.
17. **CTA-FR-AZEU** A turn repeating a model call that failed is a turn still working: its pending contribution reads **Thinking…** unchanged through every automatic retry and every wait between them, and keeps its cancel control available throughout.
18. **CTA-FR-HBAB** A pending contribution says nothing anywhere about attempts, failures, or waits — how many times the application had to ask is not something a conversation is about, and a surface that counted them aloud would make the author responsible for a number they can do nothing with.
19. **CTA-FR-QXIG** The discussion surface reads the discussion's outstanding turns from `"list agent turns"` when the artifact opens and follows the `"agent turn state changed"` event thereafter, each turn from either source carrying the tool calls active in it and the order they were activated in (per `../core/AGC-agent-conversations.md` AGC-FR-33).
20. **CTA-FR-FSBH** A discussion reopened while an agent is still thinking shows what is still coming and what that agent is doing rather than appearing finished.
21. **CTA-FR-KVIF** An outstanding turn that is `awaiting_reply` renders no pending contribution: that agent waits on the author rather than composing anything. What it waits on is already in front of the author — a question as a comment, or a **pending question set** above the discussion's composer (per `DQA-discussion-question-answering.md` DQA-FR-NRZB) — and this surface renders nothing further either way.
    - *Why:* A turn that recorded a question set appended no comment, so a rule that assumed one would draw a placeholder for a turn that is not working.
22. **CTA-FR-QTNB** A turn that delivers replaces its pending contribution with the agent's comment, thereafter an ordinary comment of the discussion — stacked in order, quotable, immutable, and counted like any other (per `CMT-comments.md` CMT-FR-08, CMT-FR-12, CMT-FR-14, CMT-FR-29).
23. **CTA-FR-LCVQ** A turn that ends by asking the author a question does the same and renders nothing further: the question arrived as an ordinary comment through the same event any comment arrives by, and the discussion shows a participant who has asked something rather than any indication that the agent is still engaged or that a reply is owed. A turn that ends by recording a **question set** renders nothing further either, and no comment arrives for it: the set arrives through its own event and is rendered by `DQA-discussion-question-answering.md` rather than by anything here.
24. **CTA-FR-ZDDI** A turn that fails **recoverably** — `unreachable`, a provider-call `timed_out`, `empty_reply`, `tls_untrusted`, `invalid_response`, or `invalid_request`, whose terminal state carries permission to retry (per `../ai/CVL-conversation-loop.md` CVL-FR-18 and `../core/AGC-agent-conversations.md` AGC-FR-17) — replaces its pending contribution **in place** with a failed contribution, the position the answer would have taken being where the author is already looking for it.
25. **CTA-FR-IGNT** Every other failure and every cancellation removes the pending contribution and renders its typed failure inline at the foot of the discussion (per `CMT-comments.md` CMT-FR-34) with no offer to retry, nothing about repeating a locked discussion, a refused credential, or a turn the author cancelled going differently.
26. **CTA-FR-UBJT** Under every one of those outcomes each comment in the discussion is untouched and none is added, a conversation gaining a line only when somebody actually said something.
27. **CTA-FR-OBRO** A pending contribution and a failed contribution alike are no part of the artifact and no part of the conversation: each is held in a session store keyed by the discussion id, so it survives the discussion moving between owner surfaces and tabs and is lost only when the application quits.
28. **CTA-FR-ZJZD** No log line anywhere records a pending or a failed contribution.
29. **CTA-FR-EZNI** Neither contributes a match to the Find and Find & Replace panels, occupies a position in the artifact's undo history, nor marks anything dirty (per `EFR-editor-find-replace.md` EFR-FR-DDUX, and per `EDT-editor.md` EDT-FR-23, EDT-FR-04).
30. **CTA-FR-XKRY** Neither is counted by any unresolved-discussion total, and neither is quotable, resolvable, lockable, or reachable by anything that reads the conversation — the Comments panel's rows, the project's search, and a fold of the discussion all read exactly the comments that were posted (per `CMT-comments.md` CMT-FR-31).
31. **CTA-FR-SWXX** A relaunch while a turn is outstanding or while a failure stands finds neither the turn, nor its placeholder, nor any offer to retry it (per `../core/AGC-agent-conversations.md` AGC-FR-23, AGC-FR-31), and the discussion reads exactly as it did before the agent was addressed.
32. **CTA-FR-LCFU** A conversation's **active agents** are the agents its author last addressed in it, and they are **derived** rather than recorded: nothing stores them, no operation saves them, and no payload carries them.
33. **CTA-FR-XBIN** The discussion surface reads the conversation's **human-authored** comments from newest to oldest, and the first of them carrying at least one tag that resolves against the project's roster settles the set — exactly the agents that one comment's tags resolve to, and no other.
34. **CTA-FR-BMHF** A comment naming several agents makes all of them active together, and a comment carrying `@all` makes every enrolled agent that can answer active (per `AGT-agents.md` AGT-FR-36).
35. **CTA-FR-IMKG** A comment carrying no tag, or none that resolves to anybody, settles nothing and the reading passes over it to the comment before it.
36. **CTA-FR-WYID** A conversation in which no human comment carries a resolvable tag has no active agent at all.
37. **CTA-FR-XTZC** An **agent's** own comment settles nothing wherever it sits in that order, so who the author is talking to stays the author's decision alone.
38. **CTA-FR-YGYP** The reading is taken against the roster **as it stands** each time the set is wanted — when the conversation is opened, before a comment is dispatched, and whenever its comments or the project's agents change — so `@all` means the room as it now is (per `AGT-agents.md` AGT-FR-37, AGT-FR-40): an agent enrolled since that comment was written is active under it, and one since removed or gone unavailable is not.
39. **CTA-FR-EVGD** Because the comments persist in the repository's own append-only log and the set is read back out of them (per `../core/CMS-comments-storage.md` CMS-FR-01, CMS-FR-31), the same conversation has the same active agents after a relaunch, after a reopen, and in whichever surface it is read.
40. **CTA-FR-QUXJ** A comment whose own tags resolve to at least one enrolled agent dispatches to exactly those, and by standing in the conversation makes exactly those its active agents from then on: an explicit mention **replaces** the set rather than joining it, so an author who turns to somebody else has turned to them.
41. **CTA-FR-HCMJ** A comment carrying no tag, or none that resolves to anybody, dispatches to the conversation's active agents and leaves that set exactly as it stands, so a follow-up reaches whoever the author was last talking to without their being named again and a remark addressed to nobody dismisses nobody.
42. **CTA-FR-IXTC** A comment in a conversation with no active agent at all dispatches nothing.
43. **CTA-FR-QNBS** Those three rules are the whole of who a comment reaches — its own resolvable tags, or failing those the conversation's active agents, or nobody — and no other state of the conversation adds a recipient to it, an agent awaiting a reply among them.
44. **CTA-FR-TTMS** Each dispatch names this discussion by its id and its opening target — the artifact, the draft, or the note — together with its fragment where it has one, and names the comment that addressed the agent (per `../core/AGC-agent-conversations.md` AGC-FR-05). One rule decides this for every discussion, whatever kind of target or fragment it carries.
45. **CTA-FR-RPND** The rules hold in every owner surface that renders the shared composer — the Editor rail, the draft discussion column, the action control's panel and opening composer, the Flow, Diff, and History panels, and the conversation tab — so a note discussion continued in its conversation tab dispatches on exactly these terms.
46. **CTA-FR-SSUZ** The rules hold for every **human-authored** comment the application appends on the author's behalf and not for a composer's alone: a proposal decision is such a comment (per `../core/DCP-draft-change-proposals.md` DCP-FR-15, `../core/PCP-prompt-change-proposals.md` PCP-FR-16) and reaches the conversation's active agents on these same terms and no others (per `DCR-draft-change-review.md` DCR-FR-15, `PCR-prompt-change-review.md` PCR-FR-14), so no surface anywhere keeps a recipient rule of its own. The one thing that varies is **how many** dispatches a set of such comments produces: a question-set submission is one batch rather than one dispatch per comment (CTA-FR-PXJB).
47. **CTA-FR-PXJB** An accepted **question-set submission** (per `DQA-discussion-question-answering.md` DQA-FR-KDVU) is one **routing batch**. Once the append has committed, the surface derives the discussion's active agents **once**, on the rules of CTA-FR-QUXJ through CTA-FR-QNBS, and invokes `"dispatch agent turn"` once per distinct active agent, naming the **final answer comment** as what addressed it.
48. **CTA-FR-ZKVD** No individual question or answer comment of that submission dispatches a turn of its own, so a set of ten questions costs one turn per active agent rather than ten. Who those agents are is derived from the conversation as it stands after the append, the agent that asked among them only where the ordinary rules make it active.
49. **CTA-FR-YWSU** An agent's delivered answer dispatches nothing: only a comment a person posted starts a round of turns, so a conversation among several agents never continues without the author and every call made is one they asked for.
50. **CTA-FR-DWCK** An agent's comment changes the active agents no more than it dispatches: a tag one agent writes — naming a colleague, quoting an earlier message, or carrying `@all` — addresses nobody and hands the conversation to nobody.
51. **CTA-FR-DGOC** The active set binds **every** discussion and distinguishes none of them: a discussion about a fragment and a discussion about the whole target derive it from their own comments on identical terms and dispatch by the same rules, in the artifact, draft, and note targets alike.
52. **CTA-FR-DNMV** What makes an agent active is a human comment naming it and nothing else: an agent that answered and was not named again is finished, and an agent named by another agent was never addressed at all.
53. **CTA-FR-JQDM** An agent is **awaiting a reply** in a conversation when a turn of its own there is outstanding in the state `awaiting_reply` (per `../core/AGC-agent-conversations.md` AGC-FR-28) — when it asked the author something and has not been answered.
54. **CTA-FR-ELIJ** The discussion surface learns that state from the same two sources it learns every turn from, and uses it for one thing alone: such a turn renders no pending contribution.
55. **CTA-FR-DMNI** Awaiting a reply adds **no recipient** to anything: an agent that asked a question is answered because the author's next comment names it or because it is the conversation's active agent, and an agent the author has since turned away from is not dispatched to merely for having asked.
56. **CTA-FR-IEPG** Nothing here obliges the author to answer: an agent that asked something is answered the moment the author writes to it, and an author who has turned to somebody else has turned to them.
57. **CTA-FR-BMBL** The state lives no longer than the running application (per `../core/AGC-agent-conversations.md` AGC-FR-23), which costs the conversation nothing: routing never consulted it, and the comments the active set is read from survive the relaunch as the registration does not.
62. **CTA-FR-UKIG** A proposal control whose proposal the discussion surface's reading does not hold renders **inert**: it names the prompt as every proposal control does, carries no word about what the proposal has become, and opens nothing.
63. **CTA-FR-SACG** Such a control states that the change is **no longer available** only once a reading that **completed** did not return it, as an attachment whose content could not be loaded states so (per `CMT-comments.md` CMT-FR-49).
64. **CTA-FR-SPFS** A reading not yet taken, still in flight, or failed is no evidence that a proposal is gone. The control is the discussion surface's only route to the decision (per `DCR-draft-change-review.md` DCR-FR-HVXK, `PCR-prompt-change-review.md` PCR-FR-03), and one that disowned a proposal still standing would leave it undecidable, with its target's one pending slot held and the agent that made it refused another (per `../tools/PDC-propose-draft-changes-tool.md` PDC-FR-08, `../tools/PPC-propose-prompt-changes-tool.md` PPC-FR-09).
65. **CTA-FR-XVNC** A control the reading does not answer for **asks for a reading** rather than settling for the answer it has. The discussion surface asks for a target's proposals when a reference to one of them is first rendered, again whenever a previous ask failed, and once more when an ask that completed did not return the proposal a reference names — that last being what heals a reading taken before the proposal existed and left behind by an event that did not arrive.
66. **CTA-FR-OWQX** The **target** is the draft for a `proposal` and the artifact for a `prompt_proposal`, and the two are read by their own commands and counted separately.
67. **CTA-FR-LOOE** The asking is bounded so a discussion surface never spins on it: the further ask is made **once per reference**, and **one ask is in flight per target** however many of its references are on screen, so a conversation carrying a dozen proposals costs one reading per target.
68. **CTA-FR-MGVJ** A **failed contribution** takes the shape and the position of the pending contribution it replaced: a message attributed to the same agent, in the place that agent's answer would have taken, carrying no attachment and no timestamp of its own.
69. **CTA-FR-RQQJ** A failed contribution states that the agent **could not produce a response** and carries a labelled **Retry** control.
70. **CTA-FR-HJLA** A failed contribution is visually distinct from a delivered comment and from a pending contribution both, by a marker of its own and by more than colour, a message that reads like an answer but is the absence of one being the worst thing the surface could render.
71. **CTA-FR-EXVN** A failed contribution names no failure code, no provider, no attempt count, and no diagnostic: what the author can act on is the Retry beside it, and everything else about what went wrong is in the session log. The one exception is `tls_untrusted`: its failed contribution states the host and the cause (unknown issuer, expired certificate, or host name mismatch) taken from the turn's `tls_failure` (per `../ai/CVL-conversation-loop.md` CVL-FR-28, `LOG-logs.md`).
72. **CTA-FR-QDDG** **Retry** invokes `"retry agent turn"` for the failed turn, which starts a **new** turn for the same agent, the same origin, and the same trigger comment (per `../core/AGC-agent-conversations.md` AGC-FR-32).
73. **CTA-FR-XNBS** Retry posts nothing: the human comment that addressed the agent is neither reposted, re-appended, nor edited, no composer is opened or seeded, and the discussion's comments are exactly what they were.
74. **CTA-FR-CERW** Activating Retry replaces the failed contribution with **Thinking…** again, and the new turn is thereafter an ordinary outstanding turn in every respect — cancellable, retried automatically on its own terms, and rendered like any other.
75. **CTA-FR-ESNJ** The Retry control is **disabled** while dispatch is being initiated, so one activation is one turn however impatiently it is pressed.
76. **CTA-FR-UUXA** A dispatch the backend refuses synchronously restores the failed contribution as it stood and renders the typed refusal inline at the foot of the discussion (per `CMT-comments.md` CMT-FR-34), leaving the offer available to try again.
77. **CTA-FR-RHPP** A discussion renders a failed contribution for the conversation's **current** recoverable failure and for no other, at most one at a time however many of that conversation's turns have failed.
78. **CTA-FR-STWA** The discussion surface reads that failure from `"list recoverable agent turn failures"` when the artifact opens and from the terminal `"agent turn state changed"` event thereafter, on exactly the terms it reads outstanding turns, so a discussion closed and reopened while a failure stands renders that failure and its Retry again rather than appearing to have delivered.
79. **CTA-FR-OUYQ** A later recoverable failure in that conversation **replaces** the one showing.
80. **CTA-FR-RUVS** The offer is retired — the failed contribution disappearing with nothing rendered in its place — when its Retry is taken and when any later **human-authored** comment is appended to the conversation.
81. **CTA-FR-GQSP** An agent-authored comment retires nothing: an agent answering elsewhere in the discussion does not mean the author has stopped wanting the answer that failed.
82. **CTA-FR-XZUO** A **locked** discussion renders a failed contribution without its Retry control: a discussion that takes no further contribution takes no further turn either, the backend would refuse the retry `discussion_locked`, and offering a control whose only outcome is a refusal is worse than offering none.
83. **CTA-FR-CSZT** A **resolved** discussion keeps its Retry, on the reasoning that lets an answer land in one: withholding a composer there is the discussion surface's own decision about what the author should be invited to add rather than a refusal the backend makes, and a turn the author had already asked for still belongs to them.
84. **CTA-FR-TJCA** A discussion locked while its failed contribution is showing loses the control in place, and one unlocked gets it back.
85. **CTA-FR-KFUF** An agent comment whose participant carries a **non-empty title** renders that title on a second line directly below the agent's name and above the body, so a reader learns what role the collaborator was answering in without leaving the discussion.
86. **CTA-FR-YOGW** The title is the snapshot that comment's own participant carries (per `../core/CMS-comments-storage.md` CMS-FR-65) and never the agent's current title: a comment written by an agent since retitled reads as it was written, and the discussion surface resolves no agent record to render one.
87. **CTA-FR-KYPK** A participant carrying **no** title and one carrying the empty string both render no such line and nothing in its place — no placeholder, no dash, and never the words `Not defined`, which belong to a prompt's substitution alone (per `../ai/CVL-conversation-loop.md` CVL-FR-04).
88. **CTA-FR-CHUJ** A human comment renders no title line, and neither does a pending or a failed contribution, neither of which is a comment with a participant to carry a snapshot.
89. **CTA-FR-IAKP** A composer ready to take an **untagged** comment carries who that comment will reach in its **placeholder** and nowhere else.
90. **CTA-FR-IGBO** An empty composer in a conversation with at least one active agent reads `Reply to @arch, @sec…`, naming every one of the conversation's active agents in the order the comment that settled the set names them, an `@all` naming the roster in the order `"list project agents"` returns it.
91. **CTA-FR-QUGP** An empty composer in a conversation with no active agent reads `Reply…`, an ordinary state of a conversation nobody has addressed an agent in rather than an error, and one that neither disables the composer nor refuses a post.
92. **CTA-FR-YGMB** No line of text above the field, beside it, or below it states a recipient, the field itself being where the author is about to write to them.
93. **CTA-FR-ZRXL** A list of recipients too long for the field is **truncated with an ellipsis** at the field's trailing edge: it never wraps to a second line and never grows the field.
94. **CTA-FR-EMQS** The untruncated list is disclosed nowhere else — no tooltip, no hover title, and no accessible name of the field carries it, the field's accessible name naming the composer exactly as it does in a conversation with no active agent at all.
95. **CTA-FR-RDSD** The placeholder is presentation and nothing more: the moment the author types it gives way to what they typed, no part of it is carried in the body that is posted (per `CMT-comments.md` CMT-FR-11), and it returns when the field is emptied again.
96. **CTA-FR-NMNE** A composer that **opens** a conversation carries its own placeholder naming what is to be discussed instead (per `ACT-action-control.md` ACT-FR-13), there being no conversation yet for an agent to be active in.
97. **CTA-FR-RYGU** The naming is a **reading** and is presented as one rather than as anything the conversation has saved: it is recomputed whenever either of its two inputs changes — when the conversation opens, whenever a comment is appended anywhere in it, and whenever the discussion surface's own reading of `"list project agents"` returns a roster it did not hold before.
98. **CTA-FR-NFYX** The discussion surface introduces no watcher and no poll for either input, and the set a dispatch uses is derived at the moment of that dispatch rather than taken from what the placeholder last read.
99. **CTA-FR-IQDY** A composer holding text names no recipient at all: the tags in what was typed are the author's own words, legible where they wrote them and emphasised where they resolve (per `AGT-agents.md` AGT-FR-29), and a composer that listed them back would be reading the message back to the person writing it.
100. **CTA-FR-FBJR** A pending contribution's **activity status** is one short line of fixed wording that says what the agent is doing at this moment rather than how far through it is.
101. **CTA-FR-IHOB** A turn waiting on a model response reads **Thinking…**.
102. **CTA-FR-HEYB** A turn with a tool call active reads the status that tool is given here, and the vocabulary is exactly this:

     ```
     search_specifications     Searching related specifications…
     read_file                 Reading a project file…
     search_drafts             Searching drafts…
     read_draft                Reading a draft…
     search_notes              Searching notes…
     search_documents          Searching documents…
     get_document              Reading a document…
     search_skills             Searching available skills…
     list_skills               Listing available skills…
     load_skill                Loading skill instructions…
     ask_user_comment          Asking a clarifying question…
     ask_discussion_questions  Preparing questions for you…
     propose_draft_changes     Preparing draft changes…
     propose_prompt_changes    Preparing prompt changes…
     openrouter:web_search     Searching the web…
     openrouter:web_fetch      Fetching from the web…
     ```

     These are the tools a conversation turn is lent (per `../ai/CVL-conversation-loop.md` CVL-FR-08, CVL-FR-30) and the whole of the vocabulary a conversation needs: a tool no conversation turn carries has no status here, the graduation loop's own tools among them.
103. **CTA-FR-VSIM** A call whose tool that table does not name reads **Working…** (per `../tools/TLC-tool-conventions.md` TLC-FR-27), so a status is never empty and a tool the discussion surface has not been taught still reads as work in progress.
104. **CTA-FR-VRJU** Every status is the discussion surface's own fixed text: none is composed from a tool's arguments, from its result, or from anything the model wrote, none of which reaches the discussion surface at all (per `../ai/CVL-conversation-loop.md` CVL-FR-26).
105. **CTA-FR-PCNW** The status changes nothing else about the contribution — its shape, its position, the agent it is attributed to, its cancel control, and its absence from the conversation are the same whichever status it reads.
106. **CTA-FR-IWOJ** A turn with several tool calls active at once reads the status of the **most recently activated** of them, that being the thing the agent turned to last and the thing it is still doing.
107. **CTA-FR-KWOF** Which one that is comes from the **activation order** the turn itself carries (per `../core/AGC-agent-conversations.md` AGC-FR-33) and never from the order events reached the discussion surface, so calls activated by one model response are ordered among themselves and two events arriving out of order settle on the same status either way.
108. **CTA-FR-IVNG** When the call being spoken for completes, fails, or is cancelled, the status becomes that of the most recently activated call **still active** at once; it is never cleared, blanked, or held at the finished call while another call is running.
109. **CTA-FR-TFGR** When no call is active and the turn is still waiting on a model response, the status is **Thinking…** again, and the turn reads that way through every automatic retry.
110. **CTA-FR-JQUU** Every transition lands on exactly one non-empty status: there is no moment at which a pending contribution reads nothing.
111. **CTA-FR-ARBB** A turn whose images the selected provider and model could not take renders an **unsupported-image notice** beside the contribution it produced.
112. **CTA-FR-XSGX** The discussion surface learns the notice from the turn itself — `images_omitted` on the terminal `"agent turn state changed"` event, and `"list agent turn image notices"` when the conversation is mounted or remounted (per `../core/AGC-agent-conversations.md` AGC-FR-37, AGC-FR-39) — on exactly the terms it learns a recoverable failure.
113. **CTA-FR-GFZE** The notice is a **status and not an error**: it reads `Images were not sent; text and image metadata were sent instead` and sits with the agent's own contribution so a reader can tell which turn it is about.
114. **CTA-FR-CYJR** The notice is announced through a status role or live region so a screen-reader user learns of it without hunting for it, and it is reachable and readable from the keyboard alone and legible without colour.
115. **CTA-FR-LVPC** The notice blocks nothing: the conversation is answered, the answer is an ordinary comment, a turn still running is still cancellable, a failed turn's **Retry** is unaffected, and the author may ask again at any moment.
116. **CTA-FR-MVWW** An author who changes the agent's model to one that takes images and asks again is answered with them, and the notice for that conversation goes.
117. **CTA-FR-NCVL** Like a pending and a failed contribution, the notice is held in the same session store keyed by the discussion id: no log line records it, it is quotable, resolvable, and lockable by nothing, and no reader of the conversation ever sees it.
118. **CTA-FR-MWPE** Agent behaviour is **identical in every owner surface**. The pending contribution, its cancel control, the failed contribution and its Retry, the unsupported-image notice, the question-set block, and the dispatch rules render and act the same in the Editor rail, the draft discussion column, the action control's panel, the Flow, Diff, and History panels, and the conversation tab, because each renders the one shared discussion surface. A pending or failed contribution that is current when a discussion moves from one owner surface to another is still shown after the move, and Retry in either surface acts on the same failed turn, so it is never offered twice for one failure.

## Non-functional requirements
- Nothing this surface derives is persisted. The active set is read out of the conversation's own comments each time it is wanted, and the pending, failed, and notice states are held in memory for as long as the application runs, so a relaunch reconstructs everything that should survive and nothing that should not.
- No status, placeholder, or notice this surface renders is composed from a model's output, from a tool's arguments, or from a tool's result, so nothing an agent writes can reach the discussion surface as chrome.
- Every control this surface adds — cancel, Retry, and the notice — is reachable and operable from the keyboard alone and is legible without colour.
- The reading of a target's proposals is bounded: one ask in flight per target and one further ask per reference, so a conversation carrying many proposals costs one reading per target rather than one per reference.
