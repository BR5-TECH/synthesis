# Git

**Spec code:** `GIT`

## Intent
Bottom-panel surface for the Git work that is line-shaped and wide: the commit log of the active worktree with the files and diffs read out of each commit, the branch listing with each branch's changes against its base, checkout, branch information and confirmed deletion, the pull-request list with each pull request's description and full conversation, the **Logs** section whose push/pull output area every transfer streams into, the top-chrome **Push** control that starts a push from anywhere in the main window, and the **Ready tasks** section where the author claims GitHub Tasks that are ready to start and graduates them (per `../core/GPP-github-polling.md`). The v1 interactive loop (author in Synthesis → commit → external agent picks up artifacts from the repo) makes Git operations first-class in v1, and this content — commit messages, hashes, branch names, transfer output — is wide and line-shaped, so it lives in the bottom panel per the placement rule. Out of scope: authoring a commit, which belongs to the Changes panel and the commit message window it opens (`CHG-changes.md`, `CMW-commit-message.md`); this panel offers no working-tree listing and no way to select what a commit carries.

## User stories
- As a user, I want to read the commit log and each commit's diff without leaving the IDE so that I can check what the last hand-off actually contained.
- As a user, I want to select a commit, see the files it changed grouped by folder, and read one file's diff beside them, so that I can check what a commit contained without losing the width of the panel.
- As a user, I want to select a branch and read the files and diffs it changed against the branch it grows from, beside each other, so that I can review a branch without checking it out.
- As a user, I want to see local and remote branches, read what a branch holds, and delete a branch I no longer need together with its linked worktree, so that stale work does not pile up.
- As a user, I want a deletion to warn me before it discards uncommitted work, and to refuse to delete the branch or worktree I am standing on, so that I never lose work by accident.
- As a user, I want to filter pull requests as open or closed and read one pull request's description, comments, reviews, and activity, so that I can stay in one tool.
- As a user, I want to see the GitHub Tasks that are ready to start and claim one into a graduation, so that work planned on GitHub reaches an agent without copying it by hand.
- As a user, I want one place where the output of every push and pull lands, whichever surface I started it from, so that a failed transfer is diagnosable from a single transcript.
- As an author who has committed, I want a **Push** control in the top chrome so that I publish my work without opening the Git panel or the Changes panel.
- As an author, I want no Push control to accept a second push while one is running, whichever control started it, so that one branch is never published twice at once.

## UI contract boundary
- **Owned by the UI**: bottom-panel layout, sections for commits / branches / PRs / ready tasks / logs and the left rail that selects between them, the commit rail, the two-column view of folder-grouped files and the file diff, its divider and its persisted width (GIT-FR-WMVK, GIT-FR-FATV), the commit file diff view (GIT-FR-KPTE through GIT-FR-TFAU), the branch selection and the branch comparison view (GIT-FR-LNEI, GIT-FR-GDMG, GIT-FR-SION), the Local / Remote switch, the branch context menu, the branch information overlay, the deletion confirmation, its warnings and its inline errors (GIT-FR-HLGO through GIT-FR-UDKY), the pull request filters, list, description, and timeline (GIT-FR-OBZW through GIT-FR-LKRX), the polling schedule the main window drives (GIT-FR-CVSB), the Ready tasks rows, states, and actions (GIT-FR-OGHO through GIT-FR-RYPO), branch switcher, the Logs section with its transfer controls and its push/pull output area, and the retention of its transcript while the panel is closed (GIT-FR-PZIE, GIT-FR-KLNK, GIT-FR-QMYB), the top-chrome **Push** control, its visibility, its availability, its accessible states, and its routing of authentication errors (GIT-FR-XXLE, GIT-FR-CNQO, GIT-FR-IMSH), the selection of the branch a status bar row names and its rendering (GIT-FR-FZMS), and the routing of an authentication error to either the token picker modal or the Global settings GitHub section (GIT-FR-10).
- **Delegated to backend (abstract)**: "list commit history", "list commit files (commit id)", "get commit file diff (commit id, path)", "list branches", "list branch compare files (name, kind)", "get branch compare file diff (name, kind, path)", "get branch information (name, kind)", "inspect branch deletion (name)", "delete branch (name, delete remote, discard uncommitted)", "create branch", "checkout branch", "get upstream sync state", "push current branch", "pull current branch", "list pull requests (state)", "create pull request", "get pull request detail", "list pull request timeline (id)", "get github polling state", "poll github ready tasks", "claim github task (issue number)", "retry github claim (issue number)", "acknowledge github claim (issue number)", "open github task issue (issue number)", "delete work stream (id, force, discard uncommitted)" and "get work stream uncommitted paths (id)" for the branch of a work stream (GIT-FR-XOLE), and "open publication issue (draft id, url)". The six polling operations are owned by `../core/GPP-github-polling.md` and the open-publication-issue operation by `../core/GHP-github-publication.md`; the two work stream operations are owned by `../core/WKS-work-streams.md`; "get upstream sync state" and "push current branch" are owned by `../core/GTC-git.md`, and the top-chrome **Push** control uses those two and no others; the panel also follows the event `"github polling changed"` of `../core/GPP-github-polling.md`. Stubs may return canned state during the walking skeleton. The panel additionally consumes the events `"git output line"` and `"git operation finished"` (owned by `../core/GTC-git.md`) to populate the push/pull output area of its Logs section, and `"branches changed"` (owned by `../core/WTC-worktree-context.md`) to keep its branches section current (GIT-FR-11); it introduces no command or event of its own for either, and the top-chrome **Push** control introduces none. The panel also receives the activation of a status bar row whose operation carries the `git_push` destination of `../core/PRG-progress-reporting.md` PRG-FR-KXQW, which the status bar routes (`STB-status-bar.md` STB-FR-RWPD); the panel introduces no command or event for it.

## Functional requirements
1. **GIT-FR-01** Git is a bottom-panel surface, selected by its own toggle in the activity bar's bottom-panel cluster (per `SNV-shell-navigation.md` SNV-FR-44).
2. **GIT-FR-02** Git renders five sections: **Commits**, **Branches**, **PRs**, **Ready tasks**, and **Logs**. A tab-like control for each stands in the left rail, and exactly one section shows at a time.
3. **GIT-FR-03** The **Commits** section describes the active worktree's history. Its rail lists commits, and its large view is the two-column view of GIT-FR-WMVK: the files of the selected commit and the diff of the selected file (GIT-FR-KPTE through GIT-FR-TFAU).
4. **GIT-FR-04** The **Branches** section lists local and remote branches and supports create-branch, branch selection (GIT-FR-LNEI), and checkout-branch from the branch menu (GIT-FR-ZEKI). The listing describes the repository whichever worktree is active. Checkout is offered only while the active worktree is the repository's primary one (per `../core/WTC-worktree-context.md` WTC-FR-21).
    - *Why:* Checkout is the operation of `WTS-worktree-selector.md` WTS-FR-15 and drives the same switch transition (per `OVW-overview.md` OVW-FR-12), so the two surfaces are routes to one behaviour.
5. **GIT-FR-05** The **PRs** section lists the current repository's pull requests under an **Open** and **Closed** filter. Selecting one shows its description and its full conversation and activity timeline inside the panel (GIT-FR-OBZW through GIT-FR-LKRX). **Create PR for current branch** stays at the top of the rail.
6. **GIT-FR-06** Wide line-shaped output (push/pull/PR check output) renders as scrollable text within the panel without overflowing into the main viewport.
7. **GIT-FR-07** Activating Git from a Dashboard widget routes the bottom panel to the Git surface (per `DSH-dashboard.md` DSH-FR-06).
8. **GIT-FR-08** Force-push and history rewrite are not exposed. Deleting a local branch together with its linked worktree is exposed only through the **Delete** action of the Branches section, after a confirmation (GIT-FR-QYWP). A remote-tracking entry that disappears because the remote deleted its branch follows from a refresh (per `../core/GTC-git.md` GTC-FR-13).
9. **GIT-FR-09** The commit log and the push/pull output area describe the project's active worktree (per `../core/WTC-worktree-context.md` WTC-FR-03), never another worktree of the same repository. A change of the active worktree reloads them against the new content root and discards the selected commit, the selected file, any diff, and any open branch menu or overlay.
10. **GIT-FR-10** An operation that fails because the project resolves no GitHub token (per `../core/GTC-git.md` GTC-FR-10) is answered by the panel according to which of the two typed causes it carries. A selection-required failure opens the token picker modal (`GHA-github-authentication.md` GHA-FR-16), and the operation runs on confirmation and is abandoned on cancellation (GHA-FR-17). A missing-token failure renders inline in the panel with a route to the Global settings GitHub section, because there is nothing to choose between (GHA-FR-19).
11. **GIT-FR-11** The branches section reloads its listing on `"branches changed"` (per `../core/WTC-worktree-context.md` WTC-FR-25), so a branch fetched by the top-chrome refresh control (`WTS-worktree-selector.md` WTS-FR-30) appears in the section and a remote-tracking entry the same refresh pruned disappears from it, without the panel being closed and reopened. Reloading the branch listing is not a worktree change: no other section reloads on this event and no inline diff is discarded, because nothing about the active worktree's content has moved.
12. **GIT-FR-OGHO** The **Ready tasks** section is a section of this panel and adds no bottom-panel surface. It renders the view of `"get github polling state"`, read when the section mounts and again on every `"github polling changed"`.
13. **GIT-FR-CVSB** The main window polls through `"poll github ready tasks"` once when a project opens and then once per configured interval while the project stays open, whether the Git panel is shown, hidden, or on another section. No interval, no selected Project, or an `invalid` configuration starts no timed poll.
14. **GIT-FR-SLRD** A change of the interval or the Project, made in Project settings, reschedules the timed poll from the moment `"github polling changed"` reports it. Closing or switching the project stops the schedule of that project.
15. **GIT-FR-LUSE** Each unclaimed ready task renders as one row with its title, its repository as `owner/name`, its issue number, a link to its issue URL, and its current Project Status. Activating the link invokes `"open github task issue (issue number)"`.
16. **GIT-FR-OZYT** Each GitHub-shadow draft renders as its own row, apart from the unclaimed rows, with its name, its status in words, its repository and issue number, a link to its issue, and a link to its draft. The draft link opens the draft's New Artifact tab, and the issue link invokes `"open publication issue (draft id, url)"`.
17. **GIT-FR-OLNA** Each pending claim renders as its own row naming its issue, with a **Retry** action. A shadow-draft row whose status is `github_shadow` and that no graduation run holds offers **Graduate**, which opens the start dialog of `GSD-graduation-start-dialog.md` for that draft.
18. **GIT-FR-NQTZ** **Claim and graduate** invokes `"claim github task (issue number)"`, then opens the start dialog for the returned draft, then invokes `"acknowledge github claim (issue number)"` once the dialog is open. A refusal renders inline on that row, and no dialog opens.
19. **GIT-FR-FTHT** **Retry** invokes `"retry github claim (issue number)"` and continues on the terms of GIT-FR-NQTZ. Cancelling the dialog, or a refused start, keeps the shadow-draft row and its **Graduate** action.
20. **GIT-FR-EZFL** **Refresh** invokes `"poll github ready tasks"` at once. It is available while a Project is selected and the configuration is not `invalid`, whether or not an interval is set, and it is disabled and marked busy while a poll is in flight.
21. **GIT-FR-HNGQ** The section renders exactly one of these states in words: **loading** while a poll is in flight and no rows exist, **empty** when the last successful poll found no unclaimed task, **not configured** with a route to Project settings, **configuration error** with the error text and a route to Project settings, or the rows.
22. **GIT-FR-RUAH** After a failed poll the rows of the last successful poll stay, are marked **stale** with the instant of that poll, and the error text renders inline above them. Stale text never reads as an empty result.
23. **GIT-FR-RYPO** Every action of the section is reachable and operable by keyboard. **Refresh** and each **Claim and graduate**, **Retry**, and **Graduate** carry accessible names that include the issue title or number, and a busy or disabled action states that in words and in its accessible state.
24. **GIT-FR-TZUI** While a claim, a retry, or a poll is in flight, every other control of the panel and of the application stays usable. Only the action in flight and the other actions of its own row are disabled.
25. **GIT-FR-XXLE** A **Push** control is rendered in the top chrome immediately after the worktree selector's refresh control and before the work stream selector (per `SNV-shell-navigation.md` SNV-FR-32). It is rendered under exactly the condition the worktree selector is rendered (per `WTS-worktree-selector.md` WTS-FR-02): while the open project's content root sits inside a Git repository it is present, and while it does not it is absent. It is available on exactly the terms of `CHG-changes.md` CHG-FR-37, read from `get upstream sync state` through the same reading as the Changes panel's **Push** and this panel's **Push** (GIT-FR-04), so no control offers a push another refuses. It is unavailable while the branch has no commit its remote lacks, while the repository has no remote, and while a push is running (GIT-FR-QMYB). Activating it invokes `"push current branch"` and nothing else: it creates no commit, pulls nothing, fetches nothing, and does not change the active worktree or its branch.
26. **GIT-FR-QMYB** A push is one shared operation across the top-chrome **Push** control, this panel's **Push**, and the Changes panel's **Push** (`CHG-changes.md` CHG-FR-43). While any push is running, every one of the three is unavailable, whichever of them started the push. A second push is refused on the client before any command is invoked, including an activation that arrives before the first push has produced any output. The running state ends on the terminal `"git operation finished"` event or when the invocation is rejected. Every push, whichever control started it, writes its output lines and its terminal status into this panel's push/pull output area. The transcript and the running state belong to the main window rather than to this panel, so a push started while the panel is closed, hidden, or showing another section is complete in the output area when the panel opens. A change of the active worktree or of the project discards the transcript with the other sections (GIT-FR-09). It does not clear the running state, because a push that was started keeps running in the backend: every Push control stays unavailable until that push ends. The progress of a running push is reported by the status bar (per `../core/GTC-git.md` GTC-FR-22) and by no other surface of the top chrome.
27. **GIT-FR-CNQO** The top-chrome **Push** control has the accessible name **Push** and is operable with Enter and Space. While unavailable or busy it stays reachable by keyboard, starts nothing, keeps its usual icon grayed out, and marks the state in its accessible state. Its reason is its accessible description and its one tooltip, shown below it at the width of the text on hover and keyboard focus: **Nothing to push — the branch is level with its remote.**, **This repository has no remote configured.**, **The branch's standing against its remote is unknown.**, or **A push is already running.**
    - *Why:* The same icon keeps the control recognizable in every state; the accessible state and the reason in words carry the state where the dimming is not seen.
28. **GIT-FR-IMSH** A push started by the top-chrome **Push** control that fails because the project resolves no GitHub token is answered according to its typed cause (per `../core/GTC-git.md` GTC-FR-10), on the terms of GIT-FR-10 and `CHG-changes.md` CHG-FR-45. `github_token_selection_required` opens the token picker modal (`GHA-github-authentication.md` GHA-FR-16), and the push runs once on confirmation and is abandoned on cancellation (GHA-FR-17). `github_token_missing` renders a dismissible note anchored to the control with a route to the Global settings GitHub section (GHA-FR-19). A push that GIT-FR-QMYB refuses after the picker is confirmed renders the same kind of note, stating that a push is already running. Every note of the control is announced as a status. Any other failure, and the terminal status of every push, appear in this panel's push/pull output area. No push failure is written to the diagnostic Logs panel by the main window.
29. **GIT-FR-FZMS** A status bar row with the `git_push` destination makes a **selection request** for a branch (per `STB-status-bar.md` STB-FR-RWPD). The panel opens on its **Logs** section (GIT-FR-PZIE) and selects that branch on the terms of GIT-FR-LNEI, local branches first. A request made during loading applies when the listing arrives. An absent branch selects nothing, and a later request replaces the selection.
30. **GIT-FR-WQHD** The left rail shows all five section controls at the narrowest supported panel width. The controls wrap onto further rows rather than clip, truncate to an ellipsis, or scroll horizontally. Each control keeps its full label, its count badge, and its keyboard operation.
31. **GIT-FR-KPTE** The Commits rail names its context: the active worktree's current branch, or **Detached HEAD** with the short commit id. Below it, it lists at most the latest 100 commits reachable from the worktree's `HEAD`, newest first, as `list commit history` returns them.
32. **GIT-FR-MVBZ** Each commit row shows the author name and email, the date, its branch context, and the commit message subject. The branch context of every row is the history's branch named in the rail header (GIT-FR-KPTE), or **Detached HEAD**, so a commit that is not a branch tip still names its branch. A commit that is also the tip of a branch shows that branch's name as a further badge. The whole message is in the row's accessible description.
33. **GIT-FR-DXNC** Selecting a commit marks it selected in words and in its accessible state, and loads its changed files. The large view lists them grouped by folder, each folder named by its project-relative path and each file by its name and change status. Files at the repository root form their own group.
34. **GIT-FR-JRYS** Selecting a file marks it selected and shows that commit's diff for it in the large view, with the commit and the file named above the diff. The selected commit stays marked while a file is selected. Selecting another commit clears the file selection and the diff. A binary file shows a binary marker in place of hunks.
35. **GIT-FR-TFAU** The Commits section renders one of **loading**, **empty history**, **no changed files**, or a typed error, in words, for the commit list, the file list, and the diff. Each failure shows in the region that made the request and leaves the other regions usable. A newer selection supersedes the response of an older one.
36. **GIT-FR-HLGO** The Branches rail opens with a **Local / Remote** switch above the list, and **Local** is selected. The list shows the branches of that kind, with the current branch marked. A selection request (GIT-FR-FZMS) sets the switch to the kind of the row it selects. An empty kind and a failed read show in words.
37. **GIT-FR-ZEKI** A branch row opens its menu by right-click, by the context-menu key, and by Shift+F10. The menu offers **Information** on every row, **Check out** on every row but the current branch's while checkout is offered (GIT-FR-04), and **Delete** on local rows. It follows `LCM-library-context-menu.md` LCM-FR-07, takes focus when it opens, moves by arrow keys, and returns focus to its row.
38. **GIT-FR-NUCX** **Information** opens a modal overlay that reads `get branch information`. It shows the name, type, upstream, current or worktree association, work stream association, tip commit, and the branch's commits newest first with author, email, date, and message. It shows loading and failure states, and closes on Escape, the close control, and the backdrop.
39. **GIT-FR-VCDG** Every overlay of this panel is a modal window whose backdrop covers the main window, and the panel holds at most one overlay at a time (per `NFI-new-file.md` NFI-FR-01). It takes focus when it opens, keeps focus inside itself, and returns focus to the control that opened it when it closes. A running request never blocks the panel.
40. **GIT-FR-QYWP** **Delete** first reads `inspect branch deletion` and then opens a confirmation that names the branch, its linked worktree path when it has one, and the effect: the local branch and that worktree are removed. Nothing is deleted before the author confirms. Cancel, Escape, and the backdrop close it and change nothing.
41. **GIT-FR-GAMV** A branch checked out in the primary worktree or in the active worktree is refused with a typed error, which says to check out another branch or switch worktree first. The inspection's refusal shows beside the row; the deletion's refusal shows in the confirmation. The panel switches nothing for the author. Another inactive linked worktree is deleted with its branch.
42. **GIT-FR-SIJB** When the plan lists uncommitted paths, the confirmation shows a warning that confirming discards them, with their count and the first paths. The remaining paths are counted, not listed. The confirm action names the discard in words. Cancel discards nothing. A backend refusal with `worktree_dirty` after the plan was read shows the same warning with the new paths.
43. **GIT-FR-CTHN** When the branch has an associated remote branch, the confirmation offers a checkbox that deletes it too, unchecked by default. The remote branch is deleted only while the box is checked. A failed remote deletion shows as a failure with its typed cause, never as a deleted remote branch, and the local deletion result still shows.
44. **GIT-FR-XOLE** A branch of a work stream shows that it belongs to a work stream. Its **Delete** confirmation uses the work stream deletion operations alone, with no remote deletion. Unmerged commits show as a warning with their count, and confirming reads **Delete anyway** and passes `force` true. `stream_busy`, `stream_has_runs`, and `stream_active` stay refusals (per `WSS-work-stream-selector.md` WSS-FR-UFZP).
45. **GIT-FR-UDKY** Every typed error of an action shows in the place where the author started it, in words, with the branch it concerns. A running action disables only its own controls. After success, the list reloads and shows a success message that names the removed branch, the removed worktree, and the state of the remote branch.
46. **GIT-FR-OBZW** The PRs rail opens with an **Open / Closed** filter, and **Open** is selected. It lists the current repository's pull requests of that state, each with number, title, author, and state in words, where merged pull requests show as **merged** under **Closed**. The list shows loading, empty, and failure states in words and offers a retry.
47. **GIT-FR-FNQA** Selecting a pull request shows its title, state, branches, and description in the large view, and below them its full timeline in time order: comments, reviews, review comments, commits, and other activity, each with author, time, and body where it has one. The view scrolls inside the panel. A timeline the backend marks as truncated says so.
48. **GIT-FR-LKRX** The PRs section answers a missing GitHub token on the terms of GIT-FR-10. A failed list or detail read after an earlier success keeps the earlier rows, marks them **stale**, and shows the error above them. The error never reads as an empty result. A change of the filter or the selection supersedes the response of an older request.
49. **GIT-FR-EPSV** While any request of this panel runs, every control outside the running action stays usable. A response that arrives after a project change, a worktree change, or a newer request for the same region is discarded and changes nothing the author sees.
50. **GIT-FR-WMVK** The large view of the **Commits** section and of the **Branches** section is two columns. The left column lists the changed files grouped by folder (GIT-FR-DXNC). The right column shows the diff of the selected file with its head (GIT-FR-JRYS). A divider stands between them. Each column scrolls on its own and fills the height of the large view.
51. **GIT-FR-FATV** The files column takes 0.30 of the large view's width by default, held between 0.15 and 0.70. Pointer drag on the divider changes it, and so do the arrow keys, Home, and End while the divider has focus. The divider is a focusable separator with its value in accessible semantics. Both sections share one width, kept in the app preferences.
52. **GIT-FR-LNEI** Activating a branch row by click, Enter, or Space selects it, marked in words and in its accessible state. Selecting checks out nothing, starts nothing, and does not change the active worktree. The selection stays while the Local / Remote switch changes. A listing reload (GIT-FR-11) without the selected branch clears the selection and its view.
53. **GIT-FR-GDMG** Selecting a branch reads `list branch compare files` for it. The large view lists the files the branch changed against its base, and its head names the branch, the base, and the short merge base. Selecting a file reads `get branch compare file diff` and shows it as GIT-FR-JRYS shows a diff. Another branch clears the file and the diff.
54. **GIT-FR-SION** The Branches large view renders one of **no branch selected**, **loading**, **nothing to compare** for a branch that is its own base, **no changed files**, or a typed error, in words, for the file list and the diff. Each failure shows in its own region and leaves the others usable. A newer selection supersedes an older response.
55. **GIT-FR-PZIE** The **Logs** section holds the **Pull** and **Push** controls and the push/pull output area. The area is the record of every transfer the author invokes anywhere in the application. A push from the Changes panel (`CHG-changes.md` CHG-FR-43) or from the top-chrome **Push** (GIT-FR-XXLE) streams into it as one started here does (per `../core/GTC-git.md` GTC-FR-22).
56. **GIT-FR-KLNK** The **Push** of the Logs section is offered only while the current branch holds commits its remote does not, on the terms of `CHG-changes.md` CHG-FR-37, read from `../core/GTC-git.md` GTC-FR-21. A branch level with or behind its remote, and a repository with no remote, leave it unavailable with the reason stated. While any push runs, it is unavailable (GIT-FR-QMYB).

## Non-functional requirements
- The Git surface is project-wide; it does not require a tab focus to be useful.
- No text the panel renders — push and pull output, PR detail, or an error — contains a token secret, because none reaches it (per `../core/GTC-git.md` GTC-FR-11).
- The panel and the top-chrome worktree selector never disagree, about what is checked out or about which branches exist: both read the active worktree's state, both follow the same events, and a change made or a refresh performed through either is reflected in the other without further action.
- The push/pull output area of the Logs section is the record of the transfers the author invoked, wherever they invoked them, including while the panel is closed. A fetch performed from the chrome is not one of them and leaves no transcript there (per `../core/GTC-git.md` GTC-FR-15), so output the author did not ask for never arrives in it.
