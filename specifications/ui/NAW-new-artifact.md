# New Artifact

**Spec code:** `NAW`

## Intent
The tab where a **prompt** is brought into being before the specification it produces exists in the project. It is a workspace over a **draft**: a named single Markdown file held in a committed folder inside the active worktree, which reaches every checkout of the project through Git while staying out of the Project panel and out of project search, edited in the same rich Markdown surface every artifact in the project is edited in, and reviewed through discussions, some pinned to the passages that still need work. A draft is one prompt and nothing else — the author writes it, brings agents into it, and refines it with them until it says what it should — so the tab is one page of writing set on a field, with the prompt's own **History** tucked out of sight until it is wanted and every action a draft affords gathered behind the single control every tab of the application carries in the field's bottom-trailing corner (`ACT-action-control.md`). A draft stays a draft for as long as it takes — an afternoon or a month — and several drafts sit side by side at different stages, because the thinking that produces a good prompt is not something to hurry through an input field. Refinement is what the History rail records: the prompt as it stood before and after each change the author accepted from an agent, each one a version they can read back and be sure of, while the ordinary typing in between is simply the live prompt. A draft nobody has proposed a change to holds one version and it is the live prompt itself — the `Original`, which stays the live prompt until the first change supersedes it. A draft is written, discussed, refined, and then either **graduated** — handed to an agent that writes the specification from it, in a working copy of its own, which the author reviews before anything reaches their files — or **archived**, which retires it from the panel's view without taking anything off disk. There is no readiness to declare before graduating: the author graduates when they judge the prompt finished, and that act is the judgement. Graduating does not end the draft: the run holds the prompt locked while it works, and a run that completes leaves the draft **graduated** and read-only rather than deleting it, so the prompt a specification was written from is still here to read beside it. Out of scope: everything graduation does once it has started — the run, its queue, its iterations, its escalations, and its publication — which are `../core/GRD-graduation.md`'s and are watched in `GRU-graduation-runs.md`; the surfaces the author starts, reviews, and publishes a graduation in, which are `GRU-graduation-runs.md`'s and which this tab only opens; the application-wide History of artifacts and Git revisions, which is `HVW-history-viewer.md`'s bottom panel and detail tabs and shares neither storage nor surface with this rail (NAW-FR-43); the action control itself — its states, its geometry, its composer, and the Discuss action it offers over every item — which `ACT-action-control.md` owns and this tab only contributes Graduate and Archive to; the discussion once it exists — its transcript, its replies, and every message after the first — which the comment margin renders and continues (`CMT-comments.md`) and `../core/AGC-agent-conversations.md` carries; the decision the author makes on a proposed change and the feedback they write with it, which are recorded in the conversation alone and appear nowhere in this rail (NAW-FR-36); the review of a change an agent has proposed — the hunks, the decision controls, and the notification that calls the author back to them, all of which are `DCR-draft-change-review.md`'s, this tab rendering the indication that a decision is owed (NAW-FR-35), and the proposal's own storage being `../core/DCP-draft-change-proposals.md`'s; the work stream a graduation run works in; and creating a plain file or a folder directly in the project, which stay with `NFI-new-file.md` and `NFW-new-folder.md`.

## User stories
- As an author, I want a prompt to sit unfinished for weeks while I think about it, without a half-written file sitting in my repository the whole time.
- As an author, I want the whole width of the tab for the text I am writing, and the version history only when I am looking back.
- As an author, I want editing a draft to be the same act as editing anything else in the project, so nothing about it is learned twice.
- As an author refining a prompt with an agent, I want every version I accepted kept, so I can read what the prompt said two rewrites ago and be sure of what changed.
- As an author, I want my own typing to stay out of that history, so the versions I look back at are the ones I settled on rather than every pause in a sentence.
- As an author, I want a past version to read exactly as the prompt does — the same page, the same rich rendering, the same raw Markdown behind the same toggle — so what I am comparing is the writing rather than two presentations of it.
- As a reviewer, I want to pin an objection to the exact passage it is about and have it stay pinned while the prompt is revised around it.
- As an author, I want several drafts in flight at once, each at its own stage, and to move between them without losing my place in any of them.
- As an author, I want to decide where the prompt lands only once I am sure it is right, rather than committing to a path before I know what I am writing.

- Layout notes: the tab is one **action row** above two columns — the **document column** and the **discussion column**, split as `DDS-draft-discussion.md` lays them out — with an optional **History rail** leading them and the **action control** floating in the tab's own bottom-trailing corner, over the discussion column. The action row is the band an Editor tab carries above its surface (per `EFR-editor-find-replace.md` EFR-FR-ABHF) with the rail's toggle added at its head, so the formatting controls, the mode toggle, the unresolved-discussion count, and the find panels all occupy it on the terms that spec sets. The editing surface is the page an Editor tab sets its text on, inset from the tab and set on a recessed field (per `EDT-editor.md` EDT-FR-63): the page centres in the document column and takes that column's measure where the column is narrower than the page's own, and with the rail shown the rail takes a narrow leading column and the two columns share what is left. The rail is one column of rows: a **live prompt** row pinned at its head, carrying the modified marker of NAW-FR-37 when the live text has moved on and its own `Original` standing while the draft holds no version (NAW-FR-38), and beneath it the versions newest first under a quiet divider, **grouped one row per accepted proposal** naming the agent and how many changes were accepted and expanding to the versions themselves, each row a source label above a timestamp with its standing — `Original`, `Superseded`, `Latest accepted` — set between them. The divider and the column below it stand only where there is a version in them. A row being read carries a leading marker of its own so the selection is legible without relying on fill alone. While a version is showing, a **strip above the page** carries the return to the live prompt at its leading edge, then states that the reading is read-only, and keeps the rendering toggle at its trailing edge where the action row's own sits; the page beneath it is the same page in the same measure on the same field, in the same two renderings, so the shape of the document does not change between reading a version and editing the prompt. The fragment discussions of the prompt take a column **below** the page rather than a margin beside it (per `CMT-comments.md` CMT-FR-64), with the orphaned section and the resolved disclosure at that column's foot; the draft's own conversation is read in the discussion column instead and pins nothing to the document (per `DDS-draft-discussion.md` DDS-FR-KPSZ, DDS-FR-NWRL). The action control keeps its corner throughout. A draft its graduation run holds, and one that has graduated, carry a **run state** in the action row's trailing cluster — a short tag naming the run's state, itself the route to that run — beside the write report and ahead of the rendering toggle, and the tab's chrome carries the same fact beside the label; activating either opens the Runs panel on that run rather than any surface of this tab's own. The action control sits over the field, clear of the page's trailing edge, and neither scrolls with the text nor moves when the rail is shown; expanded it stacks its actions above it as `ACT-action-control.md` lays them out, and it opens no composer of its own here — **Discuss** moves focus to the discussion column (per `ACT-action-control.md` ACT-FR-QWNP). The **publication tag** stands in the chrome row with the archived marker and the run-state tag, is present only while the draft holds a publication record, a standing attempt, or a standing failure, and is read-only: it names the current record's issue and opens that issue outside the application. A standing attempt and a standing failure take the **publication band**, which is the band directly under the chrome row that the graduation-lock note stands in, and that band carries the attempt's affordances and the typed error. The remote picker, the publication chooser, and the recovery choice are centred modals over the tab, mutually exclusive with the other overlays of the main window on the terms of `NFI-new-file.md` NFI-FR-01, each disabled option carrying its reason directly beneath it. The draft's name is the tab's label and is edited in place there. The destination chooser is a modal over the tab carrying the draft's one prompt on one row, its draft-relative name above and its destination below.

## UI contract boundary
- **Owned by the UI**: the action row and its arrangement; the History rail's rendering, its ordering, its labels, its live-prompt row, its selection, and whether it is shown; the read-only presentation of a selected version in both renderings, and the strip that returns to the live prompt and carries that toggle; the per-draft editing state the workspace retains; the two-mode Markdown editing surface, its formatting toolbar, its typographic roles, its page framing, its find panels, and the fidelity with which it round-trips Markdown, all as `EDT-editor.md` defines them (EDT-FR-17, EDT-FR-18, EDT-FR-21, per `EFR-editor-find-replace.md`, EDT-FR-62, EDT-FR-63, EDT-FR-66–EDT-FR-69); the reach of those find panels in this tab — the accelerators that open them, the Edit-menu route that does the same, and the states in which both are inert (NAW-FR-57, NAW-FR-59); the dirty indicator and the undo history; the acceptance of a pasted or dropped image, the position it is inserted at and the selection left after it, the pending and failure states of an insertion, the resolution of a prompt image reference to drawable content, the placeholder an unresolved reference renders as, the image removal action, and the announcements all of these make; the in-place rename of the draft in the tab's chrome; which four actions the control offers over a draft (NAW-FR-28), the control itself and its composer being `ACT-action-control.md`'s; the Graduate action's enablement; the Publish to GitHub action's enablement and every disabled reason it states, the remote picker, its persistence option, its statement of how the current choice was reached, the publication chooser — its root option, its parent rows, its Type and milestone controls, and its loading, empty, unavailable, and failed states (NAW-FR-HNVR through NAW-FR-PSMO) — the recovery choice and its three answers, the publication tag's presence, its five conditions and the order it names them in, its hover text, and its read-only rendering, the publication band that carries a standing attempt and a standing failure, and the fact that an issue opens outside the application (NAW-FR-GKBP, NAW-FR-ZQMX, NAW-FR-RVGT, NAW-FR-MFXO, NAW-FR-EOTB, NAW-FR-CBUJ, NAW-FR-KDMW, NAW-FR-XPUJ, NAW-FR-XRLD, NAW-FR-QTVX); the read-only presentation a graduation lock imposes, the run-state tag in the action row, and the routes it carries to the run; the archived marker and the graduated marker in the tab's chrome; the inconsistent-draft state (NAW-FR-41); and the inline surfacing of every failure the operations below report. The fragment discussions rendered in the margin are owned by `CMT-comments.md`, and the control, its composer, and the discussion they open are owned by `ACT-action-control.md`; neither introduces an operation here.
- **Delegated to backend (abstract)**:
  - `"create draft (name)"`, `"open draft (id)"`, `"load draft file contents"`, `"save draft file contents"`, `"rename draft (id, name)"`, and `"set draft status (id, status)"` — all owned by `../core/DRS-draft-storage.md`. They name the draft record and its one prompt under `.synthesis/drafts/` (committed, scaffolded per `../core/PST-project-storage.md` PST-FR-02 and skipped by the scanner per `../core/ASC-artifact-scanning.md` ASC-FR-09). There is no operation here that adds a file to a draft, removes one, or renames a path within one, a draft being exactly one prompt (per `../core/DRS-draft-storage.md` DRS-FR-11, DRS-FR-13), and none that writes anything into the project tree. A replacement made in the find panels reaches disk through that same `"save draft file contents"` write and introduces no operation of its own (NAW-FR-58).
  - `"store draft image (draft id, media type, filename, data)"`, `"read draft image (draft id, path)"`, `"discard draft image (draft id, path)"`, and `"sweep draft assets (draft id)"` — all owned by `../core/DAS-draft-assets.md`. The first stores a pasted or dropped image under the draft's own `assets/` folder and returns the Markdown destination to insert (DAS-FR-05); the second is what draws an image the prompt references (DAS-FR-08); the third takes back a store whose reference never reached the saved prompt (DAS-FR-09); and the fourth schedules the housekeeping pass this tab triggers when a draft opens and when it closes (DAS-FR-19, NAW-FR-55). None of them adds a file to the draft's `files/`, which still holds the one prompt (per `../core/DRS-draft-storage.md` DRS-FR-11), and none reaches outside the draft.
  - `"get draft graduation (draft id)"` — the run this draft is bound to, its state, and whether that state locks the draft, owned by `../core/GRD-graduation.md` (GRD-FR-LGDV). It is what the run-state tag renders and what decides the tab's read-only presentation (NAW-FR-44). The event `"graduation run changed"` (`../core/GRD-graduation.md` GRD-FR-EFAU) is what keeps it current.
 - `"get graduation run (run id)"` — the whole record of the run a graduated draft came from, owned by `../core/GRD-graduation.md` (GRD-FR-LGDV), read for the run-state tag this tab shows (NAW-FR-BJQX). The run id is the one `"get draft graduation"` already reports, and the record is retained for the project's life however long ago the run finished (per `../core/GRD-graduation.md` GRD-FR-LGDV).
  - `"get draft publication (draft id)"`, `"list publication remotes (draft id)"`, `"load publication metadata (draft id, remote name)"`, `"publish draft to github (draft id, remote name, persist remote, publication choice)"`, `"retry draft publication (draft id)"`, `"resolve draft publication conflict (draft id, choice)"`, `"cancel draft publication conflict (draft id)"`, `"cancel draft publication attempt (draft id)"`, and `"open publication issue (draft id, url)"` — all owned by `../core/GHP-github-publication.md` (GHP-FR-CWTG, GHP-FR-WKDE, GHP-FR-MDLD, GHP-FR-CVYK, GHP-FR-OWLB, GHP-FR-YPGL, GHP-FR-EBSA, GHP-FR-NAXT, GHP-FR-MJTB). The event `"draft publication changed"` is what keeps the publication tag, the publication band, and the action's enablement current. This tab creates, edits, and searches no issue itself, and it never reaches GitHub except through these operations.
 - **Graduate** opens the start dialog of `GSD-graduation-start-dialog.md` (GSD-FR-QMTF) and invokes nothing itself; that dialog is what enqueues the run, and the review a locked draft routes to is `GRU-graduation-runs.md`'s. This tab introduces no graduation operation of its own.
  - `"rename draft (id, name)"` carries the name binding of NAW-FR-25 through to the prompt's own filename, so renaming a draft is one call from this surface rather than two, and the surface never writes half the binding itself.
  - `"list draft history"` and `"load draft history entry"` — owned by `../core/DHS-draft-history.md`. The first is what the rail renders and what tells it whether the live prompt has moved on since the newest version (DHS-FR-10); the second is invoked when a version is actually selected and never before (DHS-FR-11).
  - The `"drafts changed"` event (`../core/DRS-draft-storage.md` DRS-FR-22) is what keeps a draft's name and status current in this tab when they are changed from the Drafts panel, and the `"draft history changed"` event (`../core/DHS-draft-history.md` DHS-FR-22) is what adds a version to the rail without it re-listing.
  - The discussions of a draft, fragment and whole-target alike, are served by `"list discussions for target"` and the rest of the discussion operations owned by `../core/CMS-comments-storage.md`, invoked by `CMT-comments.md` and the shared discussion surface rather than by this surface.
  - Graduation's write reaches the Project panel through the `"project tree changed"` event (`../core/ASC-artifact-scanning.md` ASC-FR-10); this surface does not push nodes into the tree itself.
  - The discussion the column's opening composer starts invokes `"open discussion (target, fragment, body, attachments)"` and `"dispatch agent turn"`, both declared by `ACT-action-control.md` and neither introduced here; what this tab settles is that the target is the draft, which gives the agent the draft's prompt, and that a fragment is allowed only for a selection of the prompt (NAW-FR-15, NAW-FR-32).
  - `"list draft change proposals"` and the event `"draft change proposals changed"` (`../core/DCP-draft-change-proposals.md` DCP-FR-09, DCP-FR-16) are what tell this tab whether its draft carries an undecided proposal (NAW-FR-35). The operations that read a proposal's hunks, write the author's edits to them, and decide them are invoked by `DCR-draft-change-review.md` rather than by this surface — and none of them writes the prompt, so a review under way costs this tab's own write schedule nothing until an acceptance lands.
  - No operation named here reaches an agentic integration (`../core/AIC-agentic-integrations.md`): the one route from this tab to a model is a discussion an agent was addressed in, which reaches a conversational endpoint through `../core/AGC-agent-conversations.md` alone.

## Functional requirements
1. **NAW-FR-01** New Artifact is a **tab** in the main viewport, bound to exactly one draft — not a modal and not a panel. It is therefore no floating overlay of the main window: opening it closes no overlay and no overlay closes it (per `SNV-shell-navigation.md` SNV-FR-56).
2. **NAW-FR-02** A draft is open in at most one New Artifact tab at a time, identified by the draft's own id; requesting one that is already open jumps focus to the existing tab rather than creating a second (per `TAB-tabs.md` TAB-FR-04, TAB-FR-05).
3. **NAW-FR-03** A New Artifact tab is **created** from the **Drafts panel** and from the **Map tab**, and from nowhere else. That panel creates a draft — from its pinned affordance, or from the **New Draft** entry of one of its folders, which files the new draft there — and opens the new draft's tab as the active tab (per `DRP-drafts-panel.md` DRP-FR-06, DRP-FR-26), and it opens an existing draft the same way (per `DRP-drafts-panel.md` DRP-FR-09). The Map tab creates a draft at the root of the drafts tree from the **New draft** action of a map node and opens its tab as the active tab (per `SMD-specification-map-drafts.md` SMD-FR-HVBE). Every creation route runs the same creation: the same `"create draft"`, the same `Untitled` naming, the same single prompt, the same draft template copied into that prompt (NAW-FR-06), differing only in which drafts folder the draft is filed under. The **New Artifact** items of the File menu (`SNV-shell-navigation.md` SNV-FR-24) and of the Project panel's folder context menu (`LCM-library-context-menu.md` LCM-FR-08) share this tab's name and nothing else: each opens the typed-artifact window (`NTA-new-typed-artifact.md`), which creates a typed project file, creates no draft, and opens no tab of this kind. A tab of this kind is also reached without creating anything — from a notification addressing a draft (per `NTF-notifications.md` NTF-FR-17), from a graduation run's route to its source draft (per `GRU-graduation-runs.md` GRU-FR-RZDI), and from an item of the Dashboard's Active workstreams widget (per `DSH-dashboard.md` DSH-FR-12) — each of which opens the draft named rather than making one.
4. **NAW-FR-04** A draft carries a **name**, which is the tab's label, the heading in the tab's own chrome, the filename of its prompt (NAW-FR-06), and the name the Drafts panel lists it under. A newly created draft is named **Untitled**, or the first `Untitled N` free in the worktree (per `../core/DRS-draft-storage.md` DRS-FR-27), and the name is editable in place in the tab's chrome and in the panel's row (per `DRP-drafts-panel.md` DRP-FR-11) — the surfaces are symmetric, so a rename made in either of them is immediately in force in both, and no surface shows a name a rename elsewhere has superseded. A name need not be unique.
   - *Why:* A draft is identified by its id rather than by what it is called.
5. **NAW-FR-05** The tab is two columns — the document and the discussion (per `DDS-draft-discussion.md` DDS-FR-KTVW) — beneath one **action row**, with the draft's **History rail** shown or hidden beside them and the single **action control** in the bottom-trailing corner (per `ACT-action-control.md` ACT-FR-01, ACT-FR-09). No region of this tab is a floating overlay of the window (NAW-FR-01).
6. **NAW-FR-06** A draft holds exactly one Markdown file, named for the draft — a new draft is `Untitled` holding `Untitled.md` — which the tab opens on (per `../core/DRS-draft-storage.md` DRS-FR-06). That file is the draft's **prompt**, and it is the whole of the draft: there is no second file, no folder, and no way to make one from this tab or from anywhere else (per `../core/DRS-draft-storage.md` DRS-FR-11, DRS-FR-13). A new draft's prompt is created holding the project's **draft template** where the project configures one (per `SET-project-settings.md` SET-FR-16) and empty where it does not, the copy being taken once at creation by the creation operation itself (per `../core/DRS-draft-storage.md` DRS-FR-39). The template is starting content and nothing more: it is the author's text from the first keystroke, this tab offers no control that reapplies, refreshes, or reveals it, and a template later changed in Project settings leaves every existing draft exactly as it stands.
7. **NAW-FR-07** The rail is headed **History** and renders the draft's version history: a **live prompt** row at its head, then every version the draft holds, **newest first**, with the metadata `"list draft history"` returns them with — the reverse of the order it returns them in, which is ascending by `seq` (per `../core/DHS-draft-history.md` DHS-FR-05, DHS-FR-10). The `Original` closes the column. Each version's row carries a source label — `Original` for the prompt as it stood before the first accepted change, and the proposing agent for a version an accepted change produced — together with its creation timestamp, whose absolute instant is disclosed on hover. A draft holding no version renders the live-prompt row alone (NAW-FR-38), with neither a column of past versions nor a heading over an empty one. The rail offers no control that creates, deletes, restores, renames, or edits anything: it is a way of reading what the prompt has been.
   - *Why:* Newest first puts the version the live prompt is compared against directly under it, where the author looks first.
8. **NAW-FR-08** The rail is **hidden by default** and shown by a toggle at the head of the action row, which carries the number of versions the draft holds — the live prompt counted among them, so a draft nobody has proposed a change to reads **one** rather than none (NAW-FR-38). The count is therefore legible without showing the rail. The toggle carries **no count at all** while the history has not answered, whether it has not yet or could not be reconciled (NAW-FR-41). The whole rail goes, not merely its rows: a hidden rail occupies none of the tab's width. Whether the rail is shown belongs to the draft and survives the tab closing and reopening within the session.
   - *Why:* A count is a claim about the draft, and one asserted over a history the application could not confirm is the claim NAW-FR-41 forbids.
9. **NAW-FR-09** Selecting a version in the rail renders **that version's prompt, read-only**, in place of the live prompt on the same page in the same measure and in the same two renderings the prompt itself is read in: rich by default, with the raw Markdown behind a toggle in the strip above the page, the same frontmatter region at its head and the same typographic roles on both (per `EDT-editor.md` EDT-FR-17, EDT-FR-18, EDT-FR-62, EDT-FR-63). A version opens in whichever of the two the live prompt is currently in, and the toggle over a reading moves that reading alone — the live prompt's own mode is part of the editor state a return restores untouched (NAW-FR-12). The choice holds while the author stays in the reading, versions selected one after another included, and ends with the return to the live prompt. A version whose text could not be loaded (NAW-FR-41) offers no such toggle, there being no reading for it to govern. It replaces no buffer: the live prompt's text, its dirty state, its editing mode, its undo history, and its find-panel state are all exactly as they were left and are restored the moment the author returns to it (NAW-FR-10, NAW-FR-12). Nothing in the reading accepts a keystroke, and the reading is announced read-only in words and in accessible semantics rather than by colour or by a fill alone. Selecting a version never writes, restores, or reverts anything: the only editable text in this tab is the live prompt.
10. **NAW-FR-10** The way back to the live prompt is always at hand while a version is showing: the rail's live-prompt row stays rendered and returns to it when activated, a return control **leads** the strip above the page, ahead of the words that state what is being read and with room between them, Escape returns from anywhere in the reading, and hiding the rail returns too, so the author cannot be left reading a version with no rail to leave it by. The reading is the outermost of the tab's states, so its Escape yields to every surface standing over it — the review modal, the destination chooser, and whatever the action control has open (NAW-FR-30): backing out of one of those costs the reading nothing, and the Escape after it is the reading's. A return the author asked for lands focus on the rail's live-prompt row rather than dropping it to the tab; an acceptance that returns the tab on its own (NAW-FR-42) moves focus nowhere, the author having asked for nothing. Returning restores the live prompt's editor state whole (NAW-FR-12), including an unsaved edit made before the version was opened.
11. **NAW-FR-11** The editing surface is the same two-mode Markdown surface an Editor tab presents (per `EDT-editor.md` EDT-FR-17): WYSIWYG by default with a raw-Markdown mode behind the same toggle in the same position, the same frontmatter region and its YAML treatment (EDT-FR-18, EDT-FR-20, EDT-FR-21), the same formatting toolbar, the same typographic roles on both surfaces (EDT-FR-62), the same page set on the same recessed field (EDT-FR-63), and the same Find and Find & Replace panels occupying the action row (per `EFR-editor-find-replace.md`). It carries the same Markdown fidelity too (EDT-FR-66–EDT-FR-69): a prompt the author only reads is written back byte-for-byte, and one they edit is serialised without losing a construct or changing what any of its text means. A plain text area with a toolbar over it does not satisfy this requirement.
12. **NAW-FR-12** The draft carries its own dirty state, editing mode, undo/redo history, and find-panel state, on the same terms an artifact's retained edit state carries them (per `EDT-editor.md` EDT-FR-28): held in memory, keyed by the draft, surviving a version being read and returned from, surviving the tab closing and reopening, and discarded when the project closes.
13. **NAW-FR-13** The prompt writes itself. Editing it schedules a write through `"save draft file contents"` a short rest after the last keystroke, so a burst of typing is one write rather than one per character. The surface presents no Save control of its own, only a report of whether the pending edit has landed. The same write additionally happens immediately when the tab closes and when the File menu's Save or Save All is activated with this tab active (per `SNV-shell-navigation.md` SNV-FR-28 and SNV-FR-30). The bytes that reach disk carry the project's line-ending convention, applied by that write (per `../core/DRS-draft-storage.md` DRS-FR-12), and the buffer itself holds no line-ending notion, exactly as an Editor tab's does not (per `EDT-editor.md` EDT-FR-40). A write that fails leaves the buffer dirty and surfaces the failure inline. The report is **laid out in the band above the page** — in the action row's trailing cluster while the prompt is showing, in the reading's strip while a version is, ahead of the rendering toggle in both — rather than placed over that band, whose trailing corner is where the toggle itself sits. It takes the place of the unsaved badge an Editor tab's row carries rather than standing beside it (per `EDT-editor.md` EDT-FR-16). **A write adds no version to the rail**: the author's own typing is the live prompt rather than a version of it (NAW-FR-36).
   - *Why:* The badge and the report say the same thing about the same buffer.
14. **NAW-FR-14** The discussions of prompt fragments render in a column below the page, rendered by `CMT-comments.md` on the arrangement CMT-FR-64 defines (per `DDS-draft-discussion.md` DDS-FR-KPSZ), with the unresolved count in the action row. A selection in the prompt offers **Comment**, which starts a fragment discussion of the draft (per `DDS-draft-discussion.md` DDS-FR-QMBC). Discussions of a draft, fragment and whole-target alike, persist with the draft and are deleted with it (NAW-FR-20).
15. **NAW-FR-15** The draft's **Discuss** action moves focus to the discussion column's composer (per `DDS-draft-discussion.md` DDS-FR-KTVW). A turn dispatched from here has the draft as the discussion's target, which gives the agent the draft's prompt as the material under discussion (per `../core/AGC-agent-conversations.md` AGC-FR-07). Nothing typed there is part of the prompt.
16. **NAW-FR-16** A draft carries a **status** of four positions — **active**, **archived**, **graduated**, and **published**. **Active** and **archived** are set from the action control (NAW-FR-28) and invoked through `"set draft status"`, and moving between them is reversible at any time. **Published** is set by a successful GitHub publication over an `active` draft and by nothing else (per `../core/DRS-draft-storage.md` DRS-FR-VKQO); it is not a read-only position, and a published draft edits, renames, graduates, and archives exactly as an active one does (NAW-FR-GKBP). Archiving retires a draft from the Drafts panel's default view (per `DRP-drafts-panel.md` DRP-FR-07) and takes nothing off disk: the draft keeps its prompt, its history, and its discussions, opens and edits exactly as an active one does, and can be graduated like any other. **Graduated** is neither of those and is set by no control here: a run that publishes a specification sets it (per `../core/GRD-graduation.md` GRD-FR-ARLT), it is read-only while it stands, and the tab renders it rather than offering it. It is **released** where every run that published for the draft has reached `discarded` or `failed` (per `../core/DRS-draft-storage.md` DRS-FR-KQTW), and a released draft reads `active` and behaves in this tab as one: the prompt takes keystrokes again, the rename works, and **Graduate**, **Archive**, and **Restore** are enabled. A fifth position, **github_shadow**, belongs to a draft a claim of a GitHub Task created (per `../core/DRS-draft-storage.md` DRS-FR-WFLY); no control here sets it, and the tab renders it on the terms of NAW-FR-UEWC. There is no readiness position (NAW-FR-17).
17. **NAW-FR-17** **Graduate** carries no precondition on the draft's content, an empty prompt being as graduatable as a full one, and none on `active` against `archived`. It is enabled for every draft but one its own graduation already holds — one with a non-terminal run, and one whose `graduated` status stands — which is the enablement of NAW-FR-44. A draft released by the discard or the failure of every run that published for it is graduatable again, and activating **Graduate** on one starts a **full** run that begins at the specification (per `../core/GSU-graduation-start.md` GSU-FR-IJEE), The tab asks for no separate declaration beforehand and offers no control to make one.
18. **NAW-FR-18** Activating Graduate opens the **start dialog** of `GSD-graduation-start-dialog.md` (GSD-FR-QMTF) and invokes nothing itself. That dialog is where the run is confirmed, where the work stream and the standing-work choice are answered (per `GSD-graduation-start-dialog.md` GSD-FR-VKLD), and where a preflight failure is reported; this tab's part is to offer the action and to render what the run then does to the draft (NAW-FR-44).
19. **NAW-FR-19** The tab chooses **nothing about where the specification goes**. There is no destination field, no destination root, no path validation, and no artifact-type control anywhere in it, and a draft carries no project destination at all (per `../core/DRS-draft-storage.md` DRS-FR-07): the graduation agent selects the specification paths from the captured prompt and the application validates them. Where a draft is filed in the Drafts panel says nothing about where its specification lands, and moving it between drafts folders changes nothing about a graduation.
20. **NAW-FR-20** Graduating **does not end the draft**. A successful start leaves the tab open on the same draft, now locked (NAW-FR-44), and nothing of the draft is written into the project, deleted, or carried into Git by the act of starting. A run that completes leaves the draft `graduated` and read-only with its prompt, the images that prompt embeds, its version history, its discussions, and its conversation all retained (per `../core/DRS-draft-storage.md` DRS-FR-20), so no discussion surface of the draft is closed by it and the tab keeps showing the prompt the specification was written from. A run that is rejected, discarded, or terminally fails unlocks the draft and leaves it exactly as it was; where such a run had already published, the draft's `graduated` status is released with the lock and the draft is editable and graduatable again, while the specification that run published stays in the project (per `../core/DRS-draft-storage.md` DRS-FR-KQTW).
21. **NAW-FR-21** A start that cannot proceed changes nothing about the draft: no run is queued, the prompt is still editable, and the failure is reported in the start dialog rather than here. The tab renders no error of its own for it and does not enter its locked presentation until `"get draft graduation"` reports a run.
22. **NAW-FR-22** The files a graduation writes take whatever type the classification precedence yields for where they landed (per `../core/ASC-artifact-scanning.md` ASC-FR-06), and they reach the Project panel through the watcher's `"project tree changed"` event (ASC-FR-10) like any other write — and only once the author has merged the work stream those files were committed onto into the branch the active worktree stands on (per `../core/WKS-work-streams.md` WKS-FR-GKPX), which is an act of theirs rather than of the run (per `../core/GRD-graduation.md` GRD-FR-ARLT). Nothing here records a type assignment, pushes a node into the tree, or asserts that a file exists.
23. **NAW-FR-23** Closing the tab ends the tab and not the draft: an unsaved prompt is written first (NAW-FR-13), the draft keeps its prompt, its history, its status, its conversation, and its discussions, and it stays listed in the Drafts panel. A draft is removed only by deleting it from the panel (per `DRP-drafts-panel.md` DRP-FR-12); neither archiving nor graduating removes anything (NAW-FR-16, NAW-FR-20).
24. **NAW-FR-24** Drafts belong to the project's active worktree, their folder being inside it. Changing the active worktree closes every New Artifact tab along with every other tab (per `TAB-tabs.md` TAB-FR-14), writing an unsaved prompt first, and the tab strip is repopulated from the incoming worktree's own drafts rather than the outgoing one's.
25. **NAW-FR-25** The draft's name and its prompt's filename are one thing, bound in **one direction**: renaming the draft — from the tab's chrome or from the Drafts panel's row — renames the prompt to match, the filename derived from the name (per `../core/DRS-draft-storage.md` DRS-FR-25). The tab's label, the heading in the tab's chrome, the prompt's name in the action row, and the draft's row in the panel all read the result at once. The prompt is never renamed on its own, this tab offering no affordance to rename a file (NAW-FR-26), so the two can never disagree.
26. **NAW-FR-26** The tab offers **no file affordance at all**: no way to add a file to the draft, no way to remove its prompt, no way to cut a folder in it, no file tree, and no per-file selection. A draft is one prompt for its whole life (NAW-FR-06), so the tab never presents an empty state, never asks which file is being edited, and never leaves the author with a draft that has nothing to type into. A rename of the draft is the only operation that changes anything about the prompt's path (NAW-FR-25), and the versions already in the rail keep the path each was taken at (per `../core/DHS-draft-history.md` DHS-FR-06).
27. **NAW-FR-27** Every action a draft affords is gathered behind the tab's one **action control** and nowhere else. Its two states, its corner, its dismissal, and the geometry that keeps it clear of the page are `ACT-action-control.md`'s (ACT-FR-03, ACT-FR-08, ACT-FR-09); what this spec settles is which entries a draft puts in it (NAW-FR-28). It travels with neither the text nor the rail, so it holds its corner while the surface scrolls, while the rail is shown or hidden, and while a version is being read, and the page's foot is level with an artifact's in an Editor tab on the terms ACT-FR-09 sets (NAW-FR-11, per `EDT-editor.md` EDT-FR-63).
28. **NAW-FR-28** A draft affords all four of the control's actions, so its expanded control offers exactly **Discuss** (NAW-FR-15), **Graduate** (NAW-FR-17), **Publish to GitHub** (NAW-FR-GKBP), and **Archive**, in that order (per `ACT-action-control.md` ACT-FR-04, ACT-FR-05). **Archive** invokes `"set draft status"` with `archived`, writes an unsaved prompt first, and closes the tab. On an already archived draft the last entry reads **Restore** instead, invokes the same operation with `active`, and leaves the tab open on the draft it just returned to view. On a draft its graduation holds, **Archive** and **Restore** are both disabled and **Graduate** is disabled with them (NAW-FR-44); every entry is still rendered.
   - *Why:* The shape of the draft's lifecycle stays legible while a run has it.
30. **NAW-FR-30** The action control's expansion and its composer are surfaces anchored within this tab rather than floating overlays of the window, and they share the tab with the transient surfaces the comment margin owns under the one-at-a-time rule of `ACT-action-control.md` ACT-FR-11 and ACT-FR-12. The graduation surfaces the control's **Graduate** raises are not among them: the start dialog (per `GSD-graduation-start-dialog.md` GSD-FR-QMTF) and the review (per `GRU-graduation-runs.md` GRU-FR-MYFA) are modal overlays of the **window**, governed by the window's own one-at-a-time rule rather than by this tab's, so opening one dismisses whatever other overlay the window held and none of this tab's anchored surfaces. A proposed change is decided in the document column itself (NAW-FR-35), so it is no transient surface of this tab and dismisses none of them. The History rail is not a transient surface at all: it is a region of the tab, it dismisses nothing, and nothing dismisses it.
31. **NAW-FR-31** The composer's mention picker, its **Attach** control, and its pending strip are the ones every composer of this control carries (per `ACT-action-control.md` ACT-FR-15), so an agent is addressed by typing its nickname into the message rather than through a control of the tab's own.
32. **NAW-FR-32** Posting the column's opening composer opens a whole-target discussion against the draft, or a fragment discussion where the author began it from a selection, and dispatches a turn to each agent the message addressed. The discussion is rendered in that column as the shared discussion surface and nowhere else (per `DDS-draft-discussion.md` DDS-FR-NWRL). Ctrl+Enter and Cmd+Enter post it (per `DDS-draft-discussion.md` DDS-FR-LPSC).
33. **NAW-FR-33** The composer is disabled while no comment author identity resolves, and a post the backend refuses renders its typed error inline leaving the body and the strip intact, on the terms of `ACT-action-control.md` ACT-FR-17.
34. **NAW-FR-34** A draft **affords** Discuss whenever it is open, on the terms `ACT-action-control.md` ACT-FR-23 and ACT-FR-QWNP set: the action is taken while the discussion column is hidden. A draft always holds its prompt, so nothing about what the prompt says ever disables it.
35. **NAW-FR-35** A draft may carry a **proposed change** — an ordered set of hunks an agent offers against its prompt (per `../core/DCP-draft-change-proposals.md` DCP-FR-01) — and this tab is where the author decides it, hunk by hunk in the document column (per `DCR-draft-change-review.md` DCR-FR-01). The tab renders an indication in its action row while a proposal is undecided.
36. **NAW-FR-36** The rail records **settled versions of the prompt and nothing else**. One accepted hunk puts one version there, the first putting the prompt it superseded there as `Original` (per `../core/DHS-draft-history.md` DHS-FR-07, DHS-FR-08). The rail renders one proposal's versions as **one row** naming the agent and how many changes were accepted, which expands to them.
   - *Why:* An author is otherwise left to infer from an unchanging list that their typing failed to save.
37. **NAW-FR-37** The rail's **live prompt** row is the live text, and it says how the live text stands against the newest version. Where the two are the same it is rendered plainly. Where they differ — the author having typed since — it carries a marker naming the version it has moved on from: **Modified since latest accepted version**, or **Modified since Original** where the newest version is the `Original` itself. A draft holding no version carries no marker however much the author types, its live prompt being the `Original` and there being nothing it could have moved on from (NAW-FR-38, per `../core/DHS-draft-history.md` DHS-FR-07). The comparison is made on the normalised bytes the save path persisted rather than on the buffer's own text (per `../core/DHS-draft-history.md` DHS-FR-10), so a pending unsaved edit is reported by the tab's dirty indicator and a landed one by this marker. The marker is text and accessible semantics rather than a colour, and it is announced when it changes.
38. **NAW-FR-38** Every version's row states its **standing** as well as its source. The newest version of the newest group is marked **Latest accepted**; every earlier group is marked **Superseded**; the version the first acceptance superseded is labelled **Original** and keeps that label for the draft's whole life. **No row is ever marked as the current draft.** Where the draft holds no version at all the live-prompt row is itself marked **Original**, that being what it is until a change is accepted against it (per `../core/DHS-draft-history.md` DHS-FR-07). Where the live prompt has been modified since the newest version (NAW-FR-37), the rail says that of the live prompt rather than withdrawing the newest version's label.
   - *Why:* The author then reads two facts — which version was last accepted, and that the prompt has moved on from it — instead of one that is false.
39. **NAW-FR-39** Reading a version and reading the live prompt are visibly different states of the same tab, and the difference is never carried by a highlight alone: the selected row is marked in the rail, the strip above the page states that a past version is being read and that it is read-only, and the live-prompt row stays rendered with its own marker throughout.
40. **NAW-FR-40** The rail's list is loaded without loading anything it holds. Opening the tab and showing the rail invoke `"list draft history"` alone, which reads no snapshot (per `../core/DHS-draft-history.md` DHS-FR-10); a version's text is fetched with `"load draft history entry"` when that version is selected and at no other moment, so a draft with a long history costs the tab one list. The rail follows `"draft history changed"` while it is open, so a version an acceptance produced appears without the rail re-listing.
41. **NAW-FR-41** Every failure the history reports is rendered where the author is looking and leaves the live prompt and the editor untouched. A version whose text cannot be loaded — a read that fails, or a snapshot that does not match its recorded checksum (per `../core/DHS-draft-history.md` DHS-FR-11) — renders an inline statement in place of the reading, naming what went wrong and offering a retry and the return to the live prompt; the rail keeps its other rows and every one of them stays selectable. A draft the backend reports as **inconsistent**, its storage holding something other than the one prompt (per `../core/DRS-draft-storage.md` DRS-FR-15), does not open as a draft at all: the tab renders a state naming the inconsistency, offers no editing surface and no rail, presents no file of it as the prompt, and states that the draft is deleted from the Drafts panel, that being the one thing left to do with it (per `DRP-drafts-panel.md` DRP-FR-33). A history that cannot be reconciled (per `../core/DHS-draft-history.md` DHS-FR-21) renders its own recoverable state carrying a retry, and the prompt is neither shown as changed nor shown as unchanged until it resolves. The live-prompt row carries neither the modified marker nor the `Original` standing of NAW-FR-38 there, and the rail's toggle carries no version count (NAW-FR-08). All three return the moment a retry resolves.
   - *Why:* "This is the Original" is the same unconfirmed verdict as "this has moved on from it", so neither may be asserted.
42. **NAW-FR-42** An acceptance that lands while the tab is open puts its version at the **head**, marks the newest group **Latest accepted**, marks the group before it **Superseded**, clears the live prompt's modified marker, and returns to the live prompt if a version was being read. It shows no external-change dialog (per `DCR-draft-change-review.md` DCR-FR-13).
43. **NAW-FR-43** This rail is the **draft's own** and is not the application-wide History. It lists versions of one unpublished prompt held inside that draft's own folder, it opens no History detail tab, it reaches no Git revision, and it is absent from every surface but this tab. The application-wide History — the bottom panel's version list for the active tab's artifact and the detail tabs it opens — behaves exactly as `HVW-history-viewer.md` specifies and is neither reached from here nor changed by anything here; a draft, being outside the project scan (per `../core/ASC-artifact-scanning.md` ASC-FR-09), appears in it at no point before graduation and contributes nothing to it at graduation either (NAW-FR-20).
44. **NAW-FR-44** A draft its graduation holds is **read-only in this tab, and visibly so**. `"get draft graduation"` is read when the tab mounts and followed through `"graduation run changed"` thereafter; while it reports a non-terminal run, or while the draft's `graduated` status stands, the editing surface takes no keystroke, no write is scheduled or performed (NAW-FR-13), the in-place rename in the tab's chrome is inert, and **Graduate**, **Archive**, and **Restore** are disabled in the action control with the reason stated. **Publish to GitHub** is disabled only while a **non-terminal run** holds the draft, and stays enabled on a `graduated` draft that is otherwise eligible (NAW-FR-ZQMX), publication changing the draft's metadata rather than its prompt or its graduation. The refusal is not this tab's alone — the backend refuses the same writes (per `../core/DRS-draft-storage.md` DRS-FR-19, DRS-FR-20) — so a race between an in-flight edit and a run being enqueued ends in a typed refusal surfaced inline rather than in a write that should not have happened. Everything else is untouched: the rail lists the draft's versions and reads them, the margin renders its fragment discussions, **Discuss** is still enabled, and the composer still posts, because reading a locked draft and talking about it are not writing to it. The read-only state is stated in words and accessible semantics rather than by a tone alone, and it is announced when it changes — including when it **lifts**, a run reaching `discarded` or `failed` releasing the draft through the same `"graduation run changed"` the tab already follows, so a draft the author has just discarded a run for becomes writable in front of them rather than on the next reopen.
45. **NAW-FR-UEWC** A GitHub-shadow draft (per `../core/DRS-draft-storage.md` DRS-FR-XDWS) is **read-only in this tab for its whole life**: the editing surface takes no keystroke, no write is scheduled, and the in-place rename is inert. A banner states in words that the draft mirrors a GitHub issue and cannot be edited.
46. **NAW-FR-AXFQ** On a GitHub-shadow draft the action control offers **Graduate** as its only enabled action. **Discuss**, **Publish to GitHub**, **Archive**, and **Restore** are disabled with the reason stated, and **Graduate** follows the enablement of NAW-FR-44.
47. **NAW-FR-BCHZ** A GitHub-shadow draft's tab carries a tag naming its repository and issue number. Activating it invokes `"open publication issue (draft id, url)"` with the draft's issue URL, which opens the OS default browser (per `../core/GHP-github-publication.md` GHP-FR-MJTB).
45. **NAW-FR-BJQX** A draft its graduation holds carries a **run-state tag** in the action row's trailing cluster and beside the tab's label, naming the run's current state in words — queued, working, reviewing, waiting on you, blocked, interrupted, completed, discarded, failed — and, once a run of this draft has committed its work, that the draft is **graduated**. One run is one tag. The tag is itself the route: activating it opens the Runs panel's graduation section on that run (per `GRU-graduation-runs.md` GRU-FR-MYFA), which is the one surface a run is read and acted on from, and is the way back into a decision the author dismissed or that arrived while the tab was closed. The tag renders no progress bar, no pass history, and no change set: what the run is doing in detail is read where the run is.

50. **NAW-FR-50** An image **pasted or dropped into the editing surface is stored and referenced at the cursor**. The tab takes the image data the surface offers it (per `EDT-editor.md` EDT-FR-86), invokes `"store draft image (draft id, media type, filename, data)"`, and inserts the returned destination as ordinary Markdown at the **current cursor position** — `![alt text](../assets/<opaque-id>.png)` — replacing the selection where there is one, exactly as typed text would. The insertion is one edit: one undo step, and one entry in the prompt's write schedule. Afterwards the **selection is predictable**: the caret sits directly after the inserted reference with nothing selected. Both surfaces accept it, the rich one and the raw one, and neither offers a second route: there is no upload button, no file picker, and no gallery.
51. **NAW-FR-51** An insertion shows a **pending state while the image is being stored**, and no reference is inserted before the store answers. The pending state occupies the cursor position, is legible without colour, and does not block typing elsewhere in the prompt. A store that succeeds replaces it with the Markdown reference and **writes the prompt immediately**, without waiting the ordinary rest of NAW-FR-13 out (per `../core/DAS-draft-assets.md` DAS-FR-13). A store that is **refused** inserts **nothing**: the pending state is replaced by the typed error rendered inline where the author is looking, the prompt is byte-for-byte what it was, and no undo step was taken. The refusals divide in what they tell the author. `unsupported_media_type`, `image_too_large`, and `malformed_image` say the **image** was not acceptable and are worded so the author knows to bring a different picture; `draft_locked_by_graduation` says the **draft** takes no write while its run holds it, which is the reason the tab's read-only presentation already states (NAW-FR-44); and `asset_store_failed` says the **store did not happen** and may simply be tried again (per `../core/DAS-draft-assets.md` DAS-FR-03, DAS-FR-04, DAS-FR-27). No refusal of any kind leaves a partial image on disk or a reference in the prompt. A **write that fails after a successful store** invokes `"discard draft image"` for that asset and reports the write's own failure the same way, so a failed insertion leaves neither a reference to a missing image nor an image nothing references. A discard itself refused with `asset_cleanup_failed` changes none of that: the prompt still carries no reference, the author still reads the write's failure and nothing about the cleanup, and the orphaned asset waits for the next housekeeping pass (per `../core/DAS-draft-assets.md` DAS-FR-28, NAW-FR-55).
52. **NAW-FR-52** The tab **resolves the prompt's image references for the editing surface** (per `EDT-editor.md` EDT-FR-85). A destination that resolves to this draft's own asset is fetched through `"read draft image (draft id, path)"` and drawn, and it is fetched when the image is actually shown rather than when the prompt loads. Every reference form the prompt may carry resolves the same way — the inline form and the reference-style form alike, whose label the surface has already resolved to a destination, and whose definition may stand anywhere in the document. A destination that resolves to no draft-owned asset — a missing file, an unresolved reference-style label, an external address, a path leaving the draft — renders as a **non-blocking placeholder** carrying an accessible name that says the image could not be loaded and names the destination, and the Markdown behind it is preserved untouched. A placeholder is never an error dialog and never stops the author writing.
53. **NAW-FR-53** An image the surface has selected carries a **removal action**, which removes **that Markdown reference** and nothing else. It is one ordinary edit of the prompt — one undo step, one write — and it deletes no file: the asset goes only when housekeeping finds that the saved prompt no longer references it (per `../core/DAS-draft-assets.md` DAS-FR-11, DAS-FR-12), so removing one of several references to a shared image leaves every other reference drawing. Deleting the reference by editing the Markdown by hand does exactly the same thing and is supported on identical terms.
54. **NAW-FR-54** Image support is **reachable without a pointer and legible without colour**. Paste and drop both work, and neither the pending state, nor the placeholder, nor the removal action depends on hover, on colour, or on a pointer-only gesture: the removal action is reachable from the keyboard on the selected image, the placeholder carries its accessible name whether or not it is focused, and every state is distinguished by text or shape as well as by any colour it uses. A successful insertion, a refused one, and a removal are each **announced through the tab's existing accessibility feedback**, in the same way its other outcomes are announced, so a screen-reader user learns that the image went in, that it was refused and why, or that the reference is gone.
55. **NAW-FR-55** The tab **triggers the draft's asset housekeeping when the draft opens and when it closes**, invoking `"sweep draft assets (draft id)"` in each case, and the close-triggered call is made before the tab releases the draft (per `../core/DAS-draft-assets.md` DAS-FR-19). The call is a **trigger and not a query**: it answers that a pass was scheduled and carries no account of what any pass found (per `../core/DAS-draft-assets.md` DAS-FR-15), and the tab neither reads that answer, waits on it, renders anything from it, nor asks again for an outcome. Neither call blocks anything: the tab opens and closes at its ordinary speed, the prompt writes itself on its ordinary schedule (NAW-FR-13, NAW-FR-23), and a pass that fails changes nothing about either — it raises no dialog, marks nothing, and is reported through the application's own diagnostics rather than to the author (per `../core/DAS-draft-assets.md` DAS-FR-21).
56. **NAW-FR-56** An image is **not a file of the draft**, and the tab's offer of no file affordance is unchanged (NAW-FR-26). A draft still holds exactly one prompt (NAW-FR-06); the images that prompt embeds sit in the draft's own `assets/` folder beside it (per `../core/DRS-draft-storage.md` DRS-FR-11), and the tab renders no file tree, no asset list, and no per-asset selection. What the author sees is the prompt with its pictures in it, and what they act on is the Markdown.
57. **NAW-FR-57** The two find panels the editing surface carries (NAW-FR-11) are reached in this tab exactly as they are reached in an Editor tab. The platform-standard accelerators — ⌘F and ⌘R on macOS, Ctrl+F and Ctrl+R on Windows and Linux — open the **Find** panel and the **Find & Replace** panel, switch one form for the other, and close them (per `EFR-editor-find-replace.md` EFR-FR-AYNZ, EFR-FR-BJUY), and the Edit menu's **Find** and **Find & Replace** items are enabled while this tab is the active tab on its live prompt and do exactly what those accelerators do (per `SNV-shell-navigation.md` SNV-FR-43). An open panel takes the action row's place above the page and gives it back the moment it closes (NAW-FR-11); the History rail, the comment margin, and the action control all keep their places and the page beneath moves no line. The query is matched against the live prompt as it stands in memory, an unsaved edit included (per `EFR-editor-find-replace.md` EFR-FR-DKQT): the panels read no file of the project and reach neither the universal search bar nor any search the application performs across the project.
58. **NAW-FR-58** A replacement is an ordinary edit of the live prompt. **Replace** and **Replace All** change the in-memory prompt alone, mark the draft dirty, and take their place in the draft's own undo history, a whole **Replace All** being one step however many occurrences it rewrote (per `EFR-editor-find-replace.md` EFR-FR-EYLX, EFR-FR-FYRJ; NAW-FR-12). The changed text reaches disk through the write `"save draft file contents"` schedules a short rest after it, exactly as typed text does (NAW-FR-13), so a sweep over many occurrences costs one write rather than one per occurrence, and the tab adds no save, no operation, and no file of its own for a replacement.
59. **NAW-FR-59** Both panels are inert wherever the prompt is not editable. While a version is being read (NAW-FR-09), and while the draft is read-only because its graduation holds it or because its status is `graduated` (NAW-FR-44), the accelerators open nothing, the Edit menu's two items are disabled (per `SNV-shell-navigation.md` SNV-FR-43), and **Replace** and **Replace All** do not run. A panel open over the live prompt is part of the editing state a return restores, so reading a version and coming back leaves it open with its query, its replacement text, its mode, and its match state as they were (NAW-FR-12). An **archived** draft edits exactly as an active one does (NAW-FR-16), so its panels are live like an active draft's.
60. **NAW-FR-GKBP** **Publish to GitHub** publishes the draft's **current name** as the issue title and its **current prompt** as the issue body (per `../core/GHP-github-publication.md` GHP-FR-XOBH). The issue is a root issue or a sub-issue, with the Type and milestone, that the author confirms in the publication chooser (NAW-FR-HNVR). It writes an unsaved prompt first, changes no byte of it, and leaves the tab open on the same draft. A published `active` draft becomes `published` and stays editable; a `graduated` one stays `graduated`.
61. **NAW-FR-TSQE** The tab reads `"get draft publication (draft id)"` when it mounts and again on every `"draft publication changed"` naming this draft, and renders the action's enablement, its disabled reason, the standing attempt, and the publication tag from that one read.
62. **NAW-FR-ZQMX** The action is **enabled only where the read reports the draft publishable**. Otherwise it renders disabled with the reason stated on hover and in its accessible name, taken from that read rather than composed here.
63. **NAW-FR-VBHT** Each disabled state says which one holds: an **archived** draft must be restored; a graduation lock states the lock; a standing attempt states one is in progress; and a publication refusal states its cause — no configured remote, no GitHub remote, a repository the token cannot read, a repository that accepts no issues, or a token that cannot write issues.
64. **NAW-FR-PNCL** A draft whose prompt holds a **local asset reference** disables the action and states that local media attachments are not supported, **listing every affected path** the read returned (per `../core/GHP-github-publication.md` GHP-FR-AKUM). An image reference that is already an absolute `http` or `https` URL is not listed and disables nothing.

Where the resolution names a remote and the project has exactly one configured remote, the tab opens the **publication chooser** for it without a picker. 66. **NAW-FR-RVGT** The picker lists **every** configured remote. A remote the resolution reports ineligible renders **disabled with its own exact reason** beneath it rather than being omitted, so a non-GitHub remote and a GitHub remote that cannot receive an issue are each explained where they sit. The eligible remote the resolution selected is the picker's initial choice.
67. **NAW-FR-MFXO** The picker states in words whether the current choice is **automatic**, **persisted**, or **selected for this attempt only**, from the `origin` the resolution returns. It carries one **Use this remote for future publications** option: selecting it passes `persist_remote` true, and leaving it clear passes false and applies the choice to this attempt alone.
68. **NAW-FR-JBHV** Confirming the publication chooser invokes `"publish draft to github (draft id, remote name, persist remote, publication choice)"`. Confirming the picker invokes nothing that creates. Dismissing the picker or the chooser invokes nothing, starts no attempt, and persists no remote choice. The action and both confirms are **single-flight**: each disables the instant it is activated, so one gesture is one attempt however impatiently it is repeated.
69. **NAW-FR-LQAF** A draft holding a **standing attempt** renders it in the **publication band** below the tab's chrome row, with the affordances that attempt admits: **Retry** for an `open` attempt, invoking `"retry draft publication (draft id)"`; the recovery choice for an `awaiting_choice` one; and **Abandon** for either, invoking `"cancel draft publication attempt (draft id)"`. **Retry** and the recovery choice reuse the choice the attempt saved and never reopen the publication chooser (NAW-FR-NHAY).
70. **NAW-FR-NQVD** An attempt read back after a relaunch keeps **every affordance it admits** (NAW-FR-LQAF), so a draft holding one is never left permanently unpublishable (per `../core/GHP-github-publication.md` GHP-FR-ZFPI). The tab waits on no call it did not make, so the tag names such an attempt as one that stands rather than as work in progress.
71. **NAW-FR-EOTB** A publication that answers `recovery_required` opens the **recovery choice**, naming the issue and what differs: the title, body, parent, Type, or milestone. **Update existing issue** and **Publish as a new issue** invoke `"resolve draft publication conflict (draft id, choice)"`. Cancelling invokes `"cancel draft publication conflict (draft id)"` and leaves the attempt recoverable.
72. **NAW-FR-HZSW** A publication that fails renders its typed error in the publication band, keeps the draft's status as it was, and leaves the retry affordance of NAW-FR-LQAF in place. No failure closes the tab, discards a keystroke, or marks the prompt dirty.
73. **NAW-FR-CBUJ** The **publication tag** stands in the tab's chrome row, with the archived marker and the run-state tag. It stands only where the draft holds a publication record, a standing attempt, or a standing failure.
    - *Why:* A draft's publication records are read in the Draft Information modal (per `DFI-draft-information.md` DFI-FR-BZQN), so the tab states the current publication rather than listing every one again.

    - *Why:* An attempt in the read is recorded on disk and is not running: the tab knows a publication is in progress only while it waits on a call it made.

The band under the row states the same condition, so the two never disagree about one publication.

Its one control is the tag itself where it names a record: activating it invokes `"open publication issue (draft id, url)"` for the current record and opens that issue in the system's external browser. It opens no in-application page, tab, or overlay.
77. **NAW-FR-QTVX** The tag's hover text and accessible name **name the repository and the issue** the current record holds, and the instant it was published. A tag that names an attempt or a failure states that condition instead, and carries no route out of the application.
78. **NAW-FR-UDPM** A deliberate **re-publication** is the ordinary action taken again on a draft that already has history: it starts a new attempt with a new marker, creates a new issue, and appends a new record without altering any earlier one (per `../core/GHP-github-publication.md` GHP-FR-QLDF). The tag then names the new record.
79. **NAW-FR-HNVR** Once the remote is resolved, the tab opens the **publication chooser**, a modal over the draft titled **Publish to GitHub** that names the repository. It invokes `"load publication metadata (draft id, remote name)"` once, when it opens. It creates, edits, and persists nothing until the author confirms it.
80. **NAW-FR-TCQB** The chooser's first row is the **root option**, **Publish as a root issue**. It is selected when the chooser opens. It stays enabled while the parent list, the Type list, or the milestone list loads, is empty, or fails, so no failed read blocks a root publication.

82. **NAW-FR-WMEP** The parent list, the Type list, and the milestone list each render one of four states: **loading**, **empty**, **unavailable** with the displayable error of the read, or **loaded**. An empty or unavailable list renders a notice in place of its control, and never an empty selector. A notice blocks nothing.

The control renders only for a loaded Type list with at least one Type. For an empty or unavailable list, the notice states that the issue publishes without a Type.
84. **NAW-FR-FGUI** While the root option is selected, a **Milestone** control offers **No milestone** and each open milestone, and sends the chosen milestone number. The control renders only for a loaded milestone list with at least one milestone. For an empty or unavailable list, the notice states that the issue publishes without a milestone.
85. **NAW-FR-JXDN** While a parent row is selected, the chooser shows the configured sub-issue Type as text, or states that the configured Type is unavailable and that the issue publishes without a Type. It states the configured milestone policy: the parent's milestone or none, no milestone, or a **Milestone** control as in NAW-FR-FGUI. It offers no control that changes the sub-issue Type.
86. **NAW-FR-RBTE** **Publish** in the chooser is disabled while the read is outstanding and while a call is in flight. Otherwise it is enabled, whatever state the lists are in. It sends the selected parent's issue number or null, the root Type or null, and the selected milestone number or null.
87. **NAW-FR-VUCK** **Cancel**, the close control, and Escape dismiss the chooser. A dismissal invokes nothing, starts no attempt, and changes no draft, record, or setting, and returns focus to the control that opened it.
88. **NAW-FR-PSMO** The chooser is a modal dialog with an accessible name. Focus moves to the root option when it opens, and Tab stays inside it. The root option and the parent rows form one labelled radio group. Each notice is announced as a status. Every control works by keyboard alone.
89. **NAW-FR-NHAY** A standing attempt's band states the saved choice in words: a root issue or a sub-issue of the saved parent, with the saved Type and milestone. **Retry** and **Recover** invoke their operations without the chooser and keep the saved choice. A typed error, `parent_issue_unavailable` included, renders in the band with **Retry** and **Abandon** in place.
90. **NAW-FR-QEZG** A publication that succeeds updates the publication tag and the draft's publication history as before. Each record in Draft Information states whether the issue was published as a root issue or as a sub-issue, with its parent, Type, and milestone where the record holds them (per `DFI-draft-information.md` DFI-FR-BZQN).
91. **NAW-FR-ZGDM** A recovery answer that fails renders its typed error inside the recovery choice, which stays open, and the publication band keeps the same error with **Retry** and **Abandon** in place.

## Non-functional requirements
- A draft is shared working material: its record, its prompt, and its images are committed to the project's Git repository (per `../core/DRS-draft-storage.md` DRS-FR-04), so a prompt reaches everyone who checks the project out. Its settled versions and its proposals stay in the checkout that made them (per `../core/DRS-draft-storage.md` DRS-FR-WYIN). Nothing under it is surfaced in the Project panel or reachable from project search (per `../core/ASC-artifact-scanning.md` ASC-FR-09 and `../core/SCC-search.md` SCC-FR-03), the Drafts panel being where a draft is read.
- The tab stays usable at the minimum window size the shell supports (≥1280×800): the History rail is bounded so the editing surface keeps a legible measure when it is shown, and hiding it is what a narrow window gives the author to reclaim. The fragment discussions stay legible there too, in the margin while it holds them and in a column below the page once it cannot (per `CMT-comments.md` CMT-FR-64), never over the text they annotate.
- The rail, its rows, the selection of a version, the return to the live prompt, and the retry on a failed read are reachable and operable by keyboard alone, and a version's read-only status is conveyed to assistive technology rather than by presentation alone.
- The collapsed action control is the whole of the tab's lifecycle chrome. A draft being written in shows no button whose action is not being taken, which is what keeps the tab's attention on the page.
- Opening a tab costs one draft read, one prompt read, and one history list, and none of the three reads a snapshot; a draft that has accumulated fifty versions opens in what one with a single version opens in. A graduated draft costs the same: its run is read once for the run-state tag, so the tab is no slower to open for a project with a long graduation history than for one with none.
- No action of this tab contacts a model on its own: none is reached when the tab mounts, when the prompt is edited or written, when the rail is shown or a version read, when the composer is opened or typed into, or when any other entry of the action control is activated. The only call a draft ever costs is a turn for an agent a message actually addressed, so a draft nobody has asked an agent about costs none at all.
- Posting a discussion never waits on an agent: the message is appended and it is rendered as soon as the discussion is opened, and the turns it dispatched land in it afterwards at whatever pace the models answer.
