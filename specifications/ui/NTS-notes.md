# Notes

**Spec code:** `NTS`

## Intent
Vertical-panel surface for the short notes a user attaches to an artifact, a Flow, or the project as a whole. A three-position scope selector decides what the panel shows: the notes on the entity the active tab is bound to, the project-wide notes, or every note in the project grouped by what it is attached to — so the panel serves both "what did I write about this file?" and "what have I written anywhere?" without leaving it. Notes are read, written, retimed, reassigned, and deleted entirely in the panel: each row edits in place and carries an overflow menu, and each row shows when it was last touched. A note is also a thing to think aloud about: a row opens a **discussion** about the note itself — one per note, held with the project's agents in a conversation tab rather than inside the panel — so a gap or a follow-up jotted in a hurry can be worked out where it was written down. A note is written as Markdown and read as rendered text, so the emphasis and the inline code an author reaches for in a hurry read as themselves rather than as punctuation. Out of scope: a rich-text editing surface — the inline editor is a plain field over the Markdown source — note sharing or assignment between users, the delivery of a due reminder — the Dashboard's Reminders widget (`DSH-dashboard.md` DSH-FR-03) is where a due reminder surfaces — a second conversation about any one note, rendering a conversation anywhere inside this panel, the conversation's own surface, which `CMT-comments.md` renders and `TAB-tabs.md` hosts, and discussing the artifact a note is filed against, which is a conversation started from that artifact's own tab (`ACT-action-control.md` ACT-FR-13) rather than from a note about it.

## User stories
- As a user, I want to jot a note while viewing an artifact and have it follow me back when I reopen that artifact.
- As a user, I want to see every note I have written across the project in one list, grouped by what each is attached to, so I can find one I only half remember.
- As a user, I want to fix a note's wording without leaving the panel, so a typo costs one click rather than a dialog.
- As a user, I want to move a note I filed against the wrong artifact onto the right one, so a misfiling is repairable.
- As a user, I want a reminder attached to a note so that I am pinged when it is due.
- As a user, I want to talk an agent through the gap I jotted down, so a two-line TODO becomes something I know what to do about without opening the artifact it is filed against.
- As a user, I want that conversation to stay out of the panel and in a tab of its own, so brainstorming about one note does not turn a list of notes into a chat log.

- Layout notes: the filter field sits directly beneath the panel header and the scope selector beneath it, directly above the list, as every vertical panel arranges the pair (per `SNV-shell-navigation.md` SNV-FR-58); both are pinned above the scrollable list and stay visible while it scrolls, and the create affordance is pinned below it. The selector is the single-line toggle row of `SNV-shell-navigation.md` SNV-FR-62 — three buttons acting as one radio group, each carrying a short tag and disclosing its position's full name on hover — rather than a dropdown, and it clips at its trailing edge rather than wrapping at a narrow panel width (SNV-FR-63). A rendered note body is typeset at the panel's own UI type scale, not at the document scale an Editor page uses — a note is a row in a narrow panel rather than a page of prose, and a body set at document size dwarfs every other row in the panel. Group headers appear only in the all-notes position; the entity and project-wide positions render a flat list with no headers. An entity group header carries its entity's name in the case it has on disk (per `SNV-shell-navigation.md` SNV-FR-57). Each row's `[⋯]` button sits at the row's top-right and is always rendered, not revealed on hover. In inline edit the row's Cancel and Save buttons sit at its bottom-right, Cancel leading. The reminder indicator and the relative timestamp share the row's footer line, timestamp trailing. Errors returned by a backend operation attach inline to the row that triggered them, or below the create affordance for a failed create. A note's discussion is never drawn in the panel: no row grows a card, a placeholder, a composer, or a subview for one, and the panel looks the same whether a note has a conversation or not (NTS-FR-29).

## UI contract boundary
- **Owned by the UI**: the three-position scope selector, its rendering as a toggle row, and which position is active, the entity/project/all list rendering, grouping by entity in the all-notes position and the ordering of groups and rows within them, the filter field and the client-side matching it performs, relative-timestamp formatting and the hover disclosure of absolute timestamps, the inline editor and its Save/Cancel affordances, the per-row `[⋯]` overflow menu and its entries, the delete confirmation step, the Move picker and its type-to-filter list, the reminder picker UI, the rendering of a note's Markdown body to rich text, the rendering distinction between notes attached to the current version and notes attached to a historical version, and the rendering of notes whose entity no longer resolves together with the marker that names that state.
- **Delegated to backend (abstract)**: `"list notes for entity"`, `"list project-wide notes"`, `"list all notes"`, `"create note (scope, body, optional reminder)"`, `"update note"`, `"delete note"` — owned by `../core/NTC-notes-storage.md`, which also owns the note record, its `created_at`/`updated_at` timestamps, the marking of notes whose entity no longer resolves, whether a note carries a discussion, and the transaction that removes a note together with the conversation it carries. `"get or create note discussion (note, body, attachments)"` — owned by `../core/CMS-comments-storage.md` — is what the opening composer posts, and it is the only operation this panel introduces for a discussion; every later message, lock, resolution, attachment read, and agent turn in that conversation is invoked from the shared discussion surface in the conversation tab rather than from here. `"load notes panel state"` and `"save notes panel state"` persist the selector position and the filter text and are owned by `../core/PSS-project-settings-storage.md` (PSS-FR-19). The Move picker populates its list from `"load project tree (filesystem nodes tagged by artifact type)"` (owned by `../core/PST-project-storage.md` PST-FR-07) and introduces no command of its own; a completed move is an `"update note"` carrying the new scope. The panel rescopes on the `"active tab changed"` event (owned by `../core/PST-project-storage.md`).

## Functional requirements
1. **NTS-FR-01** Notes is a vertical-panel surface.
2. **NTS-FR-02** In the panel's **entity** scope position, the panel shows the notes scoped to the entity the active tab is bound to (artifact, Flow, etc.), served by `"list notes for entity"`.
3. **NTS-FR-03** In the panel's **project-wide** scope position, the panel shows only the notes scoped to the project itself, served by `"list project-wide notes"`. This is also the position the panel occupies whenever no entity-scoped tab is active, because the entity position has nothing to bind to and is unavailable.
4. **NTS-FR-04** The user can create a note from the panel. A new note attaches to the entity the active tab is bound to, or to the project when no tab is entity-bound — in every scope position, including the all-notes position, whose grouping is a view rather than a writable scope.
5. **NTS-FR-05** The user can edit and delete existing notes from the panel, without opening any other surface.
6. **NTS-FR-06** A note may carry an optional scheduled reminder, settable at create time and from the row's overflow menu (NTS-FR-20). A note carrying one renders a reminder indicator in its footer.
7. **NTS-FR-07** Notes attached to a historical revision of an entity render with a visual distinction from notes attached to the current version. The history-attachment workflow itself is covered by `HVW-history-viewer.md`.
8. **NTS-FR-08** When the active tab changes, the panel reacts immediately without manual refresh: in the entity position it rebinds to the new tab's entity, or falls back to the project-wide position when the new tab is not entity-bound; in the project-wide and all-notes positions the rendered list is unaffected.
9. **NTS-FR-09** The scope selector is the toggle row of `SNV-shell-navigation.md` SNV-FR-62 and offers exactly three positions — the active tab's entity, project-wide, and all notes, in that order — and the chosen position is sticky: it survives tab changes (NTS-FR-08), a panel switch, and an application relaunch, persisted through `"save notes panel state"`. Returning to the entity position binds to whatever tab is active at that moment. When the persisted position is the entity position and no entity-scoped tab is active on mount, the panel renders the project-wide position (NTS-FR-03) without rewriting the persisted value.
10. **NTS-FR-10** In the **all notes** position the panel shows every note in the project, entity-scoped and project-wide alike, served by `"list all notes"`, grouped by what each note is attached to: one group per entity that has notes, a **Project** group for project-wide notes, and an **Unresolved** group for notes whose entity no longer resolves (NTS-FR-23). Groups are ordered by their most-recently-edited note, most-recent first.
11. **NTS-FR-11** Each group header in the all-notes position names its entity, and clicking an entity group's header reveals that artifact or Flow in the Project panel and opens it in its natural surface, using the same routing the Project panel click-through uses. The **Project** and **Unresolved** headers name no entity and are not click-throughs.
12. **NTS-FR-12** The panel carries a text filter field, available in every scope position, that narrows the rendered list to the notes whose body matches the entered text; in the all-notes position a note also matches when its entity's name matches. Matching is performed client-side over the notes already loaded, case-insensitively, and requires no backend call. A group left with no matching note is hidden.
13. **NTS-FR-13** The filter text is sticky on the same terms as the selector position (NTS-FR-09): it survives tab changes, a panel switch, and an application relaunch, persisted through `"save notes panel state"`.
14. **NTS-FR-14** Each note row shows a compact relative last-edited timestamp derived from the note's `updated_at` (per `../core/NTC-notes-storage.md` NTC-FR-03). Hovering it discloses the note's absolute creation and last-edit timestamps.
15. **NTS-FR-15** Notes are ordered most-recently-edited first — across the whole list in the entity and project-wide positions, and within each group in the all-notes position.
16. **NTS-FR-16** Choosing **Edit** turns the note's row into an editable multi-line text field in place, seeded with the note's current body, with **Save** and **Cancel** buttons in the row's bottom-right corner. **Save** invokes `"update note"` with the edited body and returns the row to its rendered form. **Cancel**, and the Escape key, close the editor leaving the stored note untouched.
17. **NTS-FR-17** Clicking outside an open editor neither saves nor discards it; the editor stays open until Save or Cancel resolves it. At most one row is in inline edit at a time, so requesting Edit on a second row while an editor is open does nothing until the open one is resolved. An editor whose note leaves the rendered list — because the selector moved, the filter excluded it, or its scope changed — closes and discards its unsaved content.
18. **NTS-FR-18** Every note row carries a `[⋯]` overflow button that opens a dropdown menu anchored to it. The button is always rendered on every row, including rows in the Unresolved group.
19. **NTS-FR-19** The overflow menu offers exactly five entries, in this order: **Discuss** (NTS-FR-26), **Edit** (NTS-FR-16), **Move…** (NTS-FR-22), the reminder entry (NTS-FR-20), and **Delete** (NTS-FR-21).
20. **NTS-FR-20** The reminder entry reads **Set Reminder…** on a note carrying no reminder and opens the reminder picker; it reads **Clear Reminder** on a note carrying one and invokes `"update note"` to remove it without opening the picker. Committing the picker invokes `"update note"` with the chosen instant.
21. **NTS-FR-21** **Delete** opens a confirmation step naming the note; confirming invokes `"delete note"` and removes the row, and dismissing it leaves the note untouched and invokes nothing. A note carrying a discussion is deleted with it (NTS-FR-30).
22. **NTS-FR-22** **Move…** opens a picker listing the project's artifacts, Flows included — populated from `"load project tree (filesystem nodes tagged by artifact type)"` — with a type-to-filter field and a **Project level** entry at its head. Choosing an entry invokes `"update note"` with the note's new scope and closes the picker; the note then renders under its new group in the all-notes position, or leaves the list in the entity and project-wide positions when the new scope no longer matches.
23. **NTS-FR-23** A note whose entity no longer resolves (per `../core/NTC-notes-storage.md` NTC-FR-10) renders in the **Unresolved** group showing its last-known project-relative path in place of an entity name, and its row carries an **Unresolved** marker — the same word and the same treatment the Comments panel gives a thread whose artifact has gone (per `CMP-comments-panel.md` CMP-FR-12), so one state reads one way wherever the window shows it. Such a note is fully editable and deletable, and **Move…** (NTS-FR-22) is how it is reattached. It never disappears from the panel on its own.
24. **NTS-FR-24** At most one of the panel's floating overlays — the `[⋯]` dropdown, the Move picker, the reminder picker, and the delete confirmation — is open at a time; opening one dismisses any other, and each dismisses on Escape or an outside click without invoking any operation. A conversation tab is not among them, being a tab of the main viewport rather than a surface of this panel: opening one of the panel's overlays closes no tab, and no tab closes one of them.
25. **NTS-FR-25** A note's body is Markdown, and a row renders it as rich text — emphasis, inline code, links, and short lists read as themselves rather than as their source characters — on the same terms a comment's body renders (per `CMT-comments.md` CMT-FR-09). The inline editor of NTS-FR-16 edits that Markdown source directly, so what the author types is exactly what is stored (per `../core/NTC-notes-storage.md` NTC-FR-03) and nothing rewrites it on the way in or out.
26. **NTS-FR-26** **Discuss** opens the note's one discussion — a conversation about the **note itself** rather than about the entity it is filed against — and is offered on every note the panel renders, in all three scope positions, on notes in the Unresolved group included (NTS-FR-23): a note whose entity has gone is still a note with something written in it, and the conversation is about what is written. It is unavailable only where the row names no note the panel can identify, or where the backend refuses the request; a refusal renders as its typed error inline on that row (per the layout notes) and creates no conversation, so a retry after a failure never leaves two. The action calls the single reveal route for discussions with the note's identity, which opens or focuses the note's **conversation tab** (per `TAB-tabs.md` TAB-FR-QXMV), so a conversation already open in a tab is focused rather than opened again and one that is closed gets exactly one tab.
27. **NTS-FR-27** A note that has **no** discussion opens a conversation tab whose body is the **opening composer** of the shared discussion surface (per `ACT-action-control.md` ACT-FR-RWHV). Opening it creates nothing — no discussion, no association, no opening comment, and no agent turn — because starting a conversation about a note requires the author to say what they want to discuss, and an empty conversation with an agent in it is a question nobody asked. The composer is the one every discussion carries: it addresses the project's agents through the mention picker on the terms every conversation composer does (per `CTA-comment-agent-turns.md` CTA-FR-VQFJ, `AGT-agents.md` AGT-FR-25), carries the same Attach affordance and pending strip (per `CMT-comments.md` CMT-FR-45, CMT-FR-46), and is disabled while no comment author identity resolves, stating the same reason and offering the same route (per `CMT-comments.md` CMT-FR-24). With its message field focused, **Ctrl+Enter** on Windows and Linux and **Cmd+Enter** on macOS posts the composer, on exactly the terms `ACT-action-control.md` ACT-FR-28 sets for every opening composer. Posting a non-empty body invokes `"get or create note discussion (note, body, attachments)"` once, which creates the discussion and that one human-authored opening comment together, and then dispatches an agent turn per distinct agent the message's tags resolve to, exactly as a discussion opened from a tab does (per `ACT-action-control.md` ACT-FR-16). On success the same tab shows the created discussion in the shared surface. A refused post renders its typed error inline and **retains** the body and every pending attachment so the message is corrected and sent without being retyped (per `CMT-comments.md` CMT-FR-34, CMT-FR-51), and nothing was created by the attempt. Closing the tab before posting persists nothing in the backend; the typed text and the pending attachments are kept in the session for the note, so choosing **Discuss** again restores them.
28. **NTS-FR-28** A note that **has** a discussion opens that same conversation in its conversation tab, holding every message in it, and shows no opening composer: `"get or create note discussion"` is not invoked, nothing is appended, and no agent turn is dispatched by the opening. Which notes have one the panel knows from the discussion id its list items already carry (per `../core/NTC-notes-storage.md`), so choosing **Discuss** costs no call to find out. A note has at most one conversation and the association survives an application restart, an edit, a move, and a reattachment, so **Discuss** on a given row always reaches the same conversation.
29. **NTS-FR-29** The panel is **list-only** for discussions: it renders **no** part of a note discussion — no card, no placeholder, no inline composer, no subview, and no conversation in any row, group, or scope position — and no row indicates its conversation's unread or pending state. A note conversation is read in its conversation tab and nowhere else. Closing that tab puts the surface away and leaves the conversation persisted for the next **Discuss**.
30. **NTS-FR-30** Deleting a note deletes its discussion with it. Confirming **Delete** (NTS-FR-21) invokes `"delete note"`, which removes the note, its discussion, and that discussion's whole persisted history in one backend-owned transaction (per `../core/NTC-notes-storage.md` NTC-FR-21); on success the row goes and the conversation tab of that discussion closes. On a typed failure the panel renders that error inline on the row, keeps the row, and reports nothing as deleted — so the author is never told a note is gone while its conversation, or the note itself, is still there. A note carrying no discussion deletes exactly as it does otherwise.
31. **NTS-FR-31** Everything else about a note is untouched by its having a conversation. Creating, editing, moving, filtering, grouping, ordering, reminders, the unresolved marking and its reattachment, the scope selector and its persistence, and the timestamps a row shows all behave identically whether a note carries a discussion or not, and no operation of a discussion writes to a note or changes its `updated_at`.

## Non-functional requirements
- Note bodies are short-form Markdown: authored as plain source in the inline editor and read as rendered text, so no rich-text editing surface is required.
- Filtering (NTS-FR-12) runs against the already-loaded note set and never issues a backend call, so typing in the filter field never waits on the backend.
- The panel is a narrow vertical surface: a note row truncates a long body to a few lines in its rendered form and reveals the whole body in the inline editor rather than widening the panel.
- Relative timestamps (NTS-FR-14) refresh as time passes without requiring the user to reopen the panel.
- Knowing which notes carry a conversation costs the panel nothing beyond the list it already loads (NTS-FR-28), so a project with hundreds of notes opens the panel in one call whether or not any of them has been discussed.
- The panel stays a list at every width: a note conversation is a tab rather than a column inside a narrow panel, so nothing about discussing a note takes room from reading the notes.
