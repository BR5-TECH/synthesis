# OpenSpec change workspace

**Spec code:** `OCW`

## Intent
The change workspace is the tab where an author reads one OpenSpec change as one document: its proposal, its deltas as requirement diffs against the live specs, its design, and its tasks. A propose run writes the change on a stream (per `../core/GRD-graduation.md` GRD-FR-LKGC), and the author must read what it proposes before anything is built from it. A change is several files, and a delta is meaningful only beside the requirement it replaces, so a plain file view does not show what the change does. The tab shows a change in its **location**: the working copy of a stream, from the run or the draft that made it, or the active worktree, from the Library. On a stream, the tab is also where the author discusses the change with agents, in the discussion column every draft discussion has, and decides the edits they propose in the text of each file. On a stream, the tab is also where the author starts the runs of a change: **Apply**, which implements its tasks, and **Rework…**, which revises it on the author's instruction (per `../core/OCR-openspec-change-runs.md`), and where the author confirms or declines a run that an agent requests (per `../core/CAR-change-action-requests.md`). An apply run that asks to change the plan opens a plan thread there, where the author answers its questions and decides its edits (per `../core/OPU-openspec-plan-updates.md`). A run strip shows the run of the change while it works. Out of scope: archiving a change, which a stream merge does (per `../core/OAR-openspec-archive.md`); any view of an archived change beyond the statement that it is archived; and discussing a change in a worktree that is not a stream.

## Functional requirements
1. **OCW-FR-DMGL** The tab opens for one change in one location. A stream location comes from a completed propose, apply, or rework run (per `GRU-graduation-runs.md` GRU-FR-LTWN), a draft row (per `DRP-drafts-panel.md` DRP-FR-YGOU), or a draft tab (per `NAW-new-artifact.md` NAW-FR-XDDQ). The active worktree location comes from the Library (per `LIB-library.md` LIB-FR-OKIZ). A map change chip gives either (per `SMI-specification-map-inspector.md` SMI-FR-UKIV).
2. **OCW-FR-IAPK** An open that names a file of the change selects the artifact that holds that file. An open that names no file selects the first artifact of the schema.
3. **OCW-FR-LABL** The tab invokes `"read openspec change"` with its location and change name when it opens, each time it becomes the active tab again, and on its **Refresh** action. A loading state stands in the reading pane until the first answer arrives.
4. **OCW-FR-XUJN** The tab's label is the change name. A stream location shows the stream name beside it.
5. **OCW-FR-LSFO** The header states the change name, the schema, the location, and the task progress as `<completed> of <total> tasks`. It shows one state chip for each artifact, in the build order of the schema: done, ready, blocked, or skipped.
6. **OCW-FR-QIZW** The artifact list on the leading side names each artifact of the schema in that order, with its state. Selecting one shows it in the reading pane. An artifact with no file states that the change holds no file for it.
7. **OCW-FR-NOTT** An artifact other than `specs` renders each of its files as a read-only Markdown document on the terms of `DTV-document-text-viewer.md` DTV-FR-SSQI: no script, no raw HTML, no remote resource, and inert links.
8. **OCW-FR-OUXA** The `specs` artifact renders the deltas grouped by capability, in the order the read gives them. Each group is headed by the capability id and states whether the live specs hold that capability.
9. **OCW-FR-NEQF** An `ADDED` delta renders the requirement name, its text, and its scenarios, marked as added.
10. **OCW-FR-WIKH** A `MODIFIED` delta renders the live requirement and the changed requirement side by side, the live one leading, each with its text and its scenarios whole.
11. **OCW-FR-YHIX** A `MODIFIED` delta with no live requirement renders the changed requirement alone, with a statement that the live specs hold no requirement of that name.
12. **OCW-FR-FPFE** A `REMOVED` delta renders the live requirement struck through, or its name alone with a statement where the live specs hold no requirement of that name.
13. **OCW-FR-IGTS** A `RENAMED` delta renders the old name and the new name, and the live requirement under its old name where the live specs hold one.
14. **OCW-FR-WXFK** A file that the read marks unreadable renders a statement that the file is not text, in place of its content.
15. **OCW-FR-UOKM** The tab changes a file only by a decision on a hunk of a proposal (OCW-FR-COLR). Where the location is the active worktree, each file offers **Open in editor**, which opens that file in an Editor tab (per `EDT-editor.md`). Where the location is a stream, no file offers it.
16. **OCW-FR-RFGG** A first read that fails renders its failure in the reading pane. `change_not_found` states that the change is not in that location any more. Every OpenSpec failure renders the failure notice of `OFN-openspec-failure-notices.md`, with its actions and its Details. Every other code but `change_archived` (OCW-FR-AKVG) states that the read failed, with **Retry**.
17. **OCW-FR-PFUQ** A read that fails with a code other than `change_archived` after a read that succeeded keeps the content of that read and states the failure above it: an OpenSpec failure in the failure notice of `OFN-openspec-failure-notices.md`, and every other code with **Retry**.
17. **OCW-FR-AKVG** A read that fails with `change_archived`, first or later, replaces the content of the tab with a statement that the change is archived, which names its archive folder `archived_as` (per `../core/OSM-openspec-mode.md` OSM-FR-KWWM, OSM-FR-GMKV). The statement offers no **Retry**.
17. **OCW-FR-GVZT** While the tab states that its change is archived, it shows no discussion column, no Apply, no Rework…, no History, no Information, and no run strip. It records no working interval (OCW-FR-MIEY), and it reads no proposal, no request, and no version.
18. **OCW-FR-HPHM** Each read emits through `../core/LGC-logging.md`'s frontend helpers under the `frontend` domain: an `INFO` record with the location kind and the artifact and delta counts, or a `WARN` record with the location kind and the error code. No record holds the text of a file.
19. **OCW-FR-PLDG** An open in the active worktree, where the active worktree is the working copy of a stream of the project (per `WTC-worktree-context.md` WTC-FR-RDVK), is an open of that stream's location.
20. **OCW-FR-TRLG** A tab whose location is a stream carries the discussion column of `DDS-draft-discussion.md` beside the reading pane. The column holds the whole-change discussion and the fragment discussions of the change (per `../core/CMS-comments-storage.md` CMS-FR-UEXD).
21. **OCW-FR-ZZHS** A tab whose location is a worktree that is not a stream's working copy carries no discussion column, and states that a change is discussed on its work stream.
22. **OCW-FR-ABUR** Each file of an artifact offers **Rich** and **Source**. Rich is the rendering of OCW-FR-NOTT and OCW-FR-OUXA, and Source is the file's text as stored. The choice belongs to the tab.
23. **OCW-FR-JBFZ** In Source, a selection in a file of a stream location opens a fragment discussion of that file, on the terms of `CMT-comments.md` CMT-FR-06, with the change-relative path of the file.
24. **OCW-FR-COLR** While the change holds a pending proposal (per `../core/CEP-change-edit-proposals.md`), each hunk is decorated in Source of its file with the chips of `PCR-prompt-change-review.md`: accept, reject, edit, and discuss. A file with a hunk opens in Source.
25. **OCW-FR-RRXG** The artifact list marks each artifact that holds an undecided hunk with the count of those hunks. A hunk on a new file shows that file under its artifact, marked as new, before it is accepted.
26. **OCW-FR-DTRX** A decision invokes the command of `../core/CEP-change-edit-proposals.md` for it, and the tab then reads the change again. A refusal `stream_busy` is stated at the hunk, with the name of the run that holds the stream.
27. **OCW-FR-TAZJ** The tab follows `"change edit proposals changed"` for its stream and change, and reads the proposals again on it.
28. **OCW-FR-MLXJ** A decision whose proposal closes with a commit raises an Info toast that names the change. A close whose commit fails raises an Error toast with **Retry**, which invokes `"complete change edit decision"`.
29. **OCW-FR-EJGH** While the change holds a pending edit proposal, a review bar above the reading pane states the count of undecided hunks across the change and offers **Reject all**. Reject all invokes `"decline change edit proposal"` after a confirmation that names the count, and then the tab reads the change and the proposals again.
30. **OCW-FR-RKCC** A tab whose location is a stream offers **History**. History shows the versions of the change from `"list change versions"` (per `../core/CVH-change-version-history.md`), newest first, each with the first line of its commit message, its author, its time, and the count of files it changed. A list that is truncated states it.
31. **OCW-FR-DRQD** Selecting a version shows the change as that version holds it, from `"read change version"`, in the reading pane with its own artifact list, read-only, with Rich and Source. A banner names the version and offers **Back to current**. No decision, no fragment discussion, and no edit is offered while a version is shown.
32. **OCW-FR-ABAR** A shown version offers **Compare with current**, which shows each file of the version beside the same file of the current change as a line diff, added, removed, and changed files each marked. A file that is not text in either is named with no diff.
33. **OCW-FR-QCSL** The History list reads the versions again when it opens, on **Refresh**, and on `"change edit proposals changed"` and `"new change proposals changed"` with the cause `committed` or `decided` for its stream and change.
34. **OCW-FR-ZZCS** A tab whose location is a stream offers **Information**, which opens a centred modal of the change's statistics from `"read change statistics"` (per `../core/CST-change-statistics.md`): Working time, AI interactions, Versions, Accepted proposals, Rejected proposals, Conversation tokens, Run time, and Run tokens. It renders unavailable and incomplete statistics, its footer, its dismissal, and its re-read on `"change statistics changed"` on the terms of `DFI-draft-information.md` DFI-FR-HSYB, DFI-FR-CVAX, DFI-FR-NTPG, and DFI-FR-EBIL.
35. **OCW-FR-MIEY** A working-activity observer reports settled foreground intervals of a change through `"record change working interval"`, on the terms `DFI-draft-information.md` DFI-FR-XKRM, DFI-FR-UKFR, and DFI-FR-JDWS give the editing observer of a draft. The surfaces of a change are its tab and its discussion column, and a conversation counts as related where its origin kind is `change_comment` or `change_discussion` for that change.
36. **OCW-FR-BGDN** A comment that carries a `new_change_proposal` attachment renders a card with the proposed name, the position and the total, the paths of its files, and its state. While the proposal is pending, the card offers **Accept**, **Reject**, and **Discuss**, which invoke `"accept new change proposal"`, `"reject new change proposal"`, and open a discussion with a `new_change_subject` attachment. **View files** shows the files from `"load new change proposal files"`, read-only.
37. **OCW-FR-ANKT** While the split holds an accepted proposal and none is pending, and the split is not confirmed, the tab offers **Confirm split**, which invokes `"confirm change split"` after a confirmation that names the accepted changes.
38. **OCW-FR-TZRT** A change whose split is confirmed shows a marker in its header that names the changes it was split into. Each name opens that change's tab on the same stream.
39. **OCW-FR-IJAI** An accepted proposal's card names the created change and opens its tab. An acceptance whose commit fails raises an Error toast with **Retry**, which invokes `"complete new change decision"`. A refusal `stream_busy` is stated on the card with the name of the run that holds the stream.
40. **OCW-FR-GCME** The tab stays usable at a window width of 800 px with a side panel open. Where the reading pane would be narrower than 360 px, the artifact list collapses to a menu above the reading pane, and the discussion column gives up width before the reading pane does, down to its own minimum of 280 px. While History is open, the document column keeps room for the History rail beside the reading pane before the discussion column gets more than its minimum. Where the reading pane beside the rail would be narrower than 360 px, the rail moves above the reading pane at the full width of the column, with a height of at most 40 % of the column, and its versions scroll. A file path and its Source text never wrap one letter to a line.
41. **OCW-FR-FMDZ** In Rich, an image whose Markdown destination is a relative path inside the change folder renders the image that `"read change image"` returns for it (per `../core/OSM-openspec-mode.md` OSM-FR-BLEY). A read that refuses, and any other destination, render the alt text and the destination as a link that the application does not fetch.

42. **OCW-FR-QSZP** An open that names a thread of the change selects that thread in the discussion column. An open from a rework run names its request thread (per `GRU-graduation-runs.md` GRU-FR-IKEQ), an open from a run at rest on `plan_update` or `plan_findings` names its plan thread (per GRU-FR-TCSM, GRU-FR-TVDF), and an open from a merge notice names its thread (per `OFN-openspec-failure-notices.md` OFN-FR-RLSO).
43. **OCW-FR-DTJD** A tab whose location is a stream offers **Apply** in its header. Apply invokes `"start change apply"` with the stream and the change name (per `../core/OCR-openspec-change-runs.md` OCR-FR-IDFC). It asks nothing before it, and on success the run strip shows the new run (OCW-FR-JHAB).
44. **OCW-FR-NNRY** Apply is unavailable, with a sentence that says why, while a start is in flight, while a run of the change on this stream is not terminal, and while the last `"read apply progress"` states `blocked`, the sentence then naming the missing artifacts, and while the change holds a pending edit proposal, or a closed one whose commit is still owed (per `../core/OCR-openspec-change-runs.md` OCR-FR-LNKQ). A tab whose location is not a stream offers no Apply.
45. **OCW-FR-EKYF** A refused start is stated beside the action that started it. `openspec_run_active` names the run with a route to it (OCW-FR-LYIX). An OpenSpec failure, `change_not_ready` and `cli_unavailable` included, renders the failure notice of `OFN-openspec-failure-notices.md` and states that no run started. An image preflight refusal states what the author configures. Every other code states the code and that no run started.
46. **OCW-FR-LWFQ** A tab whose location is a stream offers **Rework…** in its header. It opens a modal dialog that names the change and the stream and holds one multi-line **instruction** field, **Start rework**, and **Cancel**. Start rework is unavailable while the instruction is blank once trimmed.
47. **OCW-FR-FEOA** Start rework invokes `"start change rework"` with the stream, the change name, and the instruction. On success the dialog closes, the discussion column selects the returned thread, and the run strip shows the new run. A refusal is stated in the dialog on the terms of OCW-FR-EKYF, and the dialog keeps the instruction.
48. **OCW-FR-SCIA** In the dialog, `proposal_pending` states that the change holds a pending edit proposal that the author decides first, and `blank_instruction` states that the instruction is empty. A failure that returns a thread id also selects that thread in the discussion column.
49. **OCW-FR-BNGB** Rework… is unavailable, with a sentence that says why, while a run of the change on this stream is not terminal, and while the change holds a pending edit proposal.
50. **OCW-FR-FEBP** The dialog is a floating overlay (per `SNV-shell-navigation.md` SNV-FR-56). It moves focus to the instruction field when it opens. Escape and Cancel close it and start nothing, and focus then returns to **Rework…**. While a start is in flight, the dialog's controls are disabled.
51. **OCW-FR-JHAB** A tab whose location is a stream shows a **run strip** under its header for the newest apply run or rework run of the change on this stream, from `list_graduation_queue`. The strip names the run's title and its state in words, and renders the stage row through `RPV-run-progress.md`, driven by the run's observability record, with the labels of `../core/GOB-graduation-observability.md` GOB-FR-CAXV.
52. **OCW-FR-YTGJ** A terminal run stays in the strip with its outcome until the author closes the strip with its **Close** action. A closed strip shows again when a newer run of the change starts. A tab with no such run shows no strip.
53. **OCW-FR-BTSI** The **Tasks** stage sentence of an apply run's strip states `<complete> of <total> tasks` and the next open task, from `"read apply progress"` (per `../core/OSM-openspec-mode.md` OSM-FR-PEAK). The tab reads it when the strip shows and on each `"graduation run changed"` for the run. A failed read keeps the last answer and adds the short form of its notice (`OFN-openspec-failure-notices.md` OFN-FR-QZEC).
54. **OCW-FR-FAEL** The detail slot of the strip's stage row (per `RPV-run-progress.md` RPV-FR-13) states the check state of an apply run in the words of `GRU-graduation-runs.md` GRU-FR-HZLV. The detail slot of a rework run states nothing.
55. **OCW-FR-LYIX** The strip offers **Open run**, which opens the Runs bottom panel on its graduation section and selects the run there (per `GRU-graduation-runs.md` GRU-FR-PAHN).
56. **OCW-FR-SFYL** The tab follows `"graduation queue changed"` and `"graduation run changed"` for its stream. On each, it reads the queue again, updates the strip, and settles the availability of Apply and Rework….
57. **OCW-FR-QCPB** A comment that carries a `change_action_request` attachment renders a **request card** with the action, the instruction of a rework, and the request's state, from `"list change action requests"` (per `../core/CAR-change-action-requests.md` CAR-FR-ALHA). While the request is pending, the card offers **Confirm** and **Decline**, which invoke `"confirm change action request"` and `"decline change action request"`.
58. **OCW-FR-CTWP** A started request's card shows the title and the state of its run in words, and offers **Open run** (OCW-FR-LYIX). A declined card states that the author declined it. A failed card states its code in words (per `OFN-openspec-failure-notices.md`). A refused confirmation is stated on the card on the terms of OCW-FR-EKYF, and the card still offers Confirm.
59. **OCW-FR-GDZT** After a decision on the card, the surface dispatches the agents of the conversation's active set with the outcome's `comment_id` and `origin_kind`, on the terms of `PCR-prompt-change-review.md` PCR-FR-14. The tab follows `"change action requests changed"` for its stream and change, and reads the requests again on it.
60. **OCW-FR-YRZK** The strip of an apply run at rest on `plan_update` states **waiting for plan decisions**, on `plan_findings` **plan findings to settle**, and on `plan_update_invalid` **plan update refused** (per `../core/OPU-openspec-plan-updates.md`). On `plan_update` and `plan_findings`, it offers **Show thread**, which selects the plan thread in the discussion column.
60. **OCW-FR-ZPDC** The strip of an apply run at rest on `plan_update`, `plan_findings`, or `plan_update_invalid` offers **Continue**, which invokes `continue_graduation_run` with the run. A refused Continue is stated in the strip in the words of `GRU-graduation-runs.md` GRU-FR-BPNJ.
60. **OCW-FR-XJMR** While the plan thread holds the question set of its plan update, the chips accept, reject, edit, and discuss of each hunk of the plan proposal, and Reject all, are unavailable. One sentence at the review bar says that the questions in the plan thread are answered first. A refusal `plan_questions_pending` is stated at the hunk.
60. **OCW-FR-KZDG** While the plan proposal is pending and its plan thread holds no question set, the plan thread shows one hint line under the proposal comment. It says that the author decides the edits with the chips, or by voice or comment by addressing an agent, for example *"@arch accept the first two edits"*.
60. **OCW-FR-NWRS** The run strip takes the full width of the document column and gives no width to the discussion column. Where the column is narrower than 560 px, the title and the state take one line above the stage row, and the actions stand on that line where they fit and on a line of their own below it where they do not. The title gives way before the state, and no action leaves the strip. The next task is cut with an ellipsis, and its whole text is its tooltip and its accessible name.

## Non-functional requirements
- A read costs one backend call. The tab reads nothing while it is not the active tab.
- The artifact list is a list of buttons that the keyboard reaches with Tab, and the selected one is marked for assistive technology.
- A change of 50 deltas renders without a delay that the author can see on a machine that meets the application's floor.
