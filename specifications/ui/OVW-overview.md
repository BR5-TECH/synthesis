# UI overview

**Spec code:** `OVW`

## Intent
Defines the scope of the Synthesis v1 UI and the navigation map between its surfaces. 
Scope is interactive AI-assisted authoring of AI artifacts: a single human authors and refines artifacts and works alongside agents one task at a time. 
Several projects can be open at once, each as a project tab and one OS window (`PJT-project-tabs.md`). Everything that follows in this folder elaborates a single surface; this file is the entry point.

## UI contract boundary
- **Owned by the UI**: surface inventory, navigation map between surfaces, top-level startup flow (project picker → main window), placement of every named surface into a shell zone.
- **Delegated to backend (abstract)**: project open/create, all per-surface operations enumerated in the per-surface specs. For the walking skeleton, all of these are stubbed.

## Functional requirements
1. **OVW-FR-01** Application startup shows the Project picker as a pre-project surface; the main window does not exist until a project is opened.
2. **OVW-FR-02** Opening a project from the Project picker window replaces that window with the project window of the project: its main window. Each open project has its own project window (per `PJT-project-tabs.md` PJT-FR-IAQN). Closing the last open project returns to the Project picker; closing one of several closes only that project's window.
3. **OVW-FR-03** The main window contains exactly six zones: top chrome, main viewport, activity bar, vertical panel, bottom panel, status bar. The floating chrome of OVW-FR-06 is not among them and reserves no layout height, so nothing it renders shortens or displaces a zone.
4. **OVW-FR-04** The Dashboard tab is opened automatically in the main viewport when a project is opened.
5. **OVW-FR-05** The Project panel is the vertical panel surface selected by default when a project is opened.
6. **OVW-FR-06** The surface inventory is fixed in v1 and consists of: Project picker (pre-project, and a modal over a project window, per `PPK-project-picker.md` PPK-FR-GMYH); Dashboard, Editor, Flow, New Artifact (per `NAW-new-artifact.md`), Search results, History detail, Diff (per `DFV-diff-viewer.md`), conversation (per `CVP-conversation-presentation.md`), Map of specifications (per `SMP-specification-map.md`), Document viewer (per `DTV-document-text-viewer.md`), PDF Viewer (per `PDV-pdf-viewer.md`), Terminal (per `TRM-terminals.md`) (main-viewport tabs); the Settings window with its Global and Project groups (a native child window, per `SWN-settings-windows.md`); Project, Documents (per `DPN-documents-panel.md`), Notes, Comments (per `CMP-comments-panel.md`), Changes, Drafts (per `DRP-drafts-panel.md`), Terminals (per `TRM-terminals.md`) (vertical-panel surfaces); Runs, Logs (per `LOG-logs.md`), Git, History version list (bottom-panel surfaces); Status bar, together with its in-flight operations overlay (persistent chrome of the main window, per `STB-status-bar.md`); on Windows and Linux, the project tab strip (persistent chrome of the top chrome, per `PJT-project-tabs.md` PJT-FR-UHOC); the notification toast stack, which also shows the unreachable-address toast (transient chrome of the main window, per `NTF-notifications.md` NTF-FR-21, NTF-FR-20); New File (per `NFI-new-file.md`), New Artifact (per `NTA-new-typed-artifact.md`), New Folder (per `NFW-new-folder.md`), the commit message window (per `CMW-commit-message.md`), the GitHub token picker (per `GHA-github-authentication.md`), and the open project dialog (per `PJT-project-tabs.md` PJT-FR-GASB) as modal action surfaces; the About panel (per `ABT-about-panel.md`), a modal overlay available in the Project picker and in the main window.
7. **OVW-FR-07** Navigation between surfaces follows the map: the Project panel, Search, and Dashboard widgets open Editor and Flow tabs; Changes opens Diff tabs (per `CHG-changes.md` CHG-FR-18 and `DFV-diff-viewer.md` DFV-FR-01) and the commit message window (per `CHG-changes.md` CHG-FR-39 and `CMW-commit-message.md` CMW-FR-03); the File menu and the Project context menu open the New File window (per `NFI-new-file.md` NFI-FR-01), the New Artifact window (per `NTA-new-typed-artifact.md` NTA-FR-01), and the New Folder window (per `NFW-new-folder.md` NFW-FR-01), and a confirmed New File or New Artifact additionally opens an Editor or Flow tab on the file it created (per `NFI-new-file.md` NFI-FR-12 and `NTA-new-typed-artifact.md` NTA-FR-13); the **Drafts panel** opens New Artifact tabs, whether it creates the draft or opens one that exists, and the Dashboard's Active workstreams widget opens one on a draft that already exists (per `DRP-drafts-panel.md` DRP-FR-06, DRP-FR-26, DRP-FR-09, `DSH-dashboard.md` DSH-FR-12, and `NAW-new-artifact.md` NAW-FR-03); the Project panel opens the Map tab, also on the Flow file that is the project's delivery, and the Map tab opens Editor tabs on spec files and New Artifact tabs on the drafts its delivery creates and links (per `LIB-library.md` LIB-FR-VMAQ, `MDL-map-delivery-lens.md` MDL-FR-YSMB, `SMI-specification-map-inspector.md` SMI-FR-GAJD, and `FLO-flow.md` FLO-FR-NRBV), and a graduated draft writes its files into the project rather than opening a tab on them (per `NAW-new-artifact.md` NAW-FR-20); Editor and Flow can open History detail tabs; the status bar's Settings button and the application menu's Settings entry open the one native Settings child window rather than any tab (per `STB-status-bar.md` STB-FR-04 and `SWN-settings-windows.md` SWN-FR-05, SWN-FR-13, SWN-FR-14), the entry being reachable from the Project picker as well as from the main window (per `SWN-settings-windows.md` SWN-FR-15); the Git panel and the Changes panel can invoke the GitHub token picker modal, and the Settings window presents that same picker within itself (per `GIT-git.md` GIT-FR-10, `CHG-changes.md` CHG-FR-45, `SET-project-settings.md` SET-FR-12, and `GHA-github-authentication.md` GHA-FR-20, GHA-FR-21); activating an OS notification enters the map from outside the window entirely, first activating the project tab its address names and then opening or focusing the tab or panel surface the address names (per `NTF-notifications.md` NTF-FR-17), which is the one route into a surface that begins with the application not in front of the author; the application menu's About entry opens the About panel over the Project picker or the main window, whichever is showing, and the panel's link opens the Synthesis GitHub project in the operating system's default browser rather than in any surface of the map (per `ABT-about-panel.md` ABT-FR-KMVD, ABT-FR-WPLJ, `SNV-shell-navigation.md` SNV-FR-KXPE, and `PPK-project-picker.md` PPK-FR-EWQH); and a change of the main viewport's active tab travels the map backwards while **Selection follows tab** is on, activating the vertical panel the newly-active tab's item belongs to and selecting that item in it (per `SNV-shell-navigation.md` SNV-FR-64), the one route whose origin is a tab and whose destination is a panel.
8. **OVW-FR-08** A surface that does not appear in OVW-FR-06 cannot be opened in v1.
9. **OVW-FR-09** At startup, before any surface renders, the app loads the persisted theme preference (the "load app preferences" operation) and applies it to the application root, so that both the Project picker and the main window render in the selected theme.
10. **OVW-FR-10** When the theme preference is "system", the app follows the OS colour scheme and updates live when the OS switches between light and dark while the app is running; "light" and "dark" pin the appearance regardless of the OS.
11. **OVW-FR-11** While a project is open, another project can be opened from within its project window through the top-chrome project switcher (`SNV-shell-navigation.md` SNV-FR-17). Selecting a recent project shows the open project dialog (`PJT-project-tabs.md` PJT-FR-GASB). **This tab** replaces the project in the current project tab: it tears down the current main window and reopens it for the selected project exactly as a fresh open — Dashboard tab focused (OVW-FR-04) and the Project panel the default vertical-panel surface (OVW-FR-05) — with the previous project's tabs, panel state, retained editing state, and every conversation presentation discarded (per `CVP-conversation-presentation.md` CVP-FR-49). The pending changes of the artifacts and Flows edited in the outgoing project are written first, and a write that cannot proceed safely cancels the switch and leaves that project open (per `EDT-editor.md` EDT-FR-32, EDT-FR-33 and `FLO-flow.md` FLO-FR-29). **New tab** opens the project in a new project window and leaves the current project open. The switcher's "Open Another Project…" action opens the Project picker as a modal over the project window (`PJT-project-tabs.md` PJT-FR-IOEV) so a project outside the recent list can be opened.
12. **OVW-FR-12** A project is a Git repository, and exactly one of its worktrees is the content root every surface reads from (per `../core/WTC-worktree-context.md` WTC-FR-03). While a project is open in its project tab, that project's active worktree can be changed from the top-chrome worktree selector (`WTS-worktree-selector.md`) or by checking out a branch from the Git panel's branches section (`GIT-git.md` GIT-FR-04). The switch runs in a fixed order: the pending changes of the artifacts and Flows edited in this session are written first, and a write that cannot proceed safely cancels the switch before anything else happens (per `EDT-editor.md` EDT-FR-32, EDT-FR-33 and `FLO-flow.md` FLO-FR-29); then every tab closes, all retained editing state is discarded (per `TAB-tabs.md` TAB-FR-14 and `EDT-editor.md` EDT-FR-28), and every conversation surface is torn down — conversation tabs and unsent composer state alike — without any conversation itself being altered (per `CVP-conversation-presentation.md` CVP-FR-49, CVP-FR-50), while every terminal process keeps running and stays listed in the Terminals panel (per `TAB-tabs.md` TAB-FR-JFZR); then the switching operation is invoked. The project window is not torn down — the project switcher keeps naming the same project and the layout keeps its shape — but the viewport returns to the fresh-open state, Dashboard focused (OVW-FR-04) with the Project panel the selected vertical-panel surface (OVW-FR-05), reading from the new content root. When the switching operation fails, the window is left in that same fresh state still on the previous active worktree and the error is surfaced by the surface that requested the switch (per `WTS-worktree-selector.md` WTS-FR-24). While the active worktree is gone, the switch writes nothing and nothing cancels it (per `WTS-worktree-selector.md` WTS-FR-OSKY).
13. **OVW-FR-13** Every piece of text the application renders belongs to exactly one of three **typographic roles**, each carrying its own font family, size, and line height (configured in `GLS-global-settings.md` GLS-FR-17). **Source code** is literal source text and code: the Editor's raw-text surface, the fenced and inline code and the YAML frontmatter region within any rendered Markdown document, a Diff tab's Source rendering together with its line-number gutter (`DFV-diff-viewer.md` DFV-FR-16), a Document tab's source view (`DTV-document-text-viewer.md` DTV-FR-CIWP), and a Terminal tab's terminal (`TRM-terminals.md` TRM-FR-WRVB). **Rich Markdown** is the prose of a rendered Markdown document: the Editor's WYSIWYG surface, a Diff tab's Rich rendering (`DFV-diff-viewer.md` DFV-FR-17), and a Document tab's rich view (`DTV-document-text-viewer.md` DTV-FR-SSQI). **UI** is everything else in the inventory of OVW-FR-06 — every panel, tab, chrome, modal, status bar, comment body, note body, Flow canvas, and settings window. The UI role is what text belongs to unless one of the other two names it, so a surface added later needs no typographic decision to render correctly. Inside a zoom region, the editor zoom level multiplies the size of the Source code and Rich Markdown roles (`EZM-editor-zoom.md` EZM-FR-LRVS).
14. **OVW-FR-14** At startup, before any surface renders, the app loads the three roles' font settings alongside the theme (the "load app preferences" operation) and applies them to the application root, so both the Project picker and the main window render in them from first paint. A role whose family, size, or line height is unset renders in the application's built-in default for that role. A change made in Global settings applies to every open surface immediately, with no relaunch.
15. **OVW-FR-VYPG** The Documents panel opens a Markdown or text document of the active worktree in an Editor tab (per `TAB-tabs.md` TAB-FR-UEKW), any other Markdown or text document in a Document tab, and a PDF document in a PDF Viewer tab (per `DPN-documents-panel.md` DPN-FR-CDFO and `TAB-tabs.md` TAB-FR-LKCT). The two viewer tabs are viewer-only, are identified by the document id, and close when the last source of their document is removed (per `TAB-tabs.md` TAB-FR-KUIN).

## Non-functional requirements
- Layout zones are persistent across sessions per the rules detailed in `SNV-shell-navigation.md`.
- A font change re-typesets the open surfaces without remounting them: an Editor tab keeps its buffer, its undo history, and its scroll position across the change.
- No surface in v1 requires network connectivity to render its empty state.
