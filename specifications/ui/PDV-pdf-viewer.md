# PDF viewer

**Spec code:** `PDV`

## Intent
The read-only viewer tab for a PDF document of the Documents collection. It renders the pages of the PDF inside the application with Mozilla PDF.js, from PDF bytes that the backend supplies, so the user reads reference material without leaving the window. It offers page navigation, zoom, text search with highlighted matches, and selection and copying of the page text. It never changes, prints, or exports the file. It follows the collection: when the PDF changes it shows the new content, and when the PDF becomes unreadable it says so. Out of scope: Markdown and text documents (`DTV-document-text-viewer.md`); the panel that lists documents (`DPN-documents-panel.md`); annotation, form filling, signing, printing, and saving of a PDF; OCR; and any access by the frontend to a selected path.

## Functional requirements
1. **PDV-FR-IWDK** A `pdf` document opens in a **PDF Viewer tab**, a viewer-only tab kind separate from the Editor tab (per `TAB-tabs.md` TAB-FR-LKCT, TAB-FR-QXRF). The tab is identified by the document id, its label is the file name, and its tooltip is the full path.
2. **PDV-FR-GPLH** The viewer obtains the PDF bytes only from `"read document pdf (id)"`, which returns them base64-encoded. It passes the decoded bytes to PDF.js (`pdfjs-dist`) and gives PDF.js no URL and no path. The frontend reads no selected path and holds no filesystem access to one.
3. **PDV-FR-CEIV** The PDF.js worker is bundled with the application and is loaded from the application's own assets. The viewer loads no script, worker, font, or other resource from a remote host, and it makes no network request of its own.
4. **PDV-FR-VKRL** The viewer shows one page at a time. Each page renders to a canvas at the current zoom, with a text layer above it that holds the page's text at the text's own position and size. While a page renders, the viewer shows **Loading page…** in place of the page.
5. **PDV-FR-SAIG** The viewer provides page navigation: **Previous page** and **Next page** buttons, and a page number field that shows the current page followed by **of** and the page count. **Previous page** is disabled on the first page and **Next page** on the last. Enter in the field shows that page, clamped to the page range.
6. **PDV-FR-BEQL** With the page region focused, Page Down and Page Up show the next and the previous page, and Home and End show the first and the last. The viewer opens on the first page. The current page is announced to assistive technology when it changes.
7. **PDV-FR-HQTN** The viewer provides zoom: **Zoom out**, **Zoom in**, and **Reset zoom** buttons, and a label that shows the zoom as a percentage. The steps are 25, 50, 75, 100, 125, 150, 200, 300, and 400 percent, and the default is 100. A button is disabled at its limit. A zoom change keeps the current page and re-renders it.
8. **PDV-FR-XMRL** The viewer provides text search. A search field takes the text to find. Matching ignores case and runs across the text of every page. The viewer shows a count in the form **3 of 12**, or **No matches** when the text is not in the PDF, and it announces the count politely when it changes.
9. **PDV-FR-BPXG** Every match on the displayed page is highlighted in the text layer, and the current match is highlighted distinctly without relying on colour alone. **Next match** and **Previous match** buttons move the current match, as do Enter and Shift+Enter in the search field. The movement wraps at both ends.
10. **PDV-FR-TIFB** Moving to a match on another page shows that page and scrolls the match into view. Emptying the search field removes every highlight and the count. A new search text starts at the first match at or after the current page.
11. **PDV-FR-KDVB** The text layer is selectable. The user can select page text with the pointer and with the keyboard, and copy it with the platform's copy command, so the copied text equals the text of the selection. The text layer never blocks the pointer from selecting, and a highlight never changes the text.
12. **PDV-FR-YLWC** While the viewer reads or opens the PDF, it shows the text **Loading PDF…**. A PDF that PDF.js cannot open shows **This PDF could not be displayed.** and logs the failure. A PDF that needs a password shows **This PDF is protected by a password and cannot be displayed.** The viewer never asks for a password.
13. **PDV-FR-SLWS** The viewer shows its **unavailable state** when its document's entry is `unavailable`, when the document is no longer in the collection, or when a read fails as unavailable or unknown. The state shows **This document is unavailable.** and one sentence that gives the possible causes. It replaces the content, so the viewer shows no stale content.
14. **PDV-FR-YOQS** The viewer follows `"documents changed"`. When the revision of its document differs from the revision it shows, the viewer reads the new bytes, opens the new content, and shows it. The current page, as far as the new page count allows, the zoom, and the search text stay as they were, and the search runs again against the new content.
15. **PDV-FR-INXM** The viewer offers no way to change, save, print, or export the PDF. While a PDF Viewer tab is active, File → Save stays unavailable (per `SNV-shell-navigation.md` SNV-FR-28). Closing the tab, and replacing the content, each cancel any render in progress and release the PDF.js document.
16. **PDV-FR-QNVD** Every control of the viewer is reachable and operable with the keyboard alone, has an accessible name, and shows a visible focus indicator. The viewer uses the colours of the current theme in light and dark. The page itself keeps the colours of the PDF.
17. **PDV-FR-DXUX** The page, the zoom, and the search text belong to the tab and last while it is open. They are not written to disk, and a new PDF Viewer tab for the same document starts on the first page at 100 percent with no search.
18. **PDV-FR-KJWR** The viewer logs through `../core/LGC-logging.md` under the `frontend` domain: an `INFO` record when a PDF opens, with its page count and byte length, and a `WARN` or `ERROR` record for every failed read, open, or render. No record carries a path, a file name, the search text, or any part of the page text.

## UI contract boundary
- **Owned by the UI**: the PDF Viewer tab, its identity and label, the PDF.js rendering of pages and text layer, page navigation, zoom, text search with highlighting and match navigation, text selection and copying, the loading, error, password, and unavailable states, and the reload that a changed revision causes.
- **Delegated to backend (abstract)**: `"read document pdf (id)"` — owned by `../core/DCL-documents-collection.md`, which also owns the `"documents changed"` event the viewer follows and the status of each document. The viewer invokes nothing else and writes nothing.

## Non-functional requirements
- The viewer renders only the displayed page, so a PDF of several hundred pages opens without rendering them all.
- The viewer needs no network access, and the bundled worker is the only code PDF.js runs besides the application's own.
- A search over a PDF reads the text of each page once for the open PDF and reuses it for later searches.
