# Project settings

**Spec code:** `SET`

## Intent
Project settings is the **Project group** of the Settings window (`SWN-settings-windows.md`), present only while a project is open, for configuration that belongs to the **currently open project**: project configuration, target repo bindings, agent-adapter configuration, MCP server connections, plugin enablement, and the Docker image each agentic CLI vendor's work runs in, together with whether that work may start containers of its own on this machine's Docker daemon. Installation of plugins and adapters and all user-global preferences (including the theme) live in Global settings (`GLS-global-settings.md`); this group manages only what travels with, or is local to, the project — the project's draft template among them, the one piece of project configuration the author writes rather than picks — together with the four project-scoped pointers into user-global registries — which GitHub token the project authenticates with, which agentic integration it hands work to, which AI API integration it calls — and the conversational agents the project defines for itself, which are committed with it and shared by every contributor. Plugin enablement is in v1 because the plugin system is architectural bedrock.

## User stories
- As a user, I want one window where I can configure this project's adapters, MCP servers, plugin enablement, and bindings so that I don't have to hunt across surfaces.
- As a user, I want to enable, disable, and configure installed plugins for the project I'm working in.
- As an author, I want to write once the headings and prompts every new draft should start from, so that a draft opens on the shape my project expects rather than on a blank page I fill in from memory each time.
- As an author, I want to choose how many graduation runs may work at the same time in this project, so that I use the machine as much as I want and no more.
- As an author, I want to set how many passes a graduation run may take, how long one of its turns may run, and how much time the whole run may use, so that I give a long run more room or stop a run that costs too much.
- As an author, I want to name the Docker image my project's agent runs in, point at the Dockerfile that builds it, and build it from here in one click, so that a graduation runs in the environment my project actually needs.

## Functional requirements
3. **SET-FR-03** The Project group of the Settings window holds these sections, in this order: Project, Draft template, Target repo bindings, GitHub Project settings, Agent adapters, MCP servers, Plugins, Project Agents, Docker, Graduation. The side nav and the one-section-at-a-time rule belong to the window (per `SWN-settings-windows.md` SWN-FR-QXTV).
4. **SET-FR-04** Plugins section lists installed plugins (via "list installed plugins") with enable/disable toggles and a per-plugin configuration entry; plugin **installation** is not here — it lives in Global settings (`GLS-global-settings.md` GLS-FR-08).
5. **SET-FR-05** Agent adapters section lists installed adapters (via "list agent adapters") and supports per-adapter configuration via "configure adapter (id, config)"; adapter **installation** is not here — it lives in Global settings (`GLS-global-settings.md` GLS-FR-09).
6. **SET-FR-06** MCP servers section lists configured server connections and supports add/remove/test via the corresponding abstract operations; test results render inline in the section.
7. **SET-FR-07** Target repo bindings section lists configured bindings and supports add/edit/remove; in v1 the UI only manages the list and nothing in the application reads it.
8. **SET-FR-08** Each section maintains an independent dirty state; saving applies the section's changes via the appropriate operation and clears that section's dirty state. A section holding a dirty state is a pending change the window writes before it closes, whether or not that section is the one on screen (per `SWN-settings-windows.md` SWN-FR-08, SWN-FR-09), and a save the section reports as failed keeps the window open with that section presented (SWN-FR-11).
9. **SET-FR-10** The Project section presents the project's line-ending convention as exactly two mutually-exclusive choices — **LF** and **CRLF** — initialised from "load project config" on mount. Selecting one persists it immediately via "save project config" rather than waiting for a section save, so this control sits outside the section's dirty state (SET-FR-08); every artifact written from then on uses the chosen convention (per `../core/PST-project-storage.md` PST-FR-22).
10. **SET-FR-11** This selector and the status bar's line-ending control (`STB-status-bar.md` STB-FR-16) read and write one shared project preference (`../core/PSS-project-settings-storage.md` PSS-FR-17); each reflects a change made from the other without a reload, and a change made here marks the artifact of every open Editor tab dirty exactly as one made from the status bar does (per `STB-status-bar.md` STB-FR-18).

11. **SET-FR-12** The Project section shows which GitHub token this project's authenticated operations use, read from "get project github token binding" on mount, and offers an action that opens the token picker within this window (`GHA-github-authentication.md` GHA-FR-20) to change it. It renders the token's label, account, and masked hint and nothing more of it (per `GHA-github-authentication.md` GHA-FR-03), and its domain when the domain is not `github.com`, it states when the project resolves a token implicitly because only one is stored, and it names the Global settings GitHub section as where tokens are added when none is. Confirming a selection in the picker persists it at once via "set project github token binding", so this control sits outside the section's dirty state (SET-FR-08).
12. **SET-FR-13** The Project section shows which agentic integration this project hands work to and how it resolved — inherited from that level's global choice, overridden for this project, or nothing resolved — read from "get project agentic integration" on mount, and offers an action that changes it. The control's content and behaviour are specified by `AII-ai-integrations.md` (AII-FR-31 through AII-FR-35); the integrations themselves are configured and verified in Global settings (`GLS-global-settings.md` GLS-FR-16), never here. Choosing an integration or returning the project to the global choice persists at once via "set project agentic integration", so this control sits outside the section's dirty state (SET-FR-08).
13. **SET-FR-14** The Project section shows which AI API integration this project calls and how it resolved, read from "get project ai api integration" on mount, and offers an action that changes it, persisting at once via "set project ai api integration" and likewise sitting outside the section's dirty state. It is a second, independent control beside the agentic one (SET-FR-13), governed by the same rules in `AII-ai-integrations.md` (AII-FR-31 through AII-FR-35), because the two levels are chosen independently: overriding one leaves the other's resolution untouched.

14. **SET-FR-15** The **Project Agents** section lists the Project agents of the open project, read from "list project agents" when the section mounts. It is where one is created, edited, and deleted through "create agent", "update agent", and "delete agent". Its content and behaviour are specified by `AGT-agents.md` (AGT-FR-22, AGT-FR-23). A Project agent is committed with the project (per `../core/PSS-project-settings-storage.md` PSS-FR-AGFL). Personal agents are described in Global settings (`GLS-global-settings.md` GLS-FR-24), never here. Every action persists at once, so the section sits outside the window's dirty state (SET-FR-08).

15. **SET-FR-16** The **Draft template** section holds exactly one thing: the project's optional Markdown **draft template**, the starting content every draft created in this project is born holding (per `../core/DRS-draft-storage.md` DRS-FR-39). It presents that text in the **same rich Markdown editing surface an Editor tab sets a Markdown file on** — the two modes of `EDT-editor.md` EDT-FR-17, the frontmatter region of EDT-FR-18, the diagram fences of EDT-FR-MOYS with their Edit button and the diagram editor overlay, which covers the Settings window (EDT-FR-ADNU, EDT-FR-TOVY), the formatting band of `EFR-editor-find-replace.md` EFR-FR-ABHF, the page framing of EDT-FR-63, and the round-trip fidelity of EDT-FR-66 through EDT-FR-69 — reused whole rather than reimplemented, with its formatting band and mode toggle placed within the section because the window's chrome belongs to the window rather than to one of its sections. There is no second editor implementation and no plain text area anywhere in this section. Its editing behaviour, its serialisation, its line-ending handling, its focus behaviour, and its accessibility behaviour are therefore the surface's own and are unchanged by being used here. The section carries nothing else — no name, no path, no artifact type, no destination, and no per-draft setting — because a template is one document and everything else about a draft is decided in the draft.
16. **SET-FR-17** The template **writes itself**. An edit schedules a write through "save project config" a short rest after the last keystroke, so a burst of typing is one write rather than one per character, and a further edit before the rest elapses restarts it so the write carries the settled text. The write additionally happens immediately when the user navigates away from the section within the window, and a write already in flight when the window closes is one of the pending changes the close waits for rather than starts again (per `SWN-settings-windows.md` SWN-FR-09). The section therefore carries **no Save control**, takes no part in the per-section dirty state of SET-FR-08, and raises no discard-unsaved-changes confirmation when the window closes (per `SWN-settings-windows.md` SWN-FR-10) — there is nothing to discard, because what the author typed is already on its way to disk. The write is a whole-store write that carries every other project-public section through unchanged (per `../core/PSS-project-settings-storage.md` PSS-FR-17).
17. **SET-FR-18** The section reports where the author's text stands, in three states and no others: **saving** while a write is in flight, **saved** once it has landed, and a **save failure** naming what went wrong. A failed write **keeps the author's content in the editor exactly as they left it** — nothing is reverted, reloaded, or replaced by what is on disk — and offers a retry, so a transient failure costs the author a click rather than the text they wrote. A failed **load** is surfaced in the section on the same terms as any other project-config read error (per `../core/PSS-project-settings-storage.md` PSS-FR-10): the section states that the project's configuration could not be read and edits nothing, and it never presents an empty editor as though the project configured no template, so a damaged store is never mistaken for a cleared one and is never overwritten by what the section happened to be showing.
18. **SET-FR-19** **Deleting all of the template's content clears the template.** When the editor is left holding no text, the automatic write of SET-FR-17 persists the **unset** state rather than a configured empty template (per `../core/PSS-project-settings-storage.md` PSS-FR-21), so the project returns to the behaviour it had before a template was ever written and drafts created afterwards open on an empty prompt (per `../core/DRS-draft-storage.md` DRS-FR-06). Unset and configured are distinct states in this section as they are in the store: a section showing an empty editor for a project with no template and one showing an empty editor because the author just deleted the text both describe the same unset project, and neither is a configured empty template.
19. **SET-FR-20** The section never shows a template that is not the active worktree's own. It reads the template through "load project config" when it mounts. Neither the active project nor the project's active worktree can change while the window is open, the main window being blocked behind it (per `SWN-settings-windows.md` SWN-FR-02), so the window opened after such a change mounts against the new worktree and reads there. While a read is outstanding the section renders a loading state rather than any previously-read template, and the editing surface accepts no edit until the read has landed, so the author can neither see nor overwrite one project's template while another project's is loading.

20. **SET-FR-21** The **Docker** section settles which container image each agentic CLI vendor's work runs in for this project, and whether the agent container may reach this machine's Docker daemon. Above the vendor tabs it presents the **Docker-in-Docker** controls (SET-FR-NXDV, SET-FR-JMHE, SET-FR-PQLA), which apply to the whole project and not to one vendor. Below them it presents one tab per vendor — Claude Code, Codex, and OpenCode, in that order, Claude Code selected when the section opens — and each tab renders the same controls in the same order: an **image name** field, an optional **tag** field, an optional project-relative **Dockerfile** field, an optional **Build context** field (SET-FR-KDRP), a **Build** control, and the region the build's progress and its result are rendered in. The section reads every tab from "load project docker images" when it mounts, so a tab renders the committed project's own entry rather than anything this window holds.
21. **SET-FR-NXDV** The Docker section shows one **Docker-in-Docker** checkbox, once, above the vendor tabs. It applies to the whole project and no vendor tab repeats it. The checkbox reads its value from "load docker in docker settings" when the section mounts. The checkbox is off for a project that has stored nothing. A change persists at once through "save docker in docker settings", outside the section dirty state of SET-FR-08, as the other fields of the section do. A refused write keeps the previous value in the control and renders the refusal inline, in words that name what to do. The section states, next to the checkbox, that the setting gives the agent container access to this machine's Docker daemon through its socket, that the container then starts sibling containers on that daemon, and that the setting is kept on this machine and is not committed with the project.
22. **SET-FR-JMHE** While the checkbox is selected, the section shows a **Docker socket path** text field and a **Host gateway** toggle under it. While the checkbox is not selected, it shows neither. The field shows the platform default as its placeholder, read from `default_socket_path` (for example `/var/run/docker.sock`), and an empty field means that default. The field commits on Enter or on blur and persists at once. A path that is not absolute, or that holds a comma, is refused inline and the stored value stays. The toggle is off by default. The section states, beside the toggle, that it maps `host.docker.internal` to the host and sets `TESTCONTAINERS_HOST_OVERRIDE` for Testcontainers, and that the container sees the socket at `/var/run/docker.sock` whatever the host path is. The controls persist the three values as one record, so a change of one carries the other two through unchanged.
23. **SET-FR-PQLA** The checkbox states the platform support that "load docker in docker settings" reports. On Windows (`unsupported`) the checkbox is disabled, and the section states the reason in words: a named pipe cannot be mounted into the agent container. On macOS (`best_effort`) the checkbox works, and the section states that access is best effort: the group of the socket may not give the agent access to the daemon, and a run then stops with a message that names the socket path. On Linux (`supported`) the section states no limit. A value stored for a start that finds no socket is the start's to refuse, so the section checks nothing about the socket and reaches no Docker daemon.
24. **SET-FR-PMHB** The section reads the isolation mode from "load isolation settings" when it mounts. While the mode is Microsandbox, it states next to the Docker-in-Docker checkbox that the setting is ignored: no host Docker socket is mounted, and a graduation start does not check the socket (per `../core/GSU-graduation-start.md` GSU-FR-RQDS). The checkbox and its fields stay editable.
25. **SET-FR-GVED** Only the Claude Code tab of the Docker section is implemented. The Codex and OpenCode tabs stay selectable and render their labels grayed. Each panel starts with the statement "To Be Implemented...", and every field and control below it is grayed and disabled. It still renders the stored entry and the graduation mark of SET-FR-24.
    - *Why:* Only Claude Code is tested (`AII-ai-integrations.md` AII-FR-OTQY).
26. **SET-FR-22** A tab's Dockerfile field is filled either by typing a project-relative path or by **selecting a Dockerfile** through the native OS file picker (SET-FR-HYTR), which opens in the project folder. A file chosen inside the project fills the field with its project-relative path. A file chosen outside the project is refused inline as leaving the project, and the field stays unchanged. A path that leaves the project, an absolute one, and one that does not name a file are refused by the backend's validation (per `../core/PSS-project-settings-storage.md` PSS-FR-24) and render inline in the tab, naming which of the three the path was.
27. **SET-FR-23** A tab states **what its configuration is worth**, in the four states "load project docker images" reports (per `../core/PSS-project-settings-storage.md` PSS-FR-25): nothing configured, configured in the committed project, configured with a Dockerfile and an image reference that are valid for this project, and unavailable for graduation. It distinguishes an **absent optional Dockerfile** from a **configured Dockerfile that is invalid**: the first is a tab that simply configures no build, stated as such and not as a problem, and the second names the problem and offers the field to correct it. A tab whose vendor is not implemented yet states that instead (SET-FR-GVED).
28. **SET-FR-24** A tab's image name is **required for every vendor the project selects for graduation**, and the section marks the tab of the vendor the project resolves to — read from "get project agentic integration", the same resolution the Project section names (SET-FR-13) — as the one graduation needs. It states, on a tab whose image name is empty, that graduation cannot start until it is filled. A Dockerfile is optional everywhere; where one **is** configured the image name is required on that tab as well, because it is the build target and the reference graduation runs. Editing a field persists at once through "save project vendor image", so the section holds no dirty state and takes no part in the per-section save model of SET-FR-08. The section additionally states, once and **at the top of the section**, that the Docker backend itself is configured and verified in Global settings (`GLS-global-settings.md` GLS-FR-29), never here; it reads whether it is verified through "load docker backend" and states that too, because a Build control this section cannot enable is most often disabled by it. That statement is a **control that opens the Docker section of Global settings** rather than only a name, so the author reaches the place they are sent to (per `SWN-settings-windows.md` SWN-FR-13).
29. **SET-FR-25** **Build** builds that tab's Dockerfile into that tab's image with **one click**, invoking "build project vendor image" for the vendor. The build uses the Dockerfile and the Build context that the tab holds, in Bollard / Docker Engine mode and in Docker CLI mode (per `../core/PSS-project-settings-storage.md` PSS-FR-26). When the author clicks Build while a field of the tab is still being saved, the build starts after that save ends; a refused save starts no build and keeps its inline message. The build is **local**: it produces an image in this machine's own image store and pushes it to no registry (per `../core/PSS-project-settings-storage.md` PSS-FR-26). It is enabled only while the tab configures both a Dockerfile and an image name and the Docker backend is verified, and it states which of the three is missing while it is disabled. **While a build is running, every vendor tab's Build control in this window is disabled**, whichever tab started it, because a project builds one image at a time (per `../core/PSS-project-settings-storage.md` PSS-FR-29).
30. **SET-FR-26** The tab that started a build renders **its progress and its outcome inline**, from the backend's own events: an indeterminate indication until a total is reported and a determinate one afterwards, the phase and the message each update carries — which **accumulate in a scrolling output region of bounded height**, oldest lines dropped first, rather than each update replacing the last, because a build is read as the sequence of steps it ran and the window it is read in has a bounded size (per `SWN-settings-windows.md` SWN-FR-03) — and then the single terminal result — succeeded naming the image reference that was built, failed naming what went wrong, or cancelled. The author reads the build where they configured it rather than in another surface, and a build that is running when the section is left and returned to is still rendered against its own tab.
31. **SET-FR-27** A **failed build keeps the tab's configuration exactly as it was** — no field is cleared, reverted, or rewritten — renders the final error inline, and offers **Retry**, which is one more "build project vendor image" for that vendor. Nothing retries on its own: a build happens because the author activated Build or Retry, and a failure neither disables Retry nor prevents a later build once the project is free (per `../core/PSS-project-settings-storage.md` PSS-FR-29).
32. **SET-FR-TTTB** The **GitHub Project settings** section lists the GitHub Projects of `"list github projects"` in one selector, each by title and owner, with a **None** choice. The selected Project is read from `"get github polling state"` when the section mounts.
33. **SET-FR-NLIX** The section offers the polling interval as **Off**, **1**, **5**, **15**, **30**, and **60 minutes**. **Off** is the unset interval, which disables the launch and timed polls and keeps the manual **Refresh** of `GIT-git.md` GIT-FR-EZFL.
34. **SET-FR-UGSP** While a Project is selected, the section reads the options of its `Status` field through `"list github project statuses (project node id)"`. It shows two selectors beneath the Project selector, **Ready status** and **In Progress status**, and each lists those options by name. The selectors are absent while no Project is selected.
35. **SET-FR-JGAK** While the status read is outstanding, both selectors render a loading state and keep the stored values. A failed read renders the displayable error inline with a **Retry** action, keeps the stored values, and writes nothing.
36. **SET-FR-CJZH** When the author selects a Project, the section reads its status options before it writes. Each selector then selects the first option whose name equals its default name, `Ready` or `In Progress`, case-insensitively. A selector without such an option stays unset. The write sends the new Project, the interval, and the two selected names, or null for an unset selector.
37. **SET-FR-SDKP** A change of the Project clears both stored status names. Where the status read of the new Project fails, the write sends both names as null. A status read that succeeds while a stored name is unset selects that selector's default on the terms of SET-FR-CJZH and persists it at once.
38. **SET-FR-JNLK** A stored status name that the option list does not hold renders as selected and marked **unavailable**. The section does not replace it, clear it, or write it again, and never falls back to the default name. The author chooses another option to end the error.
39. **SET-FR-QZYV** Each status selector disables the option that the other selector holds, so the two statuses always differ. A refused write, `duplicate_status_option` included, renders inline on the terms of SET-FR-VLQJ.
40. **SET-FR-VLQJ** A change of the Project, the interval, the Ready status, or the In Progress status persists at once through `"set github polling settings (project node id, interval minutes, ready status, in progress status)"`, outside the section dirty state of SET-FR-08. A refused write keeps the previous values in the controls and renders the error inline.
41. **SET-FR-GKTA** The section states the configuration in words: no Project selected, valid with the Project title, or an error that names what to fix. An error names a missing or unreadable Project, a missing `Status` field, or a missing status by name with a request to choose an option. The section states that polling is disabled while the error stands.
42. **SET-FR-GXJU** A Project list that cannot be read renders the error inline with a **Retry** action and keeps the stored selection. The section re-reads its state on `"github polling changed"`, so a configuration error found by a poll appears without reopening the window.
43. **SET-FR-BLQN** The GitHub Project settings section holds the polling controls of SET-FR-TTTB through SET-FR-GXJU and a **Publication** group beneath them. It has no second GitHub Project selector: the Project of the polling controls is the only Project the section names.
44. **SET-FR-DWRC** The Publication group offers a **Parent issue Types** filter that accepts one or more Types, with `Feature` selected when none is stored. The author cannot clear the last selected Type. The filter decides which open issues the publication chooser offers as parents (per `NAW-new-artifact.md` NAW-FR-YLKD).
45. **SET-FR-HPKV** The Publication group offers a **Sub-issue Type** selector, with `Task` selected when none is stored. The selected Type is the Type of every sub-issue that Publish to GitHub creates, and the publication chooser offers no override (per `NAW-new-artifact.md` NAW-FR-JXDN).
45. **SET-FR-ZNLF** The Publication group offers a **Root issue Type** selector, separate from the Sub-issue Type. It offers **No Type** and each available Type, with **No Type** selected when none is stored. The selected Type pre-fills the Type control of the root option in the publication chooser (per `NAW-new-artifact.md` NAW-FR-ZOAS), and the author can change it there.
45. **SET-FR-AXEZ** The Publication group offers a **Note issue Type** selector. It offers **No Type** and each available Type, with `Feature` selected when none is stored. The selected Type is the opening value of the Type control of the note publish modal (per `NIP-note-issue-publication.md` NIP-FR-UMKW). It does not change the Root issue Type or the Sub-issue Type.
46. **SET-FR-ZHCT** The Publication group offers the **Sub-issue milestone** policy as exactly three mutually exclusive choices: **Inherit parent milestone**, **No milestone**, and **Author-selectable milestone**. **Inherit parent milestone** is selected when none is stored.
47. **SET-FR-MQUE** A change in the Publication group persists at once through `"set github publication settings (parent issue types, sub issue type, sub issue milestone policy, root issue type, note issue type)"`, outside the section dirty state of SET-FR-08. A refused write keeps the previous values in the controls and renders the error inline.
48. **SET-FR-XFNA** The section reads the stored values through `"get github publication settings"` and the available Types through `"list github issue types"` when it mounts. While the Type read is outstanding, every Type control renders a loading state and keeps the stored values. The Note issue Type selector is a Type control of this rule and of SET-FR-LJYT.
49. **SET-FR-LJYT** A stored Type of any Type control that the Type list does not hold renders as selected and marked **unavailable**. The section does not replace it, clear it, or write it again. A Type list that is empty or cannot be read renders a notice with the displayable error and a **Retry** action, keeps every stored value, and writes nothing.
50. **SET-FR-DHFS** The **Graduation** section holds an **Execution time limit** row. It reads the stored execution timeout through "load project config" and shows it in minutes. An unset value shows the two-hour default as a placeholder. A helper line says that the limit bounds each conversation turn whose provider stores no turn timeout, and that it does not bound graduation turns.
51. **SET-FR-YMRV** An entry commits on Enter or on blur and persists at once through "save project config", outside the section dirty state of SET-FR-08. An empty entry stores the unset value (per `../core/PSS-project-settings-storage.md` PSS-FR-ZLCF). An entry that is not a whole number from 1 to 360 is refused inline, and the stored value stays.
52. **SET-FR-QKKQ** The **Graduation** section also holds a **Concurrent graduation runs** drop-down for the project-wide limit of `../core/GRD-graduation.md` GRD-FR-KKKN. It offers **1**, **2**, **4**, **8**, and **Unlimited**, in that order. It states in words that the limit counts stream runs and direct runs together and that each stream or worktree works one run at a time.
53. **SET-FR-ZNXA** The control shows the limit read through "load project config" (per `../core/PSS-project-settings-storage.md` PSS-FR-JRWC), and **1** where the store holds none. A stored positive integer that the list does not hold, such as **3**, is offered as one more option in numeric order and is selected. It stays selected until the author chooses another value, and nothing writes it again.
54. **SET-FR-HQKK** A change of the selection marks the Graduation section as a pending change in the dirty state of SET-FR-08. The change is not written at once. "save project config" writes it with the other pending changes of the window, and the close of the window writes it (per `SWN-settings-windows.md` SWN-FR-08), even while another section is on screen.
55. **SET-FR-TFNG** While the read is outstanding, the control renders a loading state and accepts no choice. While a write is in flight, the section states that it saves. A failed write keeps the selection, leaves the section pending, renders the error, and offers **Retry**. A failed read states that the limit could not be read and offers no choice.
56. **SET-FR-IHQE** The selection survives a change to another section within the window. The Graduation section stays pending until a write lands. A write names the limit alone, so it carries every other project-public section through unchanged (per `../core/PSS-project-settings-storage.md` PSS-FR-ZVSD).
56. **SET-FR-PSLD** The **Graduation** section holds three sliders, in this order: **Passes per run** from 1 to 10 in steps of 1, **Time per turn** from 30 min to 48 h, and **Total time per run** from 30 min to 96 h, both in steps of 30 min. They set the settings of `../core/PSS-project-settings-storage.md` PSS-FR-QBNE, PSS-FR-HVSM and PSS-FR-RKTW.
56. **SET-FR-RTDF** Each slider reads its stored value through "load project config" and shows it as text beside its label, for example "3 h 30 min" or "2 passes". It gives that text to assistive technology as its value text. A slider with no stored value shows its default: 2 passes, 3 h or 5 h.
56. **SET-FR-HLPL** Each slider has a helper line that states what it bounds. The pass slider says it does not apply to merge runs. The total time slider says it counts working and reviewing time alone.
56. **SET-FR-ISAV** The sliders look like the Isolation sliders of `GLS-global-settings.md` (GLS-FR-USNH): a label with the value, a full-width range control in the accent colour, and the range beneath it. They work from the keyboard: the arrow keys move one step, and Home and End move to the bounds.
56. **SET-FR-WTOS** A slider change persists at once through "save project config" when the author releases the slider or the key, outside the dirty state of SET-FR-08 and the save-before-close sweep. Writes go in sequence, so quick changes in sequence are all kept. A refused write keeps the previous value in the control and renders the refusal inline.
56. **SET-FR-KAXB** Each slider has a **Reset to default** control. It clears the setting to unset through "save project config" (per `../core/PSS-project-settings-storage.md` PSS-FR-OWGI), and the slider then shows the default.
56. **SET-FR-OVTW** When the shown stage time limit is higher than the shown total time limit, the section keeps both and shows a warning that the total time limit ends the run first.
57. **SET-FR-HSTF** The GitHub Project settings section works for the host of the project token, `github.com` or a GitHub Enterprise host. Its Project picker, status selectors, Type and milestone controls, and configuration report render the data that the backend reads from that host. It asks for no host input. A feature that the host lacks shows its existing unavailable state.
58. **SET-FR-KDRP** A tab's **Build context** field is a single-line text field with the placeholder "Project root (default)". The author types a project-relative or absolute path, or selects a folder with the native OS folder picker (SET-FR-HYTR). An empty field means the project root. The field belongs to the vendor's entry and saves at once with the other fields of the entry, on the terms of SET-FR-24.
59. **SET-FR-FPCX** The folder picker opens in the current Build context folder when the field holds a path, and in the project folder otherwise. A folder outside the project is accepted and kept as selected, for example a folder of certificates. A folder inside the project fills the field with its project-relative path. A path that does not name an existing folder is refused by the backend (per `../core/PSS-project-settings-storage.md` PSS-FR-BCTX). The refusal renders inline in the tab and names the problem. The entry stays unchanged. A folder chosen in the picker goes through the same check.
60. **SET-FR-HYTR** The Dockerfile file-picker button and the Build context folder-picker button each render inside their own text field, at the trailing end. They are not separate buttons beside the field. Each button has an accessible name and works from the keyboard, in the tab order after its field. A cancelled picker changes nothing. Both fields follow the look of the Settings window and of the other fields of the Docker section.

## Non-functional requirements
- The Project group can be opened, navigated, and forms rendered before any plugin or adapter is installed (empty states are first-class).
- The Project section renders its GitHub token display without network access; it describes the binding rather than verifying the token.
- The Project section renders both AI integration controls without network access and without running any binary; each names what the project resolves to rather than re-verifying it, and neither renders an endpoint, a key, a masked hint, or a binary path.
- The Project Agents section renders without network access and reaches no model: it describes who the project may talk to and never talks to any of them.
- The Draft template section renders without network access. It reads and writes one value in the project's own configuration and reaches no draft: opening it, editing in it, and saving from it change nothing in any draft that already exists.
- The template is ordinary Markdown in `.synthesis/project.toml` and carries no Synthesis-specific syntax, so a project's template is readable and editable outside the application and is reviewed in a pull request like any other committed configuration.
- The Docker section renders without reaching a Docker daemon and without running any executable: it reads the project's committed entries and states what they are worth. Building is the one action in it that reaches a runtime.
- A build's progress is rendered from the events the backend streams, so a long build shows what it is doing while the window stays responsive and every other section stays usable.
- A section's heading is followed by one sentence saying what that section settles, written for the section rather than assembled from its own name. A sentence built out of the label reads back as a tautology on a section called Project, and flattens an acronym on one called MCP servers.
