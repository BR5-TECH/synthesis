# Specification map

**Spec code:** `SMP`

## Intent
The Map tab is the project's control plane: one tab that shows what the project is delivering and what its specifications hold. It has two lenses. The **Delivery** lens (`MDL-map-delivery-lens.md`) shows the project's delivery plan, and the **Specifications** lens shows the specification corpus as one nested map, so the architect sees at a glance which functional areas exist, what each one is for, and how complete each one is. The two lenses link to each other (`SDL-specification-delivery-links.md`), so the architect moves from planned work to the specifications it delivers and back. This spec owns the tab frame: its identity, its entry point, the lens switch, the load of the index, the toolbar, and the lifetime of the map session. In OpenSpec mode the map shows the project's own OpenSpec specifications, with the changes that are about to alter them (per `../core/OSI-openspec-spec-index.md`), and every other project shows a demo index. The tab also hosts the **Discussion column**, where the architect plans delivery in conversation with an agent: a whole-map thread covers the whole map, a node thread covers one node or milestone, and the Map holds any number of each (`../core/MPR-map-plan-proposals.md`). The column is the discussion column of the draft and the file, so the author resolves, resizes, and keeps several discussions here as there. Canvas navigation, node rendering, dependency edges, and the inspector are specified in `SMZ-specification-map-zoom.md`, `SMN-specification-map-nodes.md`, `SME-specification-map-edges.md`, and `SMI-specification-map-inspector.md`. Out of scope: indexing the corpus, deriving completeness states, and persisting the map beyond the open project.

## Functional requirements
1. **SMP-FR-KQTD** The Map tab is a main-viewport tab. Its label is `Map` and the tab strip shows the layers icon in front of the label.
2. **SMP-FR-TKUS** The toolbar starts with a two-way lens switch, **Delivery** and **Specifications**. On the first render of a map session, the tab invokes `"get delivery source"` and shows **Delivery** where the source is not `none`, and **Specifications** otherwise. The active lens is part of the map session.
3. **SMP-FR-RNLH** A switch of lens keeps the state of the other lens: its selection, its view, and its loaded data. The Delivery lens's toolbar follows the lens switch on the terms of `MDL-map-delivery-lens.md` MDL-FR-GDUP.
4. **SMP-FR-WBNL** At most one Map tab is open per project. A request to open the map while a Map tab is open activates that tab and creates no second tab (per `TAB-tabs.md` TAB-FR-KXMW).
5. **SMP-FR-HZRA** The **View map** affordance of the Project panel opens the Map tab and makes it the active tab (per `LIB-library.md` LIB-FR-VMAQ).
6. **SMP-FR-PMCX** When the Specifications lens renders and the session holds no index, the tab invokes `"load specification map"` once and shows a loading state in the canvas area until the result arrives.
7. **SMP-FR-FEJV** The index is a tree of index nodes with spec nodes as leaves, all spec nodes at one depth. The tab renders indexes of 3 to 5 levels. An index node at depth 0 is a **root node**, one whose children are spec nodes is a **leaf group**, and any other is a **branch node**.
8. **SMP-FR-QMRE** The index supplies a plural name and a singular name for each level, for example `domains` and `domain`. The map uses these names in the level control, the legend, the inspector, and the action labels, and uses no fixed level name of its own.
9. **SMP-FR-TGYU** A spec node carries exactly one completeness state: verified, built, drafted, or gap. The map shows the state the index supplies and derives no state itself.
10. **SMP-FR-HWIC** `"load specification map"` answers the source `demo` or the source `openspec` with its index (per `../core/OSI-openspec-spec-index.md` OSI-FR-OSWD). For `demo`, the map shows a fixed demo index that is built into the application. Every spec node in the demo index names a spec file that exists under `specifications/`, and every dependency names two spec nodes of the demo index.
   - *Why:* The demo index stands in for the indexing backend, but **Open in editor** must still reach a real file.
11. **SMP-FR-MNZW** For the source `openspec`, the map shows the index of `../core/OSI-openspec-spec-index.md` with its three levels of groups, capabilities, and requirements. The toolbar shows no **dependencies** toggle (per `SME-specification-map-edges.md` SME-FR-XLUQ).
12. **SMP-FR-KVKD** For the source `openspec`, where `validation` is `unavailable` or `unreadLocations` is above zero, one notice line at the top of the canvas states that the validation could not run, with the sentence of the notice of its `validationFailure` and its Details (per `OFN-openspec-failure-notices.md`), that the changes of `N` locations could not be read, or both. The line hides no node.
13. **SMP-FR-ONSD** When `"load specification map"` fails, the canvas area shows an error state that says the map could not be loaded, with a **Retry** button that invokes the load again. The toolbar controls are disabled, and no other tab or panel changes.
14. **SMP-FR-KBXW** A load that fails with an OpenSpec failure shows the error state of SMP-FR-ONSD with the failure notice of `OFN-openspec-failure-notices.md` in place of its statement. **Retry** of SMP-FR-ONSD stays and then invokes `"get openspec status"` with `recheck` set before the load. The notice adds no Retry of its own.
15. **SMP-FR-LRAX** When the loaded index has no root nodes, the canvas area shows an empty state that says no specifications are indexed.
16. **SMP-FR-CVIB** A toolbar of 38px height sits above the canvas. From left to right it holds: the lens switch (SMP-FR-TKUS), the level control (per `SMZ-specification-map-zoom.md` SMZ-FR-VYOS), a divider, the **Completeness** label, the project completeness bar, the counts line, a flexible spacer, the **dependencies** toggle (per `SME-specification-map-edges.md` SME-FR-OKUH), the **gaps only** toggle (per `SMN-specification-map-nodes.md` SMN-FR-HLDQ), and the **unplanned** toggle (SDL-FR-HZLB).
17. **SMP-FR-AOZF** The Map tab never scrolls as a whole. Its content clips at the bounds of the tab, so the toolbar stays at the top edge and nothing below the tab content shows. Only the canvas, the inspector, and the Discussion column scroll, each inside its own box.
18. **SMP-FR-YDKM** The project completeness bar is 170px wide and 8px high. It holds four segments in the order verified, built, drafted, gap. The width of each segment is the share of all spec nodes in that state. The counts line reads `N verified · N built · N drafted · N gaps`.
19. **SMP-FR-GJEW** Below a Map tab width of 1180px, the **Completeness** label is hidden, the bar is 92px wide, and the counts line reads `P% verified · N gaps`. Below 1000px the counts line is hidden, and the toggles show only their icon, with their name as the tooltip.
20. **SMP-FR-QNUH** The map session holds the active lens, the loaded index, the last delivery plan answer, the selection and the view of each lens, the focused subtree, the toggles, and the inspector state. The session is in memory for the open project. Deactivating and then reactivating the Map tab keeps the whole session.
21. **SMP-FR-BXAP** Closing the Map tab resets the view and the focused subtree, so the next open frames the map as on first paint (per `SMZ-specification-map-zoom.md` SMZ-FR-NUOB). The active lens, the index, the delivery plan answer, the selections, the toggles, and the inspector state stay in the session.
22. **SMP-FR-MEZK** A project switch or an active-worktree change discards the whole map session (per `OVW-overview.md` OVW-FR-11, OVW-FR-12). The next open of the Map tab loads the index again.
23. **SMP-FR-SWUL** The Map tab shows a dirty indicator while the Delivery lens holds unsaved changes of a Flow file (per `MDL-map-delivery-lens.md` MDL-FR-VLQJ), and Save writes them (per `FLO-flow.md` FLO-FR-27). Otherwise it shows none, and Save is unavailable while the Map tab is the active tab.
24. **SMP-FR-WNLR** The Map tab has a **Discussion column** on the right of the canvas and the inspector. A **Discussion** toggle in the toolbar shows and hides it. The column is shown on the first open of a map session. It is the discussion column of `DDS-draft-discussion.md` (DDS-FR-KTVW), and follows the discussion rules of `CMT-comments.md`.
25. **SMP-FR-WYZA** The column shows one tab for each open Map thread, in the order of `"list map discussions"`, then the control that begins another discussion, then the resolved disclosure (per `CMT-comments.md` CMT-FR-17). It shows the active thread of the session, else the first tab. Where the Map holds no open thread, it shows the opening composer of a whole-map thread.
26. **SMP-FR-EIUP** A tab reads `Map` for a whole-map thread and the node label for a node thread, cut with an ellipsis past 160px, with the full label as its tooltip. Choosing a tab shows its thread. The header names the node of a node thread, and selecting that name selects the node on the canvas of its lens.
27. **SMP-FR-DUUU** The composer holds a **Focus** chip. The chip offers **Use selected node**, which takes the selected node or milestone of the active lens as the focus of the next message, and a clear control. A message with a focus sends one `map_node` attachment (`../core/MPR-map-plan-proposals.md` MPR-FR-PMLX). In a node thread the node of the thread is the default focus.
28. **SMP-FR-IHFM** A **Discuss** entry of the context menu on a node or a milestone (`MDL-map-delivery-lens.md`, `SMN-specification-map-nodes.md`) makes the Discussion column visible and shows the thread that `"find map discussion (map node)"` returns for the node. Where it returns none, the column shows the focused opening composer of a new thread for the node, and no tab is selected.
29. **SMP-FR-KHKC** The control that begins another discussion shows the opening composer of a new whole-map thread. Posting in an opening composer creates a new thread with `"open map discussion (map node, body, attachments)"`, with the node of the composer or none, and that thread becomes the active tab. A thread that another window created appears as one tab, not two.
30. **SMP-FR-HSZM** While the column shows a thread, its header carries the overflow menu of `DDS-draft-discussion.md` DDS-FR-MZQJ, with **Mark resolved** or **Reopen discussion** (per `CMT-comments.md` CMT-FR-15). A resolved thread leaves the tabs for the resolved disclosure, and the column then shows the first open tab, or the opening composer where none is open.
31. **SMP-FR-UHZK** A resolved Map thread renders as `DDS-draft-discussion.md` DDS-FR-MZQJ sets: the header states `resolved`, and the column shows no composer and no Quote action. A resolved thread blocks no other thread, and **Discuss** on its node opens a new one.
32. **SMP-FR-PPJB** An agent comment that carries a `map_plan_proposal` attachment renders the summary row of `MPV-map-proposal-review.md` in the transcript. Its review sheet shows over the Delivery canvas (MPV-FR-CTTA).
33. **SMP-FR-XGBI** The column tells the author, in the opening composer of a whole-map thread, that the agent reads the plan and proposes changes only while a GitHub Project is the delivery source. With another source, the agent has no plan tool and the column says so.
34. **SMP-FR-AUFA** The map session holds the visibility, the split, and the active thread of the column, whether its resolved disclosure is expanded, and the unsent text of its composers. A project switch or an active-worktree change discards them with the session (SMP-FR-MEZK). Closing the Map tab keeps them.
35. **SMP-FR-SWCL** The split between the canvas and inspector side and the column takes the presets, the accelerator, and the dragged splitter of `DDS-draft-discussion.md` DDS-FR-PNXR, with the canvas side as the document column. The default is canvas 70. Below a Map tab width of 900px the column covers no part of the canvas and replaces the inspector while it is shown.
36. **SMP-FR-VDND** The presets and the accelerator hint stand in the toolbar, leading the **Discussion** toggle, and stand down while the column is hidden (per `DDS-draft-discussion.md` DDS-FR-XQMF). Below a Map tab width of 1180px the hint is hidden, and below 1000px the presets are hidden too. The accelerator and the splitter still act.
37. **SMP-FR-BOBB** A message in a Map thread dispatches the turn of the agents addressed (per `CTA-comment-agent-turns.md`), as a message in a draft discussion does. The turn works under the focus of the message (`../core/MPR-map-plan-proposals.md` MPR-FR-PMLX).
38. **SMP-FR-QHBV** `revealDiscussion` (per `CVP-conversation-presentation.md` CVP-FR-06) reveals a Map thread by opening or focusing the Map tab, showing the Discussion column, and selecting the thread. A resolved thread is shown with the resolved disclosure expanded. The Comments panel row of a Map thread (per `CMP-comments-panel.md` CMP-FR-10) uses this route.

## UI contract boundary
- **Owned by the UI**: the Discussion column, its discussion tabs, its split, and its Focus chip, the tab record and its singleton identity, the lens switch and the default lens, the toolbar and its responsive rules, the loading, error, and empty states, the completeness roll-ups computed from spec nodes, and the in-memory map session with its reset rules.
- **Delegated to backend (abstract)**:
  - `"load specification map"` — owned by `../core/OSI-openspec-spec-index.md`. It returns `{ source: 'demo' }` or `{ source: 'openspec'; index }`. For `demo`, the UI serves its built-in demo index of SMP-FR-HWIC. An index is `{ levels: { plural: string; singular: string }[]; roots: IndexNode[]; dependencies: Dependency[] }`, and the `openspec` index also holds `validation: 'valid' | 'invalid' | 'unavailable'`, `validationFailure?: OpenSpecFailure`, and `unreadLocations: number`. A failed load rejects with an `OpenSpecFailure` of `../core/OFP-openspec-failure-policy.md`. `IndexNode` is `{ id: string; label: string; summary: string; hue?: string; children: IndexNode[] | SpecNode[]; planned?: boolean; issues?: MapIssue[]; changes?: ChangeChip[] }`. `SpecNode` is `{ code: string; badge?: string; path: string; label: string; summary: string; requirements: number; scenarios: number; state: 'verified' | 'built' | 'drafted' | 'gap'; issues?: MapIssue[] }`, with `path` relative to `specifications/` in the demo index and relative to the project root in the `openspec` index. `Dependency` is `{ from: string; to: string; citations: number; unresolved?: boolean }` naming spec codes. `ChangeChip` is `{ change: string; location: { kind: 'active_worktree' } | { kind: 'stream'; streamId: string; streamName: string }; issues?: MapIssue[] }`, and `MapIssue` is `{ level: 'ERROR' | 'WARNING' | 'INFO'; message: string }`.
  - `"get openspec status"` — owned by `../core/OSM-openspec-mode.md` (OSM-FR-YXUC), invoked with `recheck` by the Retry of SMP-FR-KBXW.
  - `"get delivery source"` — owned by `../core/DSR-delivery-source.md` (DSR-FR-AECK), invoked for the default lens of SMP-FR-TKUS.
  - `"find map discussion (map node)"`, `"open map discussion (map node, body, attachments)"`, and `"list map discussions"` — owned by `../core/MPR-map-plan-proposals.md`, invoked by the Discussion column (SMP-FR-WNLR).
  - `"add comment to discussion (discussion, body, quotes, attachments)"`, `"set discussion resolution"`, and `"dispatch agent turn"` — owned by `../core/CMS-comments-storage.md` and `../core/AGC-agent-conversations.md`, invoked as a draft discussion invokes them.

## Non-functional requirements
- The map session is never written to disk and never survives a relaunch.
- The tab renders an index of 150 spec nodes without a visible delay on a pan or a zoom step.
- Diagnostic log records of the map carry counts and operation names only. They never carry a node label, a summary, a draft name, or the text of a message.
- The map needs no network connection.
